# Agent Note: 原件发布前固定导入哈希

Status: Implemented

## Problem

文件原子归位与数据库提交之间可能中断。原先在归位后才保存哈希，重试遇到已有文件时缺少可比对的登记内容，可能把中断后的修改内容接纳为原件。

## Decision

复制与散列完成后，先在素材原有字段中保存已接纳的 BLAKE3 和大小，再发布文件并更新可用状态。已有目标缺少登记哈希时报告冲突。恢复与重试继续使用同一素材 ID，并将读到的内容与登记哈希比较。

## Alternatives considered

重新导入会改变恢复身份。仅依赖文件存在或来源时间戳无法核对中断后的内容。新增文件历史表会扩大素材模型，现有哈希与可用状态已能表达两步发布。

## Consequences

文件尚未发布时可保留已登记哈希，可用状态继续阻止科学读取。中断后变化的内容报告失败，恢复原字节并检查后恢复可用。对应 pytest 源码包含原子归位后的受控中断与修改回归场景。
