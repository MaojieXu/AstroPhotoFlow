# Agent Note: 后端开发导航与数据库开发阶段约定

Status: Implemented

## Problem

平台后端任务需要定位模块归属，并追踪 HTTP、Python 客户端、MCP、生成 CLI 与原生桥接的协作。现有数据库采用单一初始化基线，core 约定仍将结构变化统一描述为迁移，开发文档还要求每次覆盖测试 workspace 单独授权，与已确认的 v1 开发规则存在冲突。

## Decision

新增仓库级 astrophotoflow-backend 技能，由根约定提供入口。技能正文路由到后端导航和联调参考，按当前源码提供责任层、代表调用关系、生成命令与测试入口。架构、接口字段与运行约定链接权威出处。

将用户确认的数据库阶段规则写入开发文档并同步英文配对。v1 开发期 workspace 内容为可替换测试数据，直接维护当前初始化基线并按需重建；进入数据库 v2 开发后保留 v1 数据并设计、验证升级迁移。core 约定和技能链接该规则，重建目标仍须核实绝对路径与清理范围，并通过控制入口停止目标实例。

## Alternatives considered

全量文件清单容易随代码变化失效，无法表达调用关系。将模块契约和字段复制到技能会增加重复维护。将 v1 测试数据的历史升级作为开发前置要求，会偏离当前单一基线机制与用户确认的阶段范围。

## Consequences

后端任务可按责任层与协议进入现有实现，接口变化可沿实际消费链选择生成和验证任务。导航入口变更需同步维护。数据替换规则限定于数据库开发阶段，外部原件与共享运行环境继续遵守其操作约定。
