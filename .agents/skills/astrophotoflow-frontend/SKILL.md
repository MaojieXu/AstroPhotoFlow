## 修改流程

1. 从任务路由定位责任层，读取该子树的 `AGENTS.md`。按索引打开源码与代表性调用者，核对当前 props、事件、插槽、模型值与测试。
2. 已有行为满足需求时直接复用。需要补充行为时扩展责任组件或现有适配。确认现有能力缺口后，在拥有该行为的层新增实现。
3. 业务包内优先使用已有 `Library*` 适配。原生控件由宿主经现有 `controls` 传入，宿主从 `@astrophotoflow/ui` 公开入口消费业务组件。新增注入项时同步实际提供者、类型与使用方。
4. 视觉使用现有语义 token、变体、图标与相邻页面布局。保留焦点、键盘、可访问名称、禁用、加载及错误状态。弹层检查 Portal、关闭与焦点恢复，画布控件检查缩放和拖拽交互。
5. 沿用已有查询、状态、国际化、客户端和原生工作流机制。业务契约查生成 SDK，新增文案同时维护中英文。按改动范围执行参考中的验证入口。

## 导航维护

索引保存查找入口和复用判断所需的关系，字段与行为细节以当前源码为准。命中后定点核对，避免每次重新扫描全仓库。入口失效或任务未覆盖时，先检查根目录是否存在 `.codegraph/`，存在则按根约定优先用 CodeGraph，否则使用 `rg` 定向查找。

新增、移动或改变已收录入口时，同步对应导航行与调用实例。架构规则链接权威文档，接口签名链接代码。仅执行构建时按现有命令与产物路径工作。共享 runtime 的启停与真实素材操作遵守根约定。
