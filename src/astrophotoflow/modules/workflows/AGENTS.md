# ⑤工作流、执行与 Agent 交互开发边界

- 先读本目录README、[数据设计](../../../../docs/architecture/data-models/05-workflows.md)与[模块导航](../../../../docs/architecture/module-map.md)。工作流、执行与Agent交互业务统一进入workflows。
- 复用原生JSON文件、自动保存、本地草稿、撤销、graphToPrompt、队列／进度／取消；平台只补项目关联、必要运行记录、多次完成预览、当前控制与薄桥接，不建第二套当前图或执行器。
- 当前图自动保存，重要方案另存；运行固定当次内容。无永久逐编辑历史、服务端恢复草稿、通用协作账本和永久画布回执。
- Agent仅操作明确活动画布；切走后暂停新修改／提交，已有运行继续且预览归原图。手改即接管，读取／重连不取回控制，用户明确交回后继续；离线未确认如实显示。
- 实际执行图像节点自动附轻量预览，科学输出不变，不扩大执行范围；只将用户选中的完整结果交②保存，未选完整中间文件不长期留存。
- MCP协议适配归interfaces，原生Store／画布／转换／事件归宿主桥接，UI包只通过公开导出接入；跨模块使用公开能力，不访问私有ORM。
- 当前仅有素材入画布窄候选：canvas.py通过②公开准备能力及原生桥接加入固定引用；不代表完整项目桥接、运行记录、预览与协作已经实现。只改任务范围，不创建空接口、假服务或不存在的测试命令；新增实现补状态与验证记录，测试是否执行遵循用户本次要求。
