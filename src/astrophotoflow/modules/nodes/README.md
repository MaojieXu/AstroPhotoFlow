# ④ 节点构建与发布概要设计

具体交接见[④接口契约](../../../../docs/api/platform-contracts.md#nodes)及[文件级详细设计](../../../../docs/api/platform-contracts.md#nodes-design)：定义JSON保存、可选测试、影响确认和⑤实例更新。测试复用⑤同次运行，新增操作仍待实现。

本文是④的唯一概要，依据[现行需求](../../../../docs/requirements/README.md)及[总架构](../../../../docs/architecture/overview.md)。数据设计见[④节点构建](../../../../docs/architecture/data-models/04-nodes.md)。2026-10-27用户确认简化方向，替代原有项目草稿、强制测试发布和旧版并存要求。

**B41 已实现workspace JSON定义契约和公开文件操作；B42／B43 的原生加载、HTTP组合与UI仍待实现。** ④目前可保存／预览更新／替换定义，不发布NodeDetails路由，也不从文件内容推断节点已加载或可运行。原生节点注册、控件、节点库和子图可复用，不等于平台节点制作、更新或试运行已经完成。

<a id="scenarios"></a>

## 1. 用户场景与需求覆盖

按[三种节点创作场景](../../../../docs/requirements/README.md#scenario-nodes)：S3封装③已有软件操作，S6与外部Agent共同编写Python函数、封装多个节点。用户或Agent制作节点，保存到当前workspace节点库，在不同项目工作流中复用，可以先使用再测试。导出及他人安装是后续目标。

主要覆盖FR-16及FR-02／03／07～11／13／14；AT-03／29验证制作和更新，AT-10／11验证加载与转换，AT-16／18验证真实运行，AT-33承接软件包配套节点。NFR-01／04／07／08约束数据独立、错误可见、支持范围和实际运行可查。完整需求由现行需求维护，不另建发布审批或逐项目节点库。

<a id="authority"></a>

## 2. 权威状态与边界

④保存工作区节点定义：标识、名称说明、输入输出、参数及执行内容。⑤统一拥有原生当前图及实例、参数、连线、复合节点独立副本、运行／测试和在线交互；③拥有软件包及可用情况。

试运行通过应用装配与⑤协调，④不建立执行器，不反向导入⑤。用户选择的完整结果才交②登记素材。保存、引擎加载、指定画布显示和实际运行分别以事实确认。

<a id="objects"></a>

## 3. 核心内容

一份可编辑节点定义承载必要内容，不拆成类型、项目草稿、固定修订、不可变发布和激活记录。端口、参数和执行映射作为定义内部内容，具体保存方式在实施时确定。公共定义不隐含测试素材、项目路径、凭据或临时会话。

自定义节点输入名称各自唯一，输出名称各自唯一；只声明实际需要的科学格式、集合或单位。参数沿用常用／高级展示，完整映射可查询。软件操作、Python和复合节点分别保存对应操作、代码或内部图，素材引用由⑤实例提供。

## 4. 能力与现状

| 能力 | 现有基础 | 待实现或验证 |
|---|---|---|
| 制作与保存 | 原生注册和控件 | workspace节点定义、网页及MCP相同操作 |
| 使用与更新 | 原生实例、连线和图序列化 | 更新影响确认、默认参数及变化端口处理 |
| 测试与错误查看 | 原生执行和日志 | ⑤真实试运行、最近测试读取、修改前内容提示 |
| 引擎加载 | 原生定义注册和刷新 | 实际加载结果、失败原因及构建／刷新／重启条件 |

不预设独立测试证据、激活历史或多层持久状态。当前是否可用从③及引擎实际情况获得；原生刷新不能证明热加载成立。

<a id="flows"></a>

## 5. 主要流程

**制作使用**：选择操作或描述功能 →填写必要定义 →保存节点库 →⑤创建实例并调用原生引擎执行。试运行可随时进行，失败不阻止保存；详情读取⑤最近测试及链接，修改后不能把旧测试表示为新内容已通过。

**修改更新**：④提供更新前后定义 →⑤展示受影响工作流 →用户确认 →替换已有实例并保存当前图。参数全部采用新版默认值，不做旧参数兼容验证；方向、名称和类型不变的端口保留连线，包括只调整顺序；改名、改类型或删除则断开对应连接，新增端口等待连接。正在执行的任务保持已采用内容，历史事实不改写；不要求旧节点长期并存。

**复合节点**：S6保存内部图和对外端口／参数映射；在当前工作流中修改内部结构时保存独立副本，只影响当前工作流，不回写节点库或其他工作流。导出安装只保留目标。

<a id="handoffs"></a>

## 6. 跨模块公开能力与交接

以下是概念能力，不是已创建接口。

| 生产者 → 消费者 | 交接及保证 | 失败含义与联调 |
|---|---|---|
| ③ →④⑤ | 软件包节点、操作及实际可用原因；执行对应真实能力 | 缺软件或许可如实提示；S3软件操作与⑤真实调用核对 |
| ④ →⑤ | 定义、更新前后内容；⑤确认影响并更新实例 | 保存失败不报告更新，加载失败可见；验证参数重置及端口增删改、重排 |
| ④ →应用装配／⑤ →④ | 提交本次节点内容测试，从⑤查询最近结果及链接 | 失败、未知不报通过；修改后说明旧测试范围，不建立第二执行器 |
| ② ↔④⑤ | ②提供科学输入，仅用户选择的结果登记素材 | 预览不替代原件；试运行与结果保存分别验证 |
| ④ →⑤ | 节点目录、定义及受控制作操作 | 节点不是可直接处理数据的MCP工具；发现、入图、显示和执行分开 |
| ① ↔④③⑤ | 公共资源及维护机制，实际加载与占用由所属模块提供 | 不覆盖执行中内容；热加载未验证时采用明确刷新或受控重启流程 |

[③软件包配套节点更新](../../../../docs/architecture/data-models/03-software.md)沿用其确认规则，不将本模块自定义节点的端口命名限制扩大到所有第三方节点。

<a id="frontend"></a>

## 7. 前后端与原生桥接

Python④管理定义，前端④展示制作、最近测试及更新影响，⑤保存确认后的实例变化。原生注册、控件、子图及端口连线重映射集中在原生桥接区域；私有UI通过公开导出消费业务能力，不导入原生Store或画布单例。

原生输出可重名且按位置保存，自定义节点的唯一命名和端口重排连接保持需要桥接验证。具体注册身份、数据格式和代码执行环境留到实施，不新增编辑器或预注册空能力。

## 9. 阶段与验收

| 阶段 | 交付与验收目标 |
|---|---|
| S3 单软件操作节点 | workspace制作保存、常用／高级参数、跨项目使用；⑤可选真实测试，保存不依赖测试通过；修改影响确认、默认参数及变化端口处理 |
| S4 真实运行 | ⑤固定本次图及④定义内容，实际软件调用和结果可查，执行中内容不被更新 |

| S6 Python与复合 | 代码及实际环境对应，复合内部图／映射可运行，局部修改只影响当前工作流 |

NODE-F01～F08沿用追踪：F01制作保存、F02端口参数、F03真实试运行、F04实际加载、F05确认更新、F06复合局部副本、F07双入口与控制、F08Python及后续导出目标。最近测试、修改后旧测试提示、加载失败、跨项目更新和运行中保护均须真实证据。

<a id="decisions"></a>

## 10. 决策及后续事项

用户确认统一workspace节点库、可先保存使用、节点统一更新、参数恢复新版默认值、只断变化端口、同方向端口不重名、最近测试由⑤提供，以及复合节点工作流局部修改。取舍见[节点ADR](../../../../frontend/docs/adr/WORKBENCH-NODES-0057-shared-editable-node-definitions.md)。

Python及复合节点仍在S6；导出和他人安装保留目标，不选择格式、渠道或阶段。定义物理保存已选择workspace JSON，必要公开签名见第④阶段详设；代码执行环境及热加载仍需对应原型。正在执行内容和历史运行事实保留，不承诺旧节点或旧环境长期可用。
