# ① 公共基础设施概要设计

具体交接见[①接口契约](../../../docs/api/platform-contracts.md#foundation)及[文件级详细设计](../../../docs/api/platform-contracts.md#foundation-design)：本机启停、实际地址、配置及繁忙维护的签名、文件和测试。M1候选已实现配置DTO、默认workspace、保存冲突、启动采用、结构化启停／重启、自动端口、维护准入及网页配置；真实验证见[矩阵](../../../docs/development/test-matrix.md#m1-foundation)。MCP控制和③⑤参与者仍待后续批次，不创建占位接口。

设计基线：2026-10-26。本文是①的唯一概要设计，依据[现行需求](../../../docs/requirements/README.md)和[总架构](../../../docs/architecture/overview.md)，统一公共能力、状态归属、源码入口及验收责任；[开发路线](../../../docs/development/platform-roadmap.md)维护阶段依赖。FND 编号仅用于本模块设计追踪，不替代 FR／NFR／AT。

**本文维护概要，实际进度以当前上下文及矩阵为准。** M1候选可读取／保存配置并比较实际启动采用值，提供网页配置、`apf restart`、自动端口、维护准入及最近控制结果。MCP启动／重启、③⑤占用、公共状态桥接、平台日志轮转和缓存清理仍待后续批次。本文中的其他概念操作与后续验收不能当成可调用接口。

## 1. 用户场景与边界

- 新用户在config.toml设置默认workspace，准备固定平台环境，启动后取得可点击网页地址并核对实际配置及版本；当前不提供workspace搬迁／复制服务。
- 用户在网页查看运行配置、修改允许调整的设置，保存后选择何时通过 CLI／MCP 显式重启。
- 外部Agent经MCP请求启动指定workspace；已运行且健康时复用，端口被其他程序占用时自动选择可用端口，返回实际网页地址。
- 用户或外部 Agent 安装软件、发布节点后，能知道需要重新检测、刷新还是重启，以及是否存在阻塞任务。
- 多个项目、页签和独立 workspace 共存；控制命令、文件操作和客户端请求始终命中明确目标。
- 页面显示真实节点进度、变更和故障；断连、重启后通过所属模块的权威记录继续工作。
- 用户查询故障、导出脱敏诊断、确认清理缓存，按说明升级及恢复，原件和业务历史得到保护。

①提供公共机制，不拥有资产、节点定义、工作流或运行状态，不增加图调度器。保持网页／ComfyUI与 FastAPI 两个常驻服务；外部软件由③按接入方式运行。业务操作经共享 HTTP 能力进入所属模块；生命周期控制执行必须能够在目标服务停止后继续完成，不建立业务写库旁路或新增常驻控制服务。

## 2. 权威状态与依赖

| 对象 | 权威及引用规则 |
|---|---|
| workspace、有效配置、待应用配置 | ①保存选择、配置和生效事实；待应用配置为目标能力，不能改变运行中客户端的连接目标。workspace 是平台数据与运行边界，项目资料由②保存 |
| 平台环境及资源 | ①核对平台包、固定runtime、网页资源及来源版本，并提供固定本地embedding资源／运行环境的公共管理机制；③拥有软件包、适配器和实际调用观察，⑤拥有检索用途及索引，历史运行引用归⑤ |
| 认证及操作授权 | ①验证 workspace 级令牌和来源；⑤拥有业务写授权及接管，所属能力在实际提交处核对。前期不增加客户端独立凭据 |
| 进程及生命周期控制 | ①保存进程身份、维护及控制结果；各模块提供繁忙与排空事实。控制回执不能代替⑤的运行记录 |
| 数据库及业务版本 | ①拥有迁移基础与连接事务；业务模型、revision、提交防重和运行意图由所属模块保存，不另建公共业务操作真相 |
| 平台日志和缓存 | ①维护自身诊断日志、公共缓存和清理记录；②⑤保护业务文件、运行日志及待登记产物 |
| 通知及画布 | 所属模块拥有事件含义和权威状态，原生应用提供现有连接及进度显示；⑤统一拥有当前图、运行、预览和在线交互 |

同进程合作使用模块公开入口，应用装配层组合路由、繁忙检查、启动及释放；core 不导入 modules 或 interfaces。现有 [Alembic 元数据装配](database/alembic/env.py)明确加载 data.models，是已限定例外；未来模型在该装配边界接入，不能扩展成其他基础文件依赖业务模块。

contracts 只依赖标准库和 Pydantic。公共请求关联与错误机制可以共用，过期写检查仍须由所属模块在实际提交处执行；数据库写入和原生图文件保存各按其边界处理；request ID 只用于关联一次请求，不能证明授权或保证副作用仅发生一次。

## 4. 关键行为约定

### 4.1 配置、初始化与文件范围

2026-10-27用户收敛范围：在config.toml设置默认workspace即可，不建立workspace身份登记或搬迁／复制服务。B11已按用户TOML的workspace.default定位，不再读active-workspace；显式配置和环境优先，不能保留两份可独立修改的默认位置。本轮不改已有dev目录、配置、指针或MCP注册。

配置只保留最新值；并发数等性能参数保存后在下次重启采用。网页显示保存值、本次采用值及是否需要重启，不建立配置修订历史。运行中的网关、CLI／MCP及控制操作继续使用实际地址；②业务资料的即时保存行为不受影响。

重启核对目标、所用设置、版本和实际就绪，失败保留可核对信息与诊断。目标workspace已经运行且健康时复用；需要启动且端口被其他程序／workspace占用时自动选择可用端口。两个服务就绪后把实际端口及对应本机允许来源写回本次所用配置，成为下次默认值，并返回可点击网页地址；回写不覆盖其他新保存设置，失败明确提示而不重复启动。此项回写选择补充此前[启动地址ADR](../../../frontend/docs/adr/WORKBENCH-FOUNDATION-0054-automatic-startup-endpoints.md)的待定事项，数据结构见[①数据设计](../../../docs/architecture/data-models/01-foundation.md)。

网页网关、CLI和MCP读取当前运行信息中的实际业务地址，并核对进程身份、健康及实际网页地址。网关生效来源必须与实际网页地址一致且维持本机限制，不能放宽到任意来源；仅扫描到空闲端口不证明绑定成功。更改默认workspace或data_dir只选择位置，不搬运旧数据，也不改变已运行服务的归属；当前不提供搬迁服务。

程序资源、共享 runtime、业务原件、可重建预览、工作目录、暂存输出、平台日志和进程记录分别归属。保留相对配置目录解析 data_dir 的现有语义；输入允许读取的根、输出允许写入的范围、覆盖及清理授权必须明确。跨模块操作复用已验证规则，实际共用需求出现后再提取实现，不能提前建立杂项文件工具库。

科学原件保护和固定引用由②负责，⑤约定本次运行的工作及输出范围，③消费明确交接。虚拟环境不等于恶意代码沙箱；平台约束不能被描述为限制本机任意用户代码访问文件。

### 4.2 重启、互斥与状态不明

目标新增 `apf restart` 及MCP启动、重启和状态查询能力，**当前不存在**。外部客户端启动本机MCP接入后，目标中的启动操作经①工作台本机控制能力定位明确workspace，即使领域服务未启动也能发起；业务请求继续共用 HTTP。启动／重启控制须能在目标两个服务未启动或关闭后完成，不建立业务写库旁路，也不新增第三个常驻服务。现有MCP使用本机stdio与客户端通信，不因此额外占用第三个网页／业务服务监听端口。公共数据以文件保存最新配置、当前运行信息及当前或最近一次启停结果，更早过程查日志；不建立通用维护任务框架。具体调用和文件写入方式在实施任务确定。

1. 固定本次 workspace、有效配置与控制目标；默认workspace设置随后变化不能改写本次目标，也不顺带激活另一 workspace。
2. 同一 workspace 的初始化、启停、重启和数据库升级互斥；共享 runtime 安装／更新保护正在使用的固定版本，不能覆盖别的实例依赖。
3. 在空闲检查与进入维护状态的同一控制交接中阻止新冲突任务进入，再核对导入、预览、原生排队／执行和托管运行；状态由所属模块及引擎公开能力提供，①不查询业务私有表。
4. 繁忙时拒绝并列出阻塞任务；无法确认是否空闲时明确拒绝并要求核对。释放本次维护占用，不留下等待完成后自动重启的请求，不默认取消或强杀业务任务。
5. 通过检查后执行停止、应用候选配置和启动，核对旧目标退出、必要端口释放及新服务就绪；遇其他进程占用时自动选择可用端口，核对并记录实际地址；仅创建进程、扫描空闲端口或收到接口回执不代表重启完成。
6. 分别表达请求受理、进行中、就绪、失败和无法确认；断连后先查已有控制事实，重复请求不能启动另一轮重启。拒绝、重试及人工恢复均有明确结果。

现有 stop 的导入／预览排空语义保留，不能因新增 restart 改成默认强制退出；当前引擎 stop 也不能被描述为已有托管运行的安全取消。进程存活、API 健康、业务依赖就绪和运行完成分别表达。

[③软件概要](../modules/software/README.md)管理软件包及配套节点，由③按实际适配提供软件使用、停止及排空观察，⑤给出实际在途运行，应用装配①的维护准入；不能仅凭软件可用或连接在线判断空闲。固定本地检索模型的使用与索引活动由⑤公开报告，①提供资源机制，不查询其私有状态，不新增常驻模型或控制服务。

### 4.3 节点更新、通知与回执

| 变更 | 设计要求与责任 |
|---|---|
| 添加已有节点、修改参数及连线 | 沿用原生编辑，无需重启；⑤负责当前图保存、冲突及实际画布应用核对 |
| 创建或修改自定义节点 | ④保存workspace节点定义，无需因此启动处理；更新影响由⑤展示并确认，当前仍待实现 |
| 保存并加载标准节点 | 核对引擎实际加载及刷新要求；④⑤验证参数重置、变化端口及执行中内容保护，不要求旧节点长期并存 |
| 安装外部软件、修改软件路径 | ③重新检测并报告实际接入条件，不能一律要求重启平台 |
| 新适配器代码、依赖或专用前端组件 | 分别说明版本、构建、刷新或受控重启条件，不承诺任意代码热替换 |

[④节点概要](../modules/nodes/README.md)采用workspace节点库、可选测试及确认更新，保存、加载、显示和实际执行分别核对。①只提供维护和装配机制；实际加载、端口重映射和执行中内容保护仍需原型，不建立节点发布门禁或激活历史，保存和注册不启动软件处理。

[⑤工作流概要](../modules/workflows/README.md)明确原生当前图自动保存、本地草稿、重要方案另存、缺依赖待修复及会话撤销；①提供认证、事务、维护和状态传递，⑤提供真实提交／占用事实。未同步草稿不冒充已保存，打开画布不自动等于长任务；维护期间保留草稿而不建立文件写库旁路，原生自动队列等托管入口交⑤核对。保存、转换、显示及运行分别由⑤确认，新增交接尚未实现。

[⑤运行概要](../modules/workflows/README.md)明确同一引擎串行基础、默认固定输入、整图／受支持目标、实际调用及产物检查，只有用户选择后才交②保存素材，未知先核对，取消回执不证明软件停止。⑤及③报告在途、占用和排空，未知不视为空闲，维护检查与任务准入共同联调；完整重跑／续跑新建关联运行，待登记产物及业务日志不随公共轮转清理。现有stop尚未接入上述外部运行事实。

执行进度复用原生节点、队列和进度显示。③取得真实软件观察，⑤关联本次运行并接入原生显示；无法取得百分比时显示真实阶段、时长和日志，不伪造完成度。

[⑤协作概要](../modules/workflows/README.md)明确普通任务连续操作和每图简单当前控制，不建立协作Settings对象，控制归⑤、用户审美资料归②、公共配置机制归①，不新增逐工具权限表。手动改图即接管、离线未确认如实显示，服务控制须与⑤提交联调；既有运行不误取消。Skill已知能力直达，需发现时才使用本地检索，embedding不可用不妨碍已知能力按真实条件使用；未来Judge只预留概念，不增加模型运行环境或端口。

领域状态优先验证原生连接和必要桥接，由应用／引擎集成与原生桥接区域完成，core 和私有 UI 均不反向导入引擎或原生 Store。消息用于提示指定对象发生变化，客户端向所属模块读取权威版本；重连重新核对，画布离线不报告已显示。浏览器关闭不影响已接受任务，但不能承诺原生视口仍在线。

桥接通过条件是：两个进程之间真实变化可达正确 workspace／目标，重连可核对，来源与权限有效，页面不持有服务令牌，业务 UI 保持导入边界。若原生通道存在已观察到的不足，记录原因后再决定增量通道，不以猜测宣称支持。节点热发布另遵循[总架构原型门槛](../../../docs/architecture/overview.md#prototype-gates)；进度和刷新入口存在不构成已通过证据。

### 4.4 诊断、清理与恢复

平台诊断日志自动轮转是待补目标，仅作用于平台服务／引擎诊断输出；不因此删除⑤的业务运行日志、历史来源或②的保留资产。诊断关联请求、workspace、控制操作及所属业务提供的版本／运行身份，不复制业务状态；导出排除令牌、软件凭据和不必要的私人资料。

轮转保留量和相关空间门槛按固定环境、数据及运行规模测量后确定，目标与实测分别记录，不编造阈值。缓存先展示归属、范围、占用和可重建条件，经用户确认后清理；实际删除前重新核对使用中及受保护引用。业务缓存通过所属模块公开入口处理，①不能扫描后直接删除业务目录，也不能把待登记产物当作缓存。

保留既有数据库显式升级和备份机制；该备份只证明数据库内容，不包含科学原件、外部引用文件或整份程序环境。恢复说明分别覆盖数据库、托管原件、外部引用、固定运行实现及网页资源；缺少旧字节时不能报告历史内容已恢复。安装或升级授权仅覆盖明确计划，失败保留已验证环境、数据、候选及诊断，恢复先核对已发生操作。

本地embedding是⑤全部业务工具检索的固定资源，①提供来源、准确版本、准备及诊断等公共机制，不承担Agent推理、排名或记忆提炼。模型不可用时由⑤明确关键词降级并说明原因，①不静默替换模型或软件。③软件副本、桥接及⑤模型的在用／保留信息需经公开交接参与维护，公共缓存清理不能直接扫描删除业务目录；具体模型及推理方式待原型，不改变现有CPU runtime或依赖。

## 5. 概念公开能力与七条交接链路

下表是后续公开操作的语义，不是新函数、HTTP 路由或 MCP 工具清单。生产者提供事实，消费者遵守所属模块的版本与失败规则；具体协议在数据设计后对齐。

| 链路 | 生产者、消费者与公开交接 | 失败含义与后续验收 |
|---|---|---|
| 初始化 F-INIT | CLI选择workspace、准备固定环境；Agent经MCP请求①本机控制启动，网页／CLI／MCP读取同一目标 | 路径无效、归档不符及缺依赖明确；已运行工作区复用，外部占用自动换到可用端口并返回实际地址，两个服务及客户端核对同一workspace；旧资料、令牌及独立实例保持。AT-01、AT-25 |
| 配置修改 F-CONFIG | 网页经受控应用能力 →①保存待应用配置；CLI／MCP读取有效／待应用状态并请求显式应用 | 未授权或过期配置写不能覆盖新保存；保存不重启、不改运行连接，重启结果可核对。FR-13、FR-14 |
| 节点保存与更新 F-NODE | ③操作 →④节点库 →⑤实例及确认更新；①提供加载／刷新／重启机制，⑤记录实际运行 | 加载失败可见、更新影响确认、参数与变化端口规则成立，正在执行内容不被覆盖。AT-02、AT-03、AT-29 |
| 运行与所选结果保存 F-RUN | ②给固定输入，④⑤给定义及图，⑤协调③实际执行、检查产物并记录事实；用户选择完整结果后交②保存，①给事务、目录、错误及诊断基础 | 执行与素材保存分别返回结果；未请求保存不构成登记失败，已请求保存失败时核对文件及登记，不重跑。AT-12～AT-18、AT-28 |
| 繁忙重启 F-RESTART | CLI／MCP →①控制；应用装配从②⑤及引擎取得繁忙事实，维护交接阻止新任务 | 繁忙或未知明确拒绝、无挂起重启；并发控制互斥、目标不漂移、空闲重启有就绪证据。FR-13、NFR-04 |
| 断连核对 F-RECONNECT | 原生连接／桥接给变化提示 →网页查询所属模块，⑤核对目标画布；CLI／MCP查询控制及⑤运行事实 | 丢消息不伪造业务结果，不因超时重复副作用；离线显示、运行状态与重新连接分别可辨。AT-07、AT-10、AT-18、AT-24 |
| 升级恢复 F-UPGRADE | ①给版本、安装计划、数据库备份及诊断；各模块给自身迁移与数据核对，用户显式授权执行及恢复 | 未知 schema 拒绝迁移；扩大计划重新授权；数据库、原件、外部引用及程序恢复边界正确。AT-01、AT-25、AT-27 |

①不持有数据库事务等待软件或整图完成。跨数据库记录与文件操作由资产／运行所有者保存可核对的事实，不能声称单个数据库事务覆盖外部软件、文件及引擎提交。

## 10. 取舍与后续设计约束

| 已确认选择 | 原因与代价 |
|---|---|
| CLI 引导＋网页配置诊断 | 使用者可以在网页管理日常设置；需要配置表单、授权和生效状态，离线初始化仍有本机入口 |
| 保存后显式应用、繁忙拒绝重启 | 不打断在途任务或留下延迟重启；用户或 Agent 须先等待完成或明确处理阻塞任务 |
| workspace 级令牌＋⑤操作授权 | 保留单用户本机信任边界和现有接入，前期不提供客户端独立撤销认证；不能把自报 actor 当授权 |
| 原生进度与连接优先 | 复用原生显示和事件基础，减少重复连接；领域通知仍需跨进程、权限、目标及重连验证，取舍记录见[前端 ADR](../../../frontend/docs/adr/WORKBENCH-FOUNDATION-0046-native-progress-and-status-reuse.md) |
