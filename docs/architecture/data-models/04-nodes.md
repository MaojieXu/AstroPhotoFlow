# ④节点构建数据设计

**设计方向已确认；节点制作、更新和运行交接均待实现。** 本文依据[现行需求](../../requirements/README.md)及[④概要](../../../src/astrophotoflow/modules/nodes/README.md)。2026-10-27确认节点定义按workspace内JSON文件保存，不新增节点定义表或版本库；具体字段、公开签名和文件职责集中见[④详细契约](../../api/platform-contracts.md#nodes-design)。

## 节点需要哪些信息

自定义节点在同一 workspace 的节点库统一管理，各项目可以使用。制作后可以先保存、加入工作流，再按需要试运行；不要求先经过项目草稿、测试通过和发布审批。

| 信息 | 用途 |
|---|---|
| 节点标识、名称与说明 | 让工作流和 Agent 找到同一个节点，名称可修改 |
| 输入与输出 | 各端口的名称、方向及类型；科学格式、单位等仅声明实际需要的内容 |
| 参数及默认值 | 说明可以调整什么；沿用常用／高级展示，必要映射可查 |
| 实际执行内容 | 对应③软件操作，或S6的Python代码、复合节点内部图及对外映射 |

端口、参数和操作映射是节点定义内的内容，不预设独立对象或表。具体素材、实例参数和连线归⑤；实际运行所用的内容、输入、参数和环境归⑤。

## 从制作到使用

1. 用户或外部 Agent 选择③提供的软件操作，填写实际需要的输入输出、参数及执行对应，保存到节点库。Python函数和复合节点沿用S6目标。
2. 用户在前端选择节点，或让 Agent 通过 AstroPhotoFlow MCP 发现节点并加入⑤工作流；由⑤协调实际执行，保存和添加节点本身不启动处理。
3. 可以随时试运行。节点详情从⑤读取最近一次测试结果及运行链接；节点修改后，注明该测试针对修改前内容，不把旧结果显示成新内容已经通过。测试失败不阻止保存，实际错误可查。
4. 保存后依据引擎实际加载情况和③软件可用情况显示问题。保存成功不等于已经加载；不另建激活历史、测试证据或多层状态对象。

## 修改已有自定义节点

- 更新前列出受影响工作流，用户确认后统一更新已有实例；不要求保留旧版节点供旧图继续执行。
- 实例参数全部采用新版默认值，不检查旧值是否兼容。自定义节点的输入名称各自唯一、输出名称各自唯一。
- 按方向、名称和类型对应端口：未变化的连接保留，单纯调整顺序也保留；改名、改类型或删除时断开对应连接。新增端口等待连接。只比较端口，不做旧参数兼容验证。
- ④提供更新前后定义，⑤负责影响展示、确认后的当前图内容、参数重置及连线更新。正在执行的任务保持已采用内容，⑤历史运行事实不改写；保存记录不保证旧代码和环境长期可用。
- [③软件包配套节点](03-software.md)继续遵循③的更新规则，本节的端口命名及参数重置规则不扩大到所有第三方节点。

## 复合节点与后续目标

S6支持把多个节点封装为一个节点，保存内部图及外露端口、参数的对应关系。在某个工作流里修改内部结构时，作为该工作流的独立副本保存，只影响当前工作流，节点库原定义和其他工作流不变。

Python节点保存用户可查看的实际代码；执行环境随实施任务确定，不提前设计代码版本库或沙箱。导出自建节点及他人安装继续保留为后续目标，暂不设计包格式、分发渠道和依赖携带方式。

## 验证与决策来源
