# ①公共基础设施数据结构初稿

**按2026-10-27用户决策精简；M1配置／控制／网页候选已实施，用户人工批准仍待完成。** 依据[现行需求](../../requirements/README.md)、[①概要](../../../src/astrophotoflow/core/README.md)及源码。本文确定需要保存什么；实际配置契约见[①详设](../../api/platform-contracts.md#foundation-design)，实现证据见[验证矩阵](../../development/test-matrix.md#b11-implementation)。

## 1. 用途与边界

服务于本地工作台的打开、配置和启停：从config.toml读取默认workspace，启动后返回可点击的网页地址；保存性能参数，下次重启采用；发生问题时查看当前状态、最近操作及日志。

当前不提供workspace搬迁／复制服务，不建立workspace身份注册、配置历史或启停历史管理系统。①不保存资产、工作流、业务运行或Agent控制权。对应FR-13～15、NFR-01／04／07／08；先支撑S1，业务联调随所属模块推进。

## 2. 保留的数据

| 内容 | 保存什么 | 用途与现状 |
|---|---|---|
| 配置 | 默认workspace、端口及性能等设置 | TOML／Settings已有；默认workspace字段、端口自动回写及重启生效机制待补 |
| 当前运行信息 | 本次采用的设置、两个服务的实际地址与进程信息 | processes.json已有进程记录；实际地址和采用值待补 |
| 当前或最近一次启停结果 | 一次操作的目标、进展、结果及错误 | init／start／status／stop已有；可断连查询的操作记录及restart待补 |

版本和来源复用现有清单，诊断继续写日志；在线状态按查询时的进程和健康检查给出，不另建资源注册表、健康观察历史或诊断实体。

## 3. 关键字段与使用规则

<a id="workspace"></a>
<a id="configuration"></a>

### 3.1 配置

| 字段或内容 | 逻辑类型 | 含义 | 当前情况 |
|---|---|---|---|
| 默认workspace | 路径 | 用户CONFIG_PATH的config.toml以workspace.default定位目标；目标workspace/config.toml仍存该工作区参数，显式配置／环境优先；不另存活动指针 | B11已实现；签名见[①详设](../../api/platform-contracts.md#foundation-design) |
| server.host／server.port | 地址／整数 | 本机业务服务地址，端口作为下次启动的优先选择 | M1候选已验证实际端口回写 |
| 网页端口与允许来源 | 端口／来源列表 | 网页使用另一端口，允许来源与实际地址一致 | 从comfyui.allowed_origins首项取首选端口，M1已验证自动调整及实际地址 |
| storage.data_dir | 路径 | 业务数据目录 | 已有，相对路径按当前配置文件目录解析 |
| imports.roots | 目录列表 | 用户授权导入的本机目录 | 已有 |
| ingestion.file_workers／preview_workers | 正整数 | 导入与预览并发数；修改后在下次重启采用 | 字段已有；当前／待应用值展示待补 |

只保存最新设置，不记录每次保存的版本、作者、摘要或恢复历史。“待应用”通过保存值与本次采用值的差异表达，不另存一份配置状态。保存配置不重启服务；启动过程中又保存的性能参数留到下一次重启。

端口用于打开工作台，无需用户管理端口历史。已运行时核对后复用；需要启动且端口被其他程序或workspace占用时自动选择可用端口。两个服务启动并核对就绪后，把实际使用端口写回本次所用配置，成为以后启动的默认值，同时返回实际网页地址。回写只更新相应端口和允许来源，不覆盖用户新保存的性能等设置；写回失败时仍返回实际地址并说明未保存，不重新启动服务。

默认workspace以配置为准，不再设计另一份可独立编辑的默认指针或workspace登记表。更改路径只选择位置，不搬运旧数据；业务数据与令牌不得随配置更改被删除。现有active-workspace及配置定位方式仍是当前实现，后续实现此目标时明确调整，本轮不改本机配置。

<a id="processes"></a>

### 3.2 当前运行信息

| 字段或内容 | 逻辑类型 | 含义 | 当前情况 |
|---|---|---|---|
| config_path／workspace | 路径 | 本次使用的配置和工作目录；后续改默认设置不改变已运行服务的归属 | 路径已有，运行记录关联待补 |
| effective_settings | 配置值 | 本次实际采用的目录、并发数、允许来源等，不含令牌正文 | 新增建议 |
| web_url／service_url | 地址 | 实际网页地址和业务地址；网页、CLI及MCP连接同一目标 | 当前从配置推导，实际地址记录待补 |
| processes | 进程列表 | 保留角色、PID、创建时间、程序、命令、workspace和启动时间 | 已有；角色为asset-service／comfyui |
| versions | 版本摘要 | 本次程序、引擎、网页及runtime的实际版本或固定来源，供诊断与⑤记录环境 | 来源清单已有，启动采用值待补 |

进程项沿用现有role、pid、create_time、executable、command、workspace、started_at，不再拆启动批次对象或增加boot_id。创建时间、程序、命令和workspace用于防止PID复用时误停其他进程，不能只留下PID。

文件中有记录不等于服务在线。查询时返回运行、停止、部分运行或无法确认，并说明原因；无法核对不能当作已停止。健康结果可以随查询返回，不长期积累观察记录。停止后经核对再清除当前进程信息；部分启动或尚未退出的进程保留可核对的信息。

客户端使用实际地址，不因配置已改而连接到尚未启动的新端口。网页允许来源必须匹配本次实际网页地址并保持本机限制。仅扫描到空闲端口不代表服务已经绑定和就绪。

<a id="maintenance"></a>

### 3.3 当前或最近一次启停结果

| 字段或内容 | 逻辑类型 | 含义 | 当前情况 |
|---|---|---|---|
| operation_id | 操作标识 | 断连后查询同一次操作及关联日志，不另加请求摘要或通用业务防重对象 | 新增建议 |
| action／state | 操作／结果 | 初始化、启动、停止、重启；进行中、完成、拒绝、失败或待核对 | 启停行为已有，记录待补 |
| config_path／workspace | 路径 | 操作开始时确定的目标 | 目标解析已有，记录待补 |
| target_settings | 配置值，可空 | 启动或重启时固定将要采用的设置，完成后由当前运行信息表达实际值 | 新增建议 |
| controller | 进程信息，可空 | 操作执行期间的控制进程，用于断连后核对是否仍在执行 | 新增建议，沿用进程身份核对方式 |
| started_at／finished_at | 时间，可空 | 开始与实际结束时间；未结束时不填完成时间 | 新增建议 |
| detail | 结果说明 | 当前步骤、阻塞任务或错误原因，附必要日志位置 | 日志基础已有，结果汇总待补 |

只保留当前或最近一次结果；更早的过程查日志。未完成或待核对的操作不能被新操作覆盖。相同workspace的冲突启停互斥；重复请求先核对，不因断连再启动一轮。operation_id用于关联，不凭一个字段承诺跨进程只执行一次。

重启仍按已确认规则检查繁忙并阻止新的冲突任务进入；忙碌或无法确认时拒绝并给出原因，不留下稍后自动重启的请求。现有stop排空行为保留。这里承接原草案MaintenanceOperation的必要启停职责，不扩展为搬迁、安装、升级、清理的通用任务框架；敏感操作确认仍由其所属能力和⑤负责。

### 3.4 复用清单与日志

平台包版本、vendor来源清单、固定runtime及依赖锁文件继续说明版本和来源；当前运行信息只记录实际采用值，不再给每项资源增加统一UUID或复制安装历史。软件包信息归③，MCP协议仍归接入层，检索模型用途归⑤，①按真实共用需求提供资源机制。

平台日志保留时间、级别、消息及已有request ID；涉及启停时关联operation_id，涉及业务时使用所属模块提供的关联信息。没有关联时不制造空对象；凭据不进入日志。平台诊断日志轮转不清除业务运行日志、原件、在用资源或待登记产物。

## 4. 结构与保存位置

~~~mermaid
flowchart TB
  C["config.toml<br/>默认workspace、端口、性能设置"]
  O["当前或最近一次启停结果<br/>目标、步骤、结果"]
  R["当前运行信息<br/>采用值、实际地址、两个进程"]
  U["网页／CLI／MCP"]
  V["现有版本与来源清单"]
  L["日志文件"]
  C -->|读取本次设置| O
  O -->|记录实际启动或停止结果| R
  R -->|就绪后回写实际端口| C
  R -->|核对后连接；返回网页地址| U
  V -->|记录实际采用版本| R
  O -->|过程和错误| L
  R -.->|查询时核对进程与健康| U
~~~

| 内容 | 保存方式 |
|---|---|
| 最新配置 | config.toml |
| 当前运行信息、当前或最近一次启停结果 | workspace内文件，优先在现有run/processes.json基础上扩展；物理布局在实现时确定 |
| 在线状态、是否有待应用设置 | 查询时核对或比较，不单独持久化 |
| 版本来源、历史诊断 | 复用现有清单与日志 |

文件为主的决定保持。写配置及启停记录需要避免并发覆盖或留下半份文件，实施时复用适用的文件互斥与完整写入方式；不为此引入公共数据库、事件账本或额外常驻服务。业务SQLite与数据库显式升级前备份机制保持，数据库升级不等于workspace搬迁服务。

## 5. 用场景检查数据是否够用

以下是后续验收条件，不是本轮功能通过记录。

| 场景 | 必须能查到或得到的结果 |
|---|---|
| Agent请求打开工作台 | 从配置定位workspace；已运行则核对后复用，否则启动；返回用户可点击的实际地址 |
| 默认端口被占用 | 两个服务使用不同的可用端口；就绪后写回配置，下次优先使用；回写失败明确说明，当前地址仍可用 |
| 修改并发数 | 设置中是新值，当前运行信息仍是旧采用值；重启后才采用新值，不需要配置历史 |
| 启停中断连或重复请求 | 查同一次操作与实际进程；待核对时不重复启动，也不删除仍需核对的记录 |
| 繁忙重启或只启动一个服务 | 显示阻塞或部分运行原因；不假报就绪，不误停别的进程；更早详情查日志 |
| 更改默认workspace位置 | 后续操作使用明确位置，旧数据不搬运，已运行服务仍按原路径和进程核对 |

## 6. 本次删减及保留理由

| 原设计 | 本次处理 |
|---|---|
| WorkspaceIdentity及登记时间、搬迁／副本身份 | 删除；默认位置直接配置，当前不提供搬迁／复制服务 |
| ConfigurationRevision、候选指针、最近就绪版本 | 删除独立对象和历史；保留最新配置与实际采用值 |
| PlatformResourceVersion及资源统一身份 | 删除统一登记；复用清单，记录本次实际版本 |
| ServiceBoot、ReadinessObservation | 合入当前运行信息或即时查询，不保存启动批次与观察历史 |
| MaintenanceOperation通用维护模型 | 收敛到当前或最近一次启停结果，不建立历史列表 |
| DiagnosticEntry及通用证据关联 | 删除独立对象；使用普通日志及必要关联 |

进程身份、真实地址、繁忙拒绝、断连核对和敏感信息保护仍有明确用途，不能随对象精简一并删去。
