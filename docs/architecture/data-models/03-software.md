# ③ 软件接入数据设计

**设计方向已确认；安装、更新和调用均待实现。** 本文对齐[现行需求](../../requirements/README.md)与[③概要](../../../src/astrophotoflow/modules/software/README.md)，不规定表结构、接口或软件包格式。

## 软件包与必要信息

项目维护可安装的软件列表及下载地址。用户在网页选择安装，或让 Agent 通过 AstroPhotoFlow MCP 请求安装；具体软件、版本及影响统一在平台网页确认后才执行。一个软件包包含平台使用的固定版本软件专用副本及配套节点，安装完成后节点在前端可见，也可由 Agent 发现并加入工作流。仅暂存当前待确认动作，不建立安装计划表、审批账本或后台更新队列，详见[③详细契约](../../api/platform-contracts.md#software-design)。

| 信息 | 用途 |
|---|---|
| 软件包名称 | 在列表中识别软件 |
| 已安装版本 | 知道当前使用的固定版本 |
| 安装位置 | 找到平台安装的软件副本 |
| 当前可用状态 | 显示已安装、未就绪或可用及原因 |

列表及下载地址由项目维护；具体保存位置和格式留待实施。③目前没有业务模型、软件包管理或适配器实现；上述均是目标，不代表已提供接口。

## 实际使用

1. 选择软件包并安装软件与节点。Agent 只连接平台统一 MCP，不必分别连接每个软件的 MCP；软件内部通信方式按适配情况确定。
2. 若需登录或许可证，节点仍可见并提示未就绪原因，Agent 通过准备工具引导；用户在软件或平台界面输入敏感信息，Agent 不读取密码、许可证或验证码。
3. 用户或 Agent 把节点加入⑤工作流，⑤协调执行；③调用软件并报告可用情况与执行观察。实际输入使用科学数据，预览不替代原件。
4. ③负责软件包及可用状态，④负责节点定义，⑤统一负责工作流及实际运行；不在③复制运行记录。

## 更新与卸载

- 软件包更新前列出受影响工作流及参数变化，经用户确认后进行；软件正在运行时等处理结束再允许更新。
- 新版软件和配套节点替换旧版；参数发生变化时采用新版默认值。新版不提供的节点保留在工作流中并提示用户处理。
- 卸载后保留工作流中的节点并提示软件未安装；重新安装后能否使用取决于实际节点及版本兼容情况。
- 历史运行保留当时实际软件、节点及参数记录；旧软件不承诺长期保留，记录存在不保证更新后可复现旧运行。
- 此更新规则仅针对项目提供的软件包及其配套节点，用户自行制作节点另按[④数据设计](04-nodes.md)的确认更新规则处理。工作流参数更新及当次运行内容由⑤管理，具体交接见[③接口契约](../../api/platform-contracts.md#software)，新增能力仍待实现。
