# 五模块开发路线

产品目标见[现行需求](../../../requirements/README.md)，职责见[总架构](../../../architecture/overview.md)，对象见[数据设计](../architecture/data-models/README.md)，源码见[模块导航](../../../architecture/module-map.md)，实现和证据见[当前上下文](../../../development/current-context.md)与[验证矩阵](../../../development/test-matrix.md)。S0～S6仍是交付阶段，不是模块数量；完成设计不代表阶段验收。

## 1. 进入开发的条件

文档顺序：**总架构 → 五模块概要 → 全局数据设计 → 具体接口契约 → 近期任务与编码**。复用当前①②和ComfyUI基础，不重建环境，不因占位目录创建空实现。①公共、②数据、③软件、④节点概要保留；统一[⑤概要](../../../../src/astrophotoflow/modules/workflows/README.md)承接编排、执行与Agent交互。

[五模块接口与文件级详细设计](../api/platform-contracts.md)明确公开签名、关键文件、调用与测试归属，第④阶段已独立核对。[第⑤阶段近期实施计划](implementation-plan.md)按M1公共、M2数据、M3软件、M4节点、M5工作流／执行／Agent、M6综合验收拆分22个Batch。M1已获批准并集成dev，M2 B21～B24已集成但Milestone用户批准待完成；本地`demo`上B41候选通过、B31／B32进行中，B62仅做发行资源预检；B33、B42、B43及B51～B61共11卡未开工。M1～M6是近期里程碑，与S0～S6及模块编号分别表达；S6保留后续范围，不预建完整协议。

每个Batch的文件／完整关键签名／调用顺序／测试输入与命令只维护在计划所链六份任务卡。技术集成与用户Milestone批准分开；M3／M4按B31→B41→B32→B33→B42→B43交叉实现、同轮分别人工验收。S2起可做目录原型，真实精简MCP及素材移除公开协议在B57一次切换；此前保留58项注册，不为路线编号提前创建空工具。原生验收共享runtime采用已确认维护窗口，详见计划环境约束。

先锁定“一份数据、一个外部软件操作、一种节点、一条图、一次真实运行”，分别验网页和Agent。结果检查后仅用户选择完整结果入素材库；自动压缩预览不能冒充科学结果保存。两类输入保证、固定集合及资料纠正规则保持；字段和协议按实际任务细化。

## 3. 阶段输入、交付和出口

| 阶段 | 前置及交付 | 可观察出口 |
|---|---|---|
| S0 设计准备 | 当前需求、五模块概要、数据草案及源码事实；对齐近期数据／接口、原型与测量环境 | 责任和实际交接明确，不编造性能门槛，不因文档完成标记S0通过 |
| S1 ①公共基础 | 复用双服务／认证／配置，补默认workspace、实际地址、自动端口回写、性能重启生效及最近启停结果 | MCP正确复用或启动并返回网页地址，繁忙重启拒绝；目标和控制可核对 |
| S2 ②③⑤基础 | 固定数据、首个软件包／配套节点与真实操作，⑤Skill直达／按需检索及精简入口协议 | 科学输入可读，缺失／就绪明确；Top10／定义按需／明确关键词降级；未来58工具整体迁移及Skill同步不漏数据业务 |
| S3 ④⑤编排与测试 | workspace节点保存和确认更新，项目当前图原生自动保存／重开／另存、可选真实测试及最小接管 | 跨项目使用，参数新默认／仅断变化端口，保存／显示／执行分别成立；无永久逐编辑历史 |
| S4 ⑤真实运行 | 原生整图／受支持目标，两类输入保证，当次图与实际参数，③调用／取消核对，各执行图像节点自动预览，多次保存及所选完整结果登记 | 范围不静默缩小、缓存真实、在途内容不改；未知先查询，取消不假报停止，补登记不重跑，完整重跑新记录 |
| S5 ⑤双入口 | 活动网页MCP、手改接管／明确交回、原生同序撤销、切图暂停、后台预览归属及换Agent接续 | 不写错误图，旧请求拒绝，不抢视图；关闭网页对工作流只查询、已受理继续，非画布业务按所属规则提供，离线未确认如实显示 |
| S6 完整产品 | 跨软件、完整查看比较、本地偏好、固定结果显式续跑、Python／复合、导出治理和Windows交付 | 真实组合逐项验收，续跑复用已保存可用结果不冒充新处理；Linux／WSL后续验证，节点导出安装及Judge实际接入另行规划 |

①不等待所有远期维护功能才联调，真实繁忙和资源机制随模块补齐。②继续现有16模型与保护，结果按用户选择保存；③更新须确认影响且等待处理结束；④自定义更新按既定全参数默认及端口规则，不要求旧版长期并存。⑤细节和验收见[阶段出口](../../../../src/astrophotoflow/modules/workflows/README.md)。

近期按模块成套验收：M2完成②自身近期功能，画布采用／运行来源在B53／B54联调；活动输入清理及实现占用从B53首次运行前接入，B54复验真实状态。③④更新／卸载由B55，普通移除公开确认与MCP由B57一次闭合。不因早期模块单元通过关闭后置项；B57需M1～M4自身批准、B61需M5批准，B62完成后才最终批准M6，详见[近期计划](implementation-plan.md#acceptance-gates)。

## 4. 必须共同联调的组合

| 组合 | 交付和共同验证 |
|---|---|
| ②③⑤ | 科学输入、文件范围、实际调用、产物检查与所选完整结果保存；原件不变，预览不替代科学数据 |
| ③④⑤ | 软件包就绪、节点定义及确认更新，实际参数／端口，执行中内容保护及最近测试 |
| ①⑤与原生桥接 | 活动目标和当前控制、原生保存／改名／删除与项目关联、自动预览及任务归属、忙闲和取消 |
| ⑤接入层与真实客户端 | 数据业务保留，精简MCP整体迁移及Skill同步；已知能力直达、按需检索、安静接续和明确交回 |

原型门槛见[总架构](../../../architecture/overview.md#prototype-gates)：原生保存联动、在线控制、目标转换及缓存、真实软件停止、自动预览和跨图归属、运行持久记录与所选结果保存、精简MCP及热加载。先验证原生机制，不增加编译器、队列、预览调度器或通用恢复系统。

本轮只调整设计和文档，不构建、不做业务回归，不改环境、数据、MCP或Skill，不提交推送。新增能力继续待实现／验证，历史证据保留原范围。
