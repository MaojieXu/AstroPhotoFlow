# ②数据与资产管理数据设计

**状态：2026-10-27 按用户场景审计的设计草案。** 现有数据管理见[素材与存储](../../../../architecture/assets.md)及[模型源码](../../../../../src/astrophotoflow/modules/data/models.py)；下文明确标出的目标尚未实现。本次只修订文档，不改变数据库或实际行为。

## 1. 要解决的问题

用户导入素材、按项目选取单张照片或素材组，将其放进工作流处理，再选择需要保存的完整结果。系统应能找到原文件、保留项目实际选中的范围，显示导入进度及预览，并允许用户管理素材和个人偏好。

②负责素材、项目资料、设备、导入和素材库预览；⑤统一管理工作流、画布预览、实际运行和受控Agent业务交互，MCP协议仍归接入层。逻辑对象不等于需要新增数据库表。

## 2. 现有模型及作用

现有 SQLite 业务模型共 16 个，完整字段和约束以[模型源码](../../../../../src/astrophotoflow/modules/data/models.py)为准。下表按用途分组，不因精简文档删除任何模型或历史数据。

| 用途 | 现有模型 | 保存什么 |
|---|---|---|
| 项目 | Project | 项目名称、目标和备注 |
| 设备 | Equipment、EquipmentSetup、CapturePreset | 设备、使用组合和拍摄预设 |
| 素材 | Asset、AssetVersion | 素材身份、当前资料、内容记录及文件位置 |
| 项目引用 | ProjectAssetReference、ProjectDatasetReference | 项目选中的素材或素材组版本 |
| 素材组 | Dataset、DatasetVersion、DatasetMember | 组的资料及某次确定的成员、顺序和校准关联 |
| 回收站 | LibraryEntryRemoval | 素材／组移除及清理进度 |
| 导入 | AssetTask、AssetTaskItem | 导入任务、分项结果及重试关系 |
| 文件资料和预览 | FitsHduMetadata、Preview | FITS 数据单元资料及素材库显示缓存 |

项目通过数据库引用素材记录，素材记录保存实际文件位置，不因项目引用复制文件。导入可选择引用或托管，网页上传进入托管存储；已有行为见[导入流水线](../../../../development/import-pipeline.md)。

## 3. 素材、项目和固定范围

- 项目记录项目资料，引用单张素材或素材组；同一素材可被多个项目使用。名称和路径不是素材身份。
- AssetVersion 是现有内容记录，不代表用户需要管理版本号，也不保证外部文件的旧字节仍存在。**已确认目标**：外部文件变化后，用户确认所观察的新内容，沿同一Asset新增内部内容记录；仅明确选择的引用改用新内容，不改旧运行或其他固定引用。固定素材组仍须显式发布及更新选择。当前独立重导入建立新素材，这套接纳流程尚未实现，详见[②详细契约](../../api/platform-contracts.md#data-design)。
- DatasetVersion 固定一组成员、顺序及校准关联。例如项目选中 100 张，之后库中的组增加到 120 张，项目仍使用原来的 100 张；用户明确更新后才采用新范围。
- 素材当前资料可以修正。**目标**：下次运行自动使用修正后的资料，并记录本次实际采用值；过去运行不被改写。导入时的接收快照仍保存当时设备和预设信息，不随当前资料修改。
- **目标**：外部文件内容发生变化时，使用前提示用户确认；文件缺失也要明确说明。现有可用性与散列字段不代表这套确认交互已实现。移动或重定位流程不在本轮确定。

## 4. 导入、设备和预览

导入任务记录批次和分项，分别显示成功、跳过、失败及未完成；同批重复跳过，独立批次不自动合并，重试和恢复沿用已接受的设备／预设快照。设备资料、文件观察、人工值与未知分开，未知不猜测。

### 设备资料的目标

| 设备 | 目标界面所需信息 |
|---|---|
| 相机 | 名称；像元尺寸以一个字段呈现。原生位深不要求用户填写 |
| 望远镜 | 名称、口径、基础焦距；减焦镜／增距镜及倍率可选，有效焦距可记录实际值 |
| 滤镜 | 名称必填，带宽可选 |
| 赤道仪和配件 | 不要求用户登记；减焦／增距信息在望远镜参数中表达 |

按实际设备及处理需要填写；导入不强迫用户填写未知资料。以上是目标界面而非当前实现：现有设备类型、相机横纵像元字段、原生位深和其他规格仍存在；旧成像系统与望远镜的界面差异需要后续验证。设备组合和拍摄预设继续作为可选的重复输入辅助，不据此新增设备控制能力。

素材库的 Preview 是显示缓存，不是科学原件。FITS HDU 资料记录文件内部可解析的数据单元，不自动创建独立素材；视频预览不等于视频处理能力。科学处理使用实际文件及受支持的选择，不能以缩略图代替。

## 5. 结果、画布和移除

- **目标**：运行期间的实际科学数据可交给后续节点；完整中间文件不作为长期保存内容。用户明确选择后，将完整结果保存为素材，允许命名，未命名使用默认名；不按中间／最终或扩展名限制。未选文件不自动登记，素材库可显示缩略预览。运行状态和实际参数由⑤保存。
- **目标**：⑤的工作流画布可保存多次处理的压缩预览，随工作流保留；删除工作流时删除专属预览。画布预览与②素材预览分别归属；用户保存的完整素材不因删除画布预览而删除。重新处理依靠工作流、参数和实际可用输入，不保证缺失原件或环境时仍可复现。
- **目标**：移除被工作流使用的素材前显示受影响工作流；用户确认移除后保留节点并提示素材已移除，可重新选择。此能力仍需⑤②联调。
- 当前回收站区分移除、恢复和永久清理。外部引用原件不被永久清理删除；现有校准引用、活动导入、生成中的预览及共享路径的保护继续按[素材与存储](../../../../architecture/assets.md)和[校准说明](../../../../development/calibration-library.md)执行。用户确认不绕过这些既有约束。

## 6. 个人偏好和后续能力

**目标，尚未实现**：当用户表示结果满意时，外部 Agent 可结合项目背景总结色调、锐度、对比度等偏好，通过 MCP 自动保存；标明是 Agent 分析及来源项目。偏好可跨项目参考，用户可查看、修改和删除。用户表达、Agent 分析和执行事实分开；工作流及运行事实仍由⑤保存，平台不保存完整聊天或内置模型推理。

个人偏好保留修改历史：保存旧正文及必要修改时间、用户表达／Agent分析、来源项目等信息，用户可查看并恢复为当前偏好；后续读取采用当前启用内容，项目明确约定仍优先，用户明确表达优先于Agent分析，不改写旧运行事实。删除偏好包括当前和历史正文，索引、可控副本与备份的清除边界如实说明。此项仍待实现；不引入通用修订框架，不在本文确定物理表或接口，也不将其他记忆类别一概扩展为可恢复历史。

比较、指标及夜间汇总仍是后续目标：比较按实际场景确定，夜间汇总优先查询已有资料，用户明确选择后形成固定范围。当前不预先定义比较、共享、登记回执、来源和通用引用保护的独立对象或表；保存成功／失败、必要的运行事实和实际引用检查仍需表达。

  W -->|"运行时读取"| R["处理"]
  R -->|"多次压缩预览"| V["工作流画布"]
  R -->|"用户选择保存完整结果"| L["素材库"]

图中项目、素材及组的基础能力已有；工作流交接、运行结果保存、多次画布预览和 Agent 偏好为目标，不能从图推断已经实现。

| 场景 | 应当成立的结果 |
|---|---|
| 导入照片 | 接收实际文件和可得资料；失败、跳过和完成分开 |
| 项目选素材组 | 固定用户选中的成员；库中追加不改变已选范围 |
| 资料修正／文件变化 | 新运行采用修正资料并记录；文件变化提示确认 |
| 移除被使用的素材 | 先展示影响；确认后节点提示素材已移除，已有保护仍生效 |
| 重复处理 | 保留多次画布压缩预览；完整中间结果不长期保存 |
| 保存结果 | 用户选择完整图片，可命名或使用默认名；不自动登记其他文件 |
| 更换项目或 Agent | 已保存个人偏好可按需参考，标明分析及来源项目；历史可查看／恢复为当前，删除覆盖旧正文，不改过去运行 |

输入固定、文件变更确认、结果保存、工作流引用提示、画布预览和偏好均需在对应实施任务中验证；不在本文预定新 API、表、预览数量或清理期限。
