# ⑤工作流、执行与 Agent 交互数据设计

**工作流、执行与Agent交互统一归⑤；新增能力尚未实现。** 依据[现行需求](../../../../requirements/README.md)、[总架构](../../../../architecture/overview.md)与[⑤唯一概要](../../../../../src/astrophotoflow/modules/workflows/README.md)。2026-10-27确认项目关联、运行和预览关联沿用同workspace的SQLite，当前图及图片仍为文件；必要字段、公开签名和文件职责见[⑤详细契约](../../api/platform-contracts.md#workflows-design)。本文不提前设计代码执行环境或热加载方案。

## 1. 从实际使用出发

打开项目 → 读取原生工作流 → 人或 Agent 编辑当前画布 → 原生引擎运行 → 每个已执行的图像节点生成压缩预览 → 用户选择完整结果保存到②素材库 → 下次交互继续。

工作流、运行和Agent交互统一进入⑤业务模块 `workflows`。①公共、②素材、③软件包、④节点定义的职责保持；MCP协议仍属于接入层。该职责划分不增加服务，也不另建编辑器、图转换器或任务队列。版权、作者归属和发布认证不建立新的数据体系；原生图、节点和任务编号只用于正确定位。

## 2. 只保留四类必要数据

| 内容 | 保存什么 | 保存建议与现状 |
|---|---|---|
| 当前工作流 | 项目关联、原生图编号、名称和文件位置；实例、连线、参数、布局及固定数据引用沿用完整原生JSON | 原生文件是唯一当前图；项目关联为少量元数据，不另存可独立修改的图副本。保存加载已有，项目联动待实现 |
| 一次运行 | 当次编辑图和执行图、输入范围及两类保证、实际输入资料和参数、节点内容与软件信息、原生任务编号、开始结束及实际结果、错误和日志位置；有真实软件调用时记录必要调用事实 | 运行保留实际采用内容，不能只指向会被覆盖的当前图。原生队列、校验、事件及取消已有；跨重启运行记录、软件调用和结果交接待实现 |
| 多次完成预览 | 压缩预览文件、所属工作流、运行、节点及输出位置；通过运行定位当次参数 | 显示和事件复用原生；自动生成和多次持久保存待实现。允许一个节点有多个图像输出，不预设数量或保留期限 |
| 当前人工／Agent控制 | 该图是否允许Agent继续、识别过期请求的控制标记；写入时核对目标及当前内容 | 仅保存当前控制，不建立交接历史。内容校验不是永久修订历史；机制与桥接待实现 |

预检、准备、受理、取消、重跑来源及所选结果保存情况，都作为同次运行的必要信息，不预设各自的管理对象。实际进度直接展示；不把每次进度消息持久化成事件账本。④查询最近测试及运行链接，修改后说明旧测试针对旧内容，不复制测试权威。

## 3. 打开项目与编辑画布

首次交给Agent前先选项目、原生保存成功并建立关联；临时图仍用原生草稿，不预建服务端临时控制行。控制按图共享，不区分客户端；同一绑定目标仍允许时换客户端可继续，人工接管后保持撤销。

- 当前图沿用原生图编号和JSON文件；名称或路径改变时更新项目关联。原生会话实例编号不作为持久图编号，收藏专用的 `.index.json` 不用来存项目关系。
- 自动保存当前图；新项目图先落实保存位置，不能因原生只对已保存文件自动保存，就宣称新图已持久化。保留未完成编排和缺依赖JSON，保存成功不代表可执行。
- Agent日常使用局部原生操作改图，整图JSON仅用于导入或明确替换；当前内容校验值只用于防止覆盖，并非新增永久版本。
- 人与Agent共用原生会话撤销。重要方案用原生“另存为”保存为独立图；每次运行保存当次图和参数。**不保留永久逐编辑历史，也不承诺重启后找回所有未运行过的编辑。**
- 未同步内容沿用原生浏览器草稿，不另建服务端恢复草稿。断连如实显示；重连先读取实际保存内容，分歧不自动覆盖或合并。
- ②素材或素材组保持已选择的固定范围；素材资料修正后，新运行使用修正值并记录。素材移除前展示影响，确认后保留缺失节点供重新选择。
- ④节点更新前确认受影响工作流，实例参数全部采用新默认值；同方向名称和类型未变的连接含重排保留，变化端口断开。复合内部局部修改只影响当前工作流；S6安排不变。

## 4. 运行、预览与结果保存

1. 明确当前画布，原生运行前控件准备及`graphToPrompt`各一次，核对内容／控制和实际参数拓扑后原生保存一次，保存失败阻止提交；转换只是准备，不要求先存再转而引入双保存。异步期间人工变化明确阻塞，不自动再转或提交另一份；实际编辑图及执行图保存在本次运行中，不另建转换记录。
2. 默认可复现，必要时准备固定输入并说明成本，已有固定托管内容不重复复制；允许明确选择较弱的仅引用保证，准备失败不自动降级。运行选择不改变导入方式。
3. 通过ComfyUI提交、队列和图调度执行。整图或受支持的指定目标包含必要依赖；原生部分有效终点可继续执行，不代表平台可以静默缩小用户请求。普通中间节点怎样作为指定目标仍须原型。
4. 实际完成的图像处理节点生成独立轻量预览，经原生UI输出及 `executed` 事件显示；科学输出保持原样。不要求另加Preview节点，不把所有节点设为终点，不为预览运行其他分支。
5. 每次完成预览随所属工作流保留，不保存实时进度每帧。按原生任务编号关联运行和工作流，切到B后A的预览仍归A，不更新错误画布或抢回视图。缓存回放不记录为又一次实际处理。
6. 完整工作文件供本次后续节点使用，不作为长期保存内容。只有用户选择的完整结果交②保存，可命名或用默认名；不因生成预览自动登记素材。旧预览不证明完整文件仍在，保存时按实际可用情况说明。

运行中采用的内容和历史事实不因改图、节点或软件更新而改变。取消请求、实际停止、失败和未知分别说明；未知先查询，不自动重跑。用户请求保存但登记失败时先核对既有文件及登记，不为补登记重新处理。

完整重跑形成新运行；S6的显式续跑仅使用已保存且可用的固定科学结果，不依赖缩略图或旧内存缓存，不建立独立续跑计划对象。科学处理默认不跨运行自动复用，先验证原生 `--cache-none` 等实际机制，不新增缓存调度层。缺少旧输入或环境时不保证复现历史结果。

## 5. Agent 如何接续

首版用户在目标网页点击“交给Agent”绑定该页面当前图，不自动跟随其他页面；需要网页打开，且Agent目标与当前活动画布一致，才允许编辑或提交新运行。切换画布后暂停对原图的后续修改和新提交；关闭网页也不提供工作流新编辑／新运行，已受理运行继续，状态和列表仍可查询；②导入、③安装等非画布操作仍按所属规则提供。迟到请求不能落到新图，回到原图后仍要核对目标、内容和控制状态。

手动参数、节点、连线、布局或撤销触发接管；查看、平移、缩放或切换页签不触发。Agent不能靠重新读取、重连或新上下文取回写权，用户明确交回才能继续；接管不取消已有运行。离线接管尚未得到服务确认时如实显示。

手动变化后Agent保持安静；下次用户交互由经验证客户端／Skill读取明确目标的最新内容、同步和控制状态。已知Skill或工作流能力直接使用，需要发现才混合检索，最多10候选；完整定义按需读取，embedding不可用时明确关键词降级。目录派生自所属模块，不建立新的业务权威。普通操作连续进行；敏感操作由所属业务核对明确计划确认，不增加通用审批或身份平台。

工具受理、图保存、画布实际应用、引擎执行及素材保存分别返回真实结果；显示确认是当前连接观察，不建立永久回执对象。未来Judge只保留外部评价边界，完整聊天与模型会话继续在外部客户端。
