# 05｜素材、版本、运行来源与项目记忆

**这些能力全部属于首版，不因采用 Extension 而推迟。**

## 1. 数据原则

项目数据库保存关系与事实；文件对象库保存科学数据、快照、日志和预览。ComfyUI 的工作流 JSON 与 `/history` 是集成输入，不是完整业务数据库。[S14](08_调研来源与核验记录.md#s14)

所有长期数据放在独立可配置目录。卸载 Extension 或更新 ComfyUI 不自动删除项目。每个数据库迁移前备份，并提供失败后恢复路径。

## 2. 核心实体

| 实体 | 最小内容 |
|---|---|
| Project | 稳定 ID、名称、根目录、状态、创建时间、配置版本 |
| Workflow | 所属项目、稳定 ID、当前版本、兼容性与同步状态 |
| WorkflowRevision | 编辑图、执行图或其编译状态、图散列、父版本、变更来源 |
| Asset | 逻辑素材 ID、所属项目、角色、标签、原始导入信息 |
| AssetVersion | 内容散列、大小、格式、存储模式／位置、元数据、来源、可恢复性 |
| CollectionRevision | 固定的素材版本成员、顺序、筛选条件和排除记录 |
| Run | 工作流版本、输入集合快照、环境清单、状态、prompt_id、起止时间 |
| NodeRun / Attempt | 节点、操作版本、有效参数、job_id、日志、退出状态、重试关系 |
| Artifact | 输出文件、所属 NodeRun、输入来源、验证状态、预览或科学数据类别 |
| Metric | 指标值／不可用原因、单位、算法版本、ROI、样本量、所属结果 |
| ChangeEvent | 请求 ID、来源身份、变更前后、版本、审批引用、事件序号 |
| Conversation | 项目、提供方会话 ID、标准化消息、摘要与相关操作 |
| MemoryItem | 内容、来源、适用范围、状态、修订、更新时间与过期条件 |

表结构可在实现中拆分，但这些信息关系不能省略。跨实体引用采用稳定 ID，不能仅凭文件名或聊天中的自然语言描述关联。

## 3. 素材导入与索引

**引用导入：**保留外部位置，不在导入时复制原件。记录路径、大小、时间和可获得的内容指纹；文件被移动、删除或改写时显示状态。路径不能当作永久内容身份。

**复制托管：**复制到项目受控存储，计算内容散列，验证后再完成登记。导入中断不产生假完整条目。相同内容允许内部去重，但仍保留不同逻辑用途、标签和来源。

目录索引、元数据解析、散列、缩略图均作为异步任务；用户能看到待处理、失败和重试。文件夹与集合不是同一概念：集合可以跨目录，运行时冻结成员及顺序，后续目录变化不修改历史输入。

原始曝光、校准素材、处理中间结果、最终输出和展示预览分角色管理。原件保护默认开启。

## 4. 运行输入的真实性

“记录了文件路径”不等于“知道当时读到了什么字节”。引用文件可能在任务运行期间被其他软件修改。

首版默认提供**可复现执行模式**：预检后将输入物化到运行快照或已验证的内容对象库，再交给工具。复制或写时复制要保证后续外部写入不会改变快照；硬链接不自动满足这个要求。

用户可选择节省存储的“仅引用执行”，但须明确确认较弱保证：记录执行前后指纹、检测变化，无法证明全过程稳定时标记 `input_consistency_unverified`。这类运行可以保留结果，但不能显示为完整可复现。

因此，引用导入“不复制”与运行时“为复现建立快照”是两个不同选择。界面显示预计空间并允许用户决定，不隐瞒运行快照成本。

## 5. 每次运行必须保存什么

| 类别 | 内容 |
|---|---|
| 工作流 | 编辑图版本、实际 API 图、图散列、节点／端口映射 |
| 输入 | 素材版本、实际可读对象、内容指纹、集合成员与顺序、HDU／切片选择 |
| 参数 | 用户配置、连线来源、最终解析值、默认值展开结果、单位转换 |
| 环境 | ComfyUI／Frontend、Extension、适配器、工具版本、配置、相关星库或模型版本 |
| 执行 | run／node／job／attempt ID，时间、状态、退出码、日志、警告、资源信息（可获得时） |
| 输出 | 文件内容散列、格式与元数据验证、来源边、指标、预览及验证状态 |
| 权限 | 操作来源、审批记录、网络／上传授权摘要，不保存明文凭据 |

来源是一张图：某个结果可以由多个素材和多个步骤共同产生。保存直接父输入，再通过关系追溯完整链路，不能只记录“来自某次聊天”。

可追溯与位级可复现不同：即使版本齐全，硬件、并行算法或工具内部非确定性也可能影响数值。系统应记录已知限制，不承诺所有流程输出完全一致。

## 6. 结果登记与中间文件

外部工具先写 job staging 目录，完成后验证。通过的输出移入受控存储并登记版本；文件移动和数据库提交之间出现异常时，通过恢复日志核对，不让数据库指向不存在的文件。

中间结果也有来源与保留策略。清理前展示被哪些工作流、历史版本和记忆引用；原始素材、被保护结果和当前运行输入不得被自动清理。

派生预览可重新生成；缺失预览不等于科学数据丢失。失败任务的部分文件单独归类，不自动进入“最终结果”。

## 7. 历史与恢复

| 操作 | 语义 |
|---|---|
| 画布撤销／重做 | 修改当前图状态；通过统一变更服务形成可追溯提交 |
| 工作流恢复 | 以历史图为基础生成新当前版本，保留此前所有版本 |
| 素材恢复 | 仅在旧内容实际保留时可恢复；形成新版本引用或新物化内容 |
| 运行重现 | 从旧快照发起新的 run，重新预检环境，不把旧 run 改为新运行 |
| 聊天回退 | 调整上下文；不撤销已经发生的文件写入或外部处理 |

禁止把原生 Ctrl+Z 解释为全系统回滚。ComfyUI 面板的图撤销可以借鉴，但外部文件、项目数据库和软件会话需要各自的恢复规则。[S02](08_调研来源与核验记录.md#s02)

外部修改过的引用原件若未保存旧内容，就只能恢复旧记录和元数据，不能恢复旧文件。恢复按钮必须根据实际快照能力启用，不作虚假承诺。

## 8. 项目记忆

分为聊天历史、项目长期记忆、全局偏好。项目成员可访问同一项目的会话记录和经验，但不同会话有各自模型上下文，不强行混成一个提供方 session。

长期记忆保存经验内容、关联 run／结果／消息、适用对象、软件版本、置信或验证状态、启用状态和历史修订。优先按需检索，不在每次对话中注入全部历史。

自动提炼的经验先成为候选。来自用户明确确认或达到配置规则的候选才可成为启用记忆；“实验一次效果不错”不能自动升级成对所有项目适用的规则。

用户可编辑、停用和删除。删除或停用后立即停止检索；审计仅保留必要的动作信息。需要清除内容时连同索引及可控副本处理，备份保留策略明确说明，不能以“删了”掩盖内容仍在可检索副本中。

记忆与执行事实冲突时，执行记录优先。旧软件版本下的经验应显示适用性提醒；来源丢失或结果被判定无效时，可以停用相关经验。

## 9. 隐私、导出与存储治理

本地优先不等于自动完全离线。用户选择云端模型时，聊天、参数、元数据和预览可能离开本机；按类别显示并控制外发内容。原始 FITS 默认不上传。

项目导出至少包含工作流、版本与来源清单；选择“含素材”时只打包有权分发且已选择的数据。外部引用丢失、专有软件和凭据不得伪装成已完整导出。

存储页面显示原件、运行快照、中间结果、预览、日志与备份占用。清理是明确操作，提供影响预览和引用检查；运行期间禁止回收正在使用的对象。
