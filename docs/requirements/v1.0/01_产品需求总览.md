# 01｜产品需求总览

**版本：v1.0 · 2026-10-22**  
本文件定义目标需求。除引用的上游事实外，下述能力均为 AstroPhotoFlow 需要交付的产品要求。

## 1. 产品定位与用户

AstroPhotoFlow 是基于 ComfyUI Extension 的本地天文图像处理工作台。目标用户拥有真实天文素材，希望把分散在不同软件里的处理能力串成可视化流程，同时保留手动控制、Agent 辅助、科学数据精度和项目连续性。

首版面向一名本地用户，可以有多个项目、多个工作流、多个浏览器页签，但同一工作流不允许多个写入者无序并发。产品开源，不以商业计费、云端分发或独立桌面包装为首版目标。

## 2. 产品必须成立的五个条件

| 条件 | 用户能观察到的结果 |
|---|---|
| 操作真实发生 | Agent 的操作落到指定项目和工作流，有执行回执，而不是只生成说明 |
| 人机状态一致 | 手动和 Agent 交替操作，不出现两份互相覆盖的已保存参数 |
| 处理链路可运行 | 一个软件的输出能被下一个软件理解，不只是连上线 |
| 来源可回查 | 每个输出能查到具体输入版本、有效参数、软件环境和运行日志 |
| 项目可持续 | 关闭、重启后可继续；素材、历史和记忆不会随聊天会话消失 |

## 3. 首版范围

### 3.1 首版必须交付（P0）

| 编号 | 功能 | 需求与边界 |
|---|---|---|
| FR-01 | 项目管理 | 创建、打开、切换、归档项目；项目包含工作流、素材、运行、会话和记忆 |
| FR-02 | 原生工作流编辑 | 保留节点、连线、参数、保存和加载；托管工作流有版本及兼容性状态 |
| FR-03 | 适配包与能力目录 | 安装／禁用适配包、检测外部软件；一个软件一个分类，每操作一个节点；显示不可用原因 |
| FR-04 | 天文素材库 | 引用／复制导入、文件夹索引、标签、搜索、集合、FITS 元数据和预览 |
| FR-05 | 图像查看与结果比较 | 缩放、平移、显示拉伸、原图／结果／版本对比、相同 ROI 比较和指标解释 |
| FR-06 | 内置 Agent | 读取现场、拟定计划、编辑工作流、运行、读取结果、在授权范围内迭代 |
| FR-07 | 外部 Agent 接入 | 通过一个 AstroPhotoFlow MCP 入口访问同一项目、素材和工作流 |
| FR-08 | 统一变更与接管 | 版本校验、操作审计、事件同步、撤销；用户接管后阻止 Agent 继续写入 |
| FR-09 | 执行管理 | 排队、预检、启动、进度／日志、完成、失败、取消；状态必须与实际一致 |
| FR-10 | 完整运行来源 | 保存图快照、输入版本、有效参数、工具版本、输出、指标和错误 |
| FR-11 | 历史版本与恢复 | 工作流、素材和结果形成历史；恢复生成新版本，不删除历史 |
| FR-12 | 项目记忆 | 聊天、项目经验、全局偏好分开；经验有来源、启用状态和人工管理 |
| FR-13 | 环境与安装体验 | 缺失依赖集中确认、可查看安装计划；失败不污染已验证环境；重启后可继续任务上下文 |
| FR-14 | 本地安全与隐私 | 数据目录权限、工具授权、敏感操作确认、云模型数据披露、凭据隔离 |
| FR-15 | 可重复交付 | 明确版本组合、启动／诊断脚本、测试素材清单、源码及第三方许可说明 |

### 3.2 首版不承诺的能力（P1）

不做多用户协作、多 Agent 并发改同一图、云端集群、任意软件自动理解、任意 ComfyUI 第三方节点完全兼容、零重启动态注册、自动跨运行结果缓存、完整 PixInsight 支持或独立 decision model 训练。独立桌面安装包在本地闭环验收后开展。

“不支持”必须明确显示，不能悄悄降级到另一工作流、另一个项目或另一种数据格式。

## 4. 两种入口，一个项目

**工作台入口：**用户打开 ComfyUI，进入 AstroPhotoFlow 项目，自行编辑或使用内置 Agent。

**外部 Agent 入口：**用户在已有 Codex／Claude Code 等客户端中配置 AstroPhotoFlow MCP，直接访问同一业务服务。外部客户端自行负责模型推理，不能强迫它再调用一层内置 Agent。

浏览器关闭时，仍运行的本地服务可以处理项目查询、受支持的已保存工作流和任务。实时选中节点、当前视口、原生撤销等能力依赖在线前端。ComfyUI 的服务器 API 支持无浏览器提交任务，但不因此自动获得浏览器画布状态。[S14](08_调研来源与核验记录.md#s14)

## 5. 首版工作台交互

以下是信息布局要求，不是必须改造 ComfyUI 整体布局的要求。首版通过官方侧栏、底部面板和扩展视图实现；具体挂载位置在原型阶段验证。官方提供侧栏与底部面板 API。[S16](08_调研来源与核验记录.md#s16)

| 区域 | 必须展示的信息 |
|---|---|
| 项目状态区 | 当前项目、工作流、版本、未保存／同步失败状态、Agent 是否正在写入 |
| 节点画布 | 原生节点、数据连接、参数、执行状态；当前 Agent 目标明确可见 |
| Agent 区 | 对话、计划、变更预览、确认卡、真实工具回执、停止与接管 |
| 素材区 | 原始素材、集合、派生结果、过滤搜索、导入方式及可恢复状态 |
| 查看／比较区 | 科学数据来源、预览拉伸、缩放／ROI、对比版本和指标 |
| 运行／历史区 | 任务状态、节点日志、输入输出关系、版本差异和恢复入口 |

运行时不得因为 Agent 更新而不断抢占视图。用户选择“跟随 Agent”后才自动定位节点；否则仅提示变更。

比较视图必须说明对比条件：相同 ROI、相同／独立显示拉伸、是否已配准。不同尺寸或未配准结果不可伪装成逐像素对齐比较。指标缺失、不可计算和失败必须与数值零区分。

## 6. 关键用户旅程

### A. 手动开始，Agent 接续

用户导入素材，创建处理节点并调整参数。Agent 读取当前已确认版本、素材集合和选中节点，提出修改。用户确认后画布显示新值，用户可以接管或撤销。提交运行前保存并固定版本。

### B. Agent 构建，用户接管

用户提出目标。Agent 检查工具与输入，先展示流程计划和成本／资源约束，再创建节点和连线。用户点击接管后，Agent 的未执行写操作失效；当前外部任务是否停止另行明确处理。

### C. 软件缺失

预检列出缺失的软件、适配包、星库或权限，以及来源、版本、下载量（可确定时）、安装位置和是否需要重启。用户一次确认该明确计划；计划扩大时重新确认。安装后重新扫描、校验并恢复上下文，不盲目重放可能已经执行的处理步骤。

### D. 比较与继续

用户或 Agent 运行两个参数版本。工作台按同一原始素材来源展示两个结果，支持指标和图像比较。用户标记优选版本，可将结论及运行来源保存为项目经验。下次打开项目后从指定版本继续。

## 7. 第一条真实流程

首条标准流程以一组许可清晰的天文 FITS 素材为输入，完成：

> 导入与检查 → Siril 校准／配准／叠加中与素材匹配的步骤 → ASTAP 天文定位 → 结果登记、预览与比较 → 项目经验保存。

首个开发小闭环可以只实现“已有校准序列 → Siril 配准／叠加 → 预览”；但正式首版验收需要跨两个实际软件，并验证 CLI 与 MCP 两种适配通道。MCP 通道可使用自己实现的受控 FITS 分析示例，不强行依赖 PixInsight。

Siril 官方支持无界面脚本执行；ASTAP 官方文档给出命令行定位、星库依赖与结果文件格式。这只证明接入路径存在，不证明本项目适配已经可用。[S11](08_调研来源与核验记录.md#s11) [S12](08_调研来源与核验记录.md#s12)

## 8. 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-01 | 项目数据库和托管文件独立于 ComfyUI 安装目录；更新代码不覆盖项目数据 |
| NFR-02 | FITS 大文件不得全量进入浏览器或模型上下文；索引、散列和预览异步执行 |
| NFR-03 | 长任务不阻塞 UI；未知进度显示阶段／运行时长，不编造百分比 |
| NFR-04 | 服务异常后区分失败、未知、待核对；不得把失联任务自动标为成功 |
| NFR-05 | 核心手动处理不依赖云模型；调用云端模型时明确可能外发的文字、元数据、预览或文件 |
| NFR-06 | 在 D0 指定基准机器与数据规模后测试性能；性能目标是验收目标，不冒充已测结果 |
| NFR-07 | 对当前受支持节点集保证协议一致性；超出集合显式标记“未验证／不可托管” |
| NFR-08 | 操作、任务和结果使用关联 ID；可从一次失败定位到节点、适配器和日志 |

详细验收用例见 [07](07_实施路线与验收清单.md)。
