## 1. 产品定位与目标用户

AstroPhotoFlow 是基于 ComfyUI 源码构建的本地可视化工作流平台，以天文图像处理为主要业务场景。用户管理真实素材、制作节点、编排外部软件操作，查看和比较真实结果，并保存版本、来源及可复用经验。

面向一名本地用户，允许多个项目、工作流和浏览器页签。用户在网页工作台手动操作；外部通用 Agent 通过 AstroPhotoFlow MCP 操作同一份数据与工作流。目标是减少使用和学习门槛：用户表达目标，Agent发现工具、准备环境、制作节点、逐步运行并检查结果，网页提供可见状态与人工接管。Agent推理、聊天交互和模型会话由外部客户端负责，产品不内置Agent；本地embedding仅用于工具检索。

产品成立需要满足：操作命中明确目标且真实发生；人和 Agent 看到一致的已确认状态；跨软件数据交接可运行；结果能回查输入、参数与环境；关闭、重启或更换 Agent 后仍可继续项目。

当前体系为五模块。工作流、执行和Agent交互统一归⑤；当前图复用原生JSON，重要方案另存，每次运行保存当次内容。新增功能仍待实现或验证。

## 2. 范围与交付边界

| 范围 | 要求 |
|---|---|
| 首个真实闭环 | 一份固定数据、一个真实外部软件操作、一种标准节点、一条工作流、一次真实运行，结果检查后由用户选择完整结果保存到素材库；分别验证网页手动与外部 Agent 入口 |
| 完整产品 | 五模块有效需求，包含跨软件交接、节点制作、工作流方案保存及资产版本、运行来源、比较与恢复、本地上下文记忆、冲突处理与用户接管 |
| 当前交付平台 | Windows 优先；安装、运行、外部软件及发行能力按实际版本组合验收。核心手动处理不依赖云模型或生成式图像模型 |
| 后续平台目标 | Linux／WSL 保留后续交付目标，独立记录平台与工具兼容性，不能用 Windows 证据代替 |
| 待原型验证 | 标准节点热发布；须验证新增节点、草稿保留、旧图加载及运行中的实现不变，才能声明支持 |
| 工具选择 | Siril、ASTAP、PixInsight 为接入候选；③的实施任务锁定首个软件、具体操作、版本、依赖与测试素材。列出候选不构成已经接入或完整支持该软件的承诺 |
| 软件包与工具发现 | 平台管理固定版本的软件及配套节点，前端与Agent查看同一目录；全部业务工具用本地embedding＋关键词混合检索，每次最多10个候选，完整定义按需读取；模型不可用明确降为关键词检索 |

明确排除：内置Agent、聊天界面、Agent推理或生成式模型后端、模型提供方凭据管理、完整聊天归档、客户端会话同步及模型内部状态恢复。本地检索用embedding不属于上述生成式模型后端，也不使本地记忆默认向量化。多用户协作、多个Agent无序并发改同一图、云集群、任意软件自动理解、任意第三方节点完整兼容、自动跨运行科学结果缓存、独立decision model训练均不属于本基线交付承诺。独立桌面包装不是本地网页闭环的前置条件；任意核心代码原地热替换不承诺支持。

首个闭环是阶段出口，不等于完整产品交付。已有能力继续保留，待实现和未验证范围以当前上下文及证据为准，不因本文归并而标记完成。

## 3. 关键用户旅程

| 旅程 | 用户或外部 Agent 的操作 | 可观察的成功结果 |
|---|---|---|
| 导入与组织 | 选择引用或托管方式，上传或从授权目录导入，补充资料、设备及预设，组织集合与项目引用 | 登记、原件可用、解析及预览状态分别可查；项目和集合指向明确版本，失败与可重试项可见 |
| 整夜目录到目标处理 | 按实际入口导入目录，汇总今晚目标及历史关联；用户选择目标和今晚／历史范围，Agent按Skill或已有workflow逐步编排、运行和调参 | 只处理今晚不自动加入历史目标帧，范围固定且疑义不自动合并；参数、工作流、实际结果及最终采用项可追溯 |
| 从叠加结果继续 | 拖入已叠加素材，建立固定版本的数据引用节点，读取项目背景后由人或Agent继续处理 | 原件或固定科学结果作为输入，预览只用于查看／评价；引用、图和运行分别留痕，已有原生拖放不冒充该能力已实现 |
| 手动制作与编排 | 填写节点端口参数及执行内容，保存到节点库后加入画布，可以按需试运行 | 各项目可使用；最近测试及加载问题可查，更新确认后参数和连线按FR-16处理 |
| Agent 接续与用户接管 | 外部 Agent 读取项目和当前已保存图，通过 MCP 提交变更；用户继续修改、撤销或接管 | 操作命中指定项目和图，过期内容不覆盖新编辑；当前连接核对实际显示，接管后旧写授权失效 |
| 预检与运行 | 检查软件、权限和数据；固定输入与当次图内容后提交，查看进度与日志，必要时取消 | 实际执行与记录一致；检查实际输出并在运行中记录来源；仅用户选择后保存完整素材。失败、未知、取消请求和已停止分别表达 |
| 依赖缺失与恢复 | 查看缺失软件、适配包、星库及安装计划，授权明确计划后安装并重新检测 | 安装失败不破坏已有环境；恢复任务上下文前核对已发生操作，不盲目重跑 |
| Agent发现并逐步构建 | 固定流程优先Skill／workflow及已知能力直接调用，需要新能力时才检索工具／节点库节点／软件操作，读取定义并制作或复用节点 | 前端与Agent同一目录，候选分型及就绪明确，搜索最多10项且降级可见；后续编辑不改在途快照，结果检查后可查看，用户选择后登记 |
| 比较、恢复与记忆 | 比较两组参数的结果，标记选择，保存经验；从另存方案或运行用图继续 | 对比条件及指标来源可查，恢复保留历史；经验关联实际运行与适用条件 |
| 重启或更换 Agent | 重新打开项目，外部客户端按需读取背景、偏好、最新工作流、运行与交接摘要 | 能依据本地记录继续工作，无需平台持有原客户端完整聊天或模型会话 |

网页保持原生画布与侧栏：节点库下依次为素材库、工作流，侧栏可调宽和收起，设备管理位于导入旁。项目、版本、草稿、同步失败和运行状态应可辨认。Agent 变更不自动抢占视图；用户选择跟随时才自动定位。

以下四类详细场景补充上述旅程索引，不替代依赖恢复、比较、历史、记忆和跨次接续。正常流程允许纯手动完成，或由外部Agent在明确任务范围内连续操作；具体实现状态仍以当前上下文为准。

### 3.1 导入与整理

2026-10-28 来源选择交互修订：文件与文件夹选择窗口关联点击导入时的桌面宿主，打开时置前一次，关闭后返回宿主；不持续抢焦点或全局置顶。取消网页选择或离开组件同时关闭本次系统选择窗口；同一服务同时只打开一个导入选择窗口，重复请求明确反馈，不叠加后台窗口。文件范围、托管和资料规则保持。

2026-10-28 设置呈现修订：工作台设置隐藏“授权导入目录”整块表单及相关增删、路径提示控件，避免与直接选择本机来源混淆。只改变呈现；已有import_roots配置及旧接口保留，保存其他配置时原样保留隐藏值。

2026-10-28 用户修订来源规则：网页导入直接打开本机文件／文件夹选择器，后端读取用户本次选择的绝对路径，不再要求先配置授权根目录或限制在预设目录内。文件夹仍只选择当前层支持素材，确认数量／大小后采用托管副本。HTTP／CLI／MCP可省略root_id并提交绝对path走同一托管链路；现有root_id＋相对路径及上传接口保留。此条覆盖此前“网页必须先配置授权目录”的约束，不改变平台服务认证、支持格式、受理范围冻结、来源变化检查及科学原件保护。

### 3.2 数据进入画布与安静接续

2026-10-28 Nodes 2.0 展示补充：素材库加入操作改为行右侧悬停／选中／键盘聚焦时出现的图标，缩略图保持可拖放。固定引用节点默认显示名称、单张预览、成员前后切换及原图尺寸／曝光／滤镜／ISO或Gain／温度；相机、Offset、Bin、CFA、格式及像素类型由原生只读详情弹窗查看。图像组按引用内固定顺序逐张读取，参数属于当前成员；尺寸来自固定版本，拍摄资料使用素材库当前值，不按缩略图猜尺寸。JSON隐藏但继续作为唯一执行及保存引用；展示不改变科学原件、不自动执行、不将静态预览冒充运行结果。

2026-10-28 本轮实现范围：共享素材库单件或固定图像组通过“加入画布”按钮／原生拖放加入当前活动图或子图，复用 ComfyUI 节点创建、撤销和草稿保存。组按固定版本保存全部有序成员，不受列表搜索、分页影响；原件未就绪时禁止加入，预览不作为科学输入。节点类型统一为 `APF_DATA_REFERENCE`，唯一 `reference` STRING 控件保存既有 InputReference；不建立新素材、不复制原件、不主动提交运行。MCP／CLI 直接加入网页中已授权的活动画布；用户从素材库更多菜单“交给 Agent（加入素材）”明确交回此项控制。手动编辑、切图／子图或断线撤销；查询和重连不恢复。客户端指定页面、根图、当前子图、内容与控制标记；迟到请求拒绝，未知结果查询同一 operation_id，不自动重复添加。只返回实际应用事实，不把引用准备、原生草稿或自动保存推成文件已保存或运行已提交。当前候选及未执行验收见验证矩阵，完整项目绑定、通用改图与运行能力仍由后续批次交付。

| 场景要素 | 说出要处理的数据，由Agent加入画布 | 用户拖入素材后请Agent继续 |

### 3.5 贯穿场景的结束、异常与接续

处理完成后，用户查看结果、提出反馈，Agent把修改对应到当次图内容及实际运行；比较后明确采用、继续尝试或手动接管。用户明确选择哪些完整结果保存到素材库，不按中间／最终分类限制；其他工作文件不长期保留。新增一晚素材时明确独立处理或加入指定历史范围，明确采用的集合范围，更新当前图并产生新运行，不改旧事实。

依赖缺失时查看明确安装计划；普通任务连续进行，安装、永久删除、覆盖原件、外发及付费操作仍需明确计划确认或具体预授权。取消请求、Agent停止回答、实际软件停止分别处理；断连或登记失败先核对已有操作，恢复历史图、补登记和重新执行分别交所属模块，不盲目重跑。

关闭、重启或更换Agent后，依据②项目及有效记忆、⑤保存图与实际运行与主动交接摘要继续，不要求平台保存完整聊天；图控制状态跨客户端共享；读背景不恢复已撤销写权。节点导出及他人安装继续作为后续目标，包格式、渠道、接收平台及交付阶段未定。以上分别沿用FR-01／05／11～14／16、NFR-01／04／07／08和AT-17～27／29～31，不重复新增编号。

工作流推荐数量和排序、具体分批依据、视频工具及格式组合、Python执行封装、依赖方案和客户端接续协议留待后续设计。图、输入、版本与控制状态的正确性由实际提交处保证；Skill指导及接续体验需要真实客户端验证，不能写成平台能够强制任何外部模型每轮读取。取舍见[场景决策ADR](../../frontend/docs/adr/WORKBENCH-SCENARIOS-0053-context-and-scientific-inputs.md)。

## 4. 功能需求

以下阶段沿用第 8 节的 S0～S6。阶段表示该能力的最小可联调交付和后续完善范围，不改变已有功能；跨模块需求由公开入口协作，不复制业务权威。

### FR-01 项目与工作连续性

- **归属与阶段**：②保存项目资料，⑤关联项目工作流、运行及预览；S2固定数据、S3项目图，S6完整连续性。
- **用户目标与行为**：创建、打开、切换、归档和管理项目，一个项目有多条工作流；关联固定素材／集合、背景及记忆，重开后从保存图、运行记录和多次预览继续。
- **边界**：项目通过②数据库引用素材；当前图使用原生workspace内JSON文件，⑤只补项目与原生图编号／位置的关联，不另存可独立编辑的图副本。复制／另存产生独立图，跨项目不扩大素材访问；外来JSON需明确关联项目，不自动取得项目关系。
- **验收**：重开、改名、另存和切换对应正确项目及图；素材组范围固定。归档及删除保持既有原件和活动任务保护，工作流专属预览可随图删除；导出说明图、素材、软件及缺失范围，不捆绑凭据或无权分发内容。

### FR-02 原生工作流与画布

- **归属与阶段**：⑤，S3当前图保存／另存及重开，S5完整在线协作。
- **用户目标与行为**：复用原生画布及JSON加载，以workflow或Skill为起点，拖入②固定科学引用，编辑节点、连线、参数和布局；Agent日常以局部操作改图，整图JSON用于导入或明确替换。自动保存当前图，重要方案用原生另存，撤销复用会话内共同编辑顺序。
- **边界**：连续输入不逐帧永久存储，不建立永久逐编辑修订、服务端恢复草稿或独立转换对象。浏览器本地未同步内容与保存图分开；重连先核对实际保存，分歧不自动覆盖／合并。缺依赖JSON保留待修复，不自动安装或替换；API图不承诺恢复原布局及子图。首版Agent编辑／新运行需明确在线活动画布，关闭网页后不新编辑工作流或提交运行；②导入、③安装等非画布操作仍按所属规则提供。转换使用原生graphToPrompt，实际图保存在当次运行。
- **验收**：保存重开后原生图及固定数据引用正确，节点更新遵循FR-16；允许保存未完成编排但不冒充可运行。运行用图／参数可查，另存保留独立方案；重启不承诺恢复每次未运行编辑。缺失、不支持转换及未同步状态明确。详见[⑤概要](../../src/astrophotoflow/modules/workflows/README.md)。

### FR-03 软件适配与能力目录

- **归属与阶段**：③负责软件包，④提供配套节点，⑤负责工作流及运行，⑤提供统一发现；S2开始首个软件包，随阶段联调。
- **用户目标与行为**：项目维护软件列表及下载地址，用户在网页选择或通过Agent请求安装固定版本软件专用副本及配套节点；安装／更新的具体软件、版本及影响统一在平台网页确认后执行。MCP受理待确认不等于已安装；前端展示节点，Agent只连接AstroPhotoFlow MCP并可发现节点、加入工作流。软件内部通信方式按实际适配确定。
- **准备与维护**：登录或许可未完成时节点仍可见并说明原因；Agent 通过准备工具引导，用户在软件或平台界面输入敏感信息。更新前列出受影响工作流和参数变化并由用户确认；软件运行结束后更新，软件和配套节点替换为新版，变化参数使用新版默认值。新版缺失的节点及卸载后节点保留在图中并提示。
- **边界及验收**：③管理名称、已安装版本、安装位置和可用状态，⑤记录实际运行版本与参数。旧软件不承诺长期保留；历史记录不改写，但不保证能复现旧运行。本规则不改变用户自制节点的版本设计。安装、登录、发现、真实执行、确认更新和卸载均须实际验证；当前尚未实现。AT-02、AT-03、AT-25、AT-33。

### FR-04 数据、素材与业务资料

- **归属与阶段**：②，S2 提供稳定数据交接，S6 完善检索、文件治理及业务操作。
- **用户目标与行为**：引用或托管导入，单图和批量上传、授权目录索引；管理分类、标签、元数据、搜索筛选排序、集合成员与版本；保留项目、设备、使用组合、拍摄预设和校准关联。完整场景补齐夜间目标汇总、历史关联及必要项目背景，用户选择今晚／历史后形成明确固定输入。按钮和Agent入口承接同一业务规则；Agent查看实际可得构成后组织参数并分批导入，汇总成功、跳过、失败和未识别项。视频登记、静态预览和固定科学输入交接分别表达，详见[导入场景](#scenario-import)及[处理起点](#scenario-processing)。
- **边界**：物理文件夹与逻辑集合分开；登记、托管、解析和预览各自报告状态。人工值、文件观察和预设保留来源，未提供、null和0分别处理。外部内容变化经用户确认后沿同Asset新增内部内容记录，只在明确选择的节点／引用采用；固定组不得原地改写，旧运行及旧版本内容事实不改，不承诺找回被覆盖旧字节。设备、预设及版本保留当时快照；校准关联固定目标版本并支持默认、继承、不使用及成员覆盖，绑定本身不等于执行校准。
- **验收**：引用与托管的文件行为可区分，索引和版本可查，重试沿用已接受快照；修改或删除设备不回写历史，同一素材在不同集合的校准配置互不覆盖。夜间汇总保留目标来源和疑义，不凭文件名自动合并；只处理今晚不自动加入历史目标帧。移动、改名、重定位和导出保持身份及可用性说明；现有OBJECT及target_name字段不等于完整场景已实现。

- **边界**：科学原件默认只读，敏感授权及控制由服务在实际提交处验证；自然语言、客户端自报身份、Skill、工作流、Header、日志、工具文本和模型意见不扩大权限。平台保护自身令牌及适配器所需凭据，不管理模型提供方账户；外部Agent自带权限和云端使用由客户端负责，模型或索引不替代授权。
- **验收**：错误身份、越权路径和越界操作被拒绝；日志、工作流、导出及网页资源不泄漏服务令牌。MCP 返回的背景、参数和预览可能进入客户端模型上下文，按目标与必要范围读取，原始科学文件不默认外发。

### FR-15 可重复交付与维护

- **归属与阶段**：①及各模块，S1 建立基础，S6 完成 Windows 交付；Linux／WSL 后续独立验收。
- **用户目标与行为**：按文档安装、构建、运行、诊断、卸载、升级和恢复，核对平台、工具与依赖版本、源码来源和支持范围。
- **边界**：workspace数据独立于程序资源；数据库schema迁移前提供数据备份与失败恢复方案，升级不能覆盖原件或令牌；软件包按FR-03确认替换。上游源码与测试素材保留来源和许可，不将参考项目默认变成运行依赖，也不承诺 Registry 或独立桌面包装已支持。
- **验收**：锁定版本组合可重建；发行 wheel 在仓库外安装可运行且用户无需 Node／Git，sdist 可在无 Node 环境重建；说明匹配实际入口、迁移、资源和支持平台，诊断导出排除凭据及不必要的私人内容。

### FR-16 节点构建、测试、保存与更新

- **归属与阶段**：④管理节点定义，③提供操作，⑤管理实例及更新，⑤协调真实试运行。S3验证一种软件操作节点，S6支持Python函数及复合节点；导出和他人安装保留目标，格式、渠道及阶段后续确定。
- **用户目标与行为**：自定义节点在同一workspace节点库统一管理，保存后各项目可使用，测试通过不是使用门槛。保留标识、名称说明、输入输出、参数默认值及实际执行内容；常用／高级展示保持，科学格式和单位只声明实际需要的内容。节点详情从⑤读取最近一次测试及链接，修改后说明旧测试针对修改前内容。
- **边界**：更新前列出受影响工作流，经用户确认后统一替换；实例参数全部采用新版默认值，不做旧参数兼容验证。自定义节点输入名各自唯一、输出名各自唯一，名称和类型未变的端口保留连线，包括重排；改名、改类型或删除则断开对应连接。执行中任务保持已采用内容，历史事实不改写，不要求旧版长期并存。③软件包配套节点仍按FR-03，不将此命名规则扩大到任意第三方节点。复合节点在工作流内的内部修改只影响当前图，不回写节点库和其他工作流。用户代码按本地可执行代码处理，具体环境另行设计。
- **验收**：保存、加载、加入图、运行和最近测试查看分别成立；测试失败可以保存，旧测试不冒充新内容已通过。跨项目更新先确认影响，参数重置、端口增删改及重排符合规则；复合局部副本不影响其他图。加载失败及未就绪原因可见。热加载及执行中内容保护须原型验证，不从前端刷新推定支持。详见[④概要](../../src/astrophotoflow/modules/nodes/README.md)及[④数据设计](../architecture/data-models/04-nodes.md)。

## 5. 数据与科学处理规则

以下规则约束 FR-02～FR-05、FR-09～FR-12、FR-16 的设计与验收；当前实现细节见[素材与存储](../architecture/assets.md)、[导入流水线](../development/import-pipeline.md)、[预览](../development/library-preview.md)、[设备及预设](../development/settings-organization.md)、[校准关联](../development/calibration-library.md)。

| 主题 | 必须保持的业务规则 |
|---|---|
| 身份与引用 | 项目通过数据库引用素材，素材记录保存文件位置；集合固定选定成员及顺序，新增成员需用户明确更新。资料修正后新运行采用修正值并记录，历史运行不改；文件内容变化时提示确认，交互待实现 |
| 状态与来源 | 登记、原件可用、元数据解析、预览就绪分别表达；人工输入、文件观察、预设与未知保留来源，不用文件名猜测替代已声明规则 |
| 业务快照 | 接受导入时冻结组合、预设和设备资料，重试沿用；设备修改或永久删除保留历史快照；校准目标固定版本，继承、null 和覆盖分别表达，不以清空旧绑定绕过引用保护 |
| 数据交接 | 已登记素材通过稳定引用交接，包含实际输入所需的版本、集合顺序和HDU／切片选择；同次运行的上游工作文件可经⑤明确交给后续节点，不必先登记为素材。工作目录和输出属于明确任务；序列文件及关联帧共同交接 |
| 输入真实性 | 默认可复现模式，在执行前物化或使用已验证固定内容，显示准备与空间成本；已有固定内容无须每次重复制，准备失败不自动降级。可明确选择仅引用执行并记录较弱保证及前后变化检测，无法证明稳定时标记未验证；保留结果不等于完整可复现，运行选择不改变导入方式 |
| 科学格式 | 保留 FITS 等科学格式及明确数值精度；类型、缩放、单位转换有记录。支持的 HDU／切片明确选择，不支持的立方体、压缩或表格明确报告；重采样、裁切或配准后的 WCS 更新、验证或标为无效 |
| 预览与指标 | 科学原件只读，预览独立且可重建；不能将 JPEG、缩略图或普通显示张量当作完整科学文件。指标关联算法、单位、ROI、样本量和处理阶段，缺失值不当成 0 |
| 结果与来源 | ⑤记录实际输入、参数和运行事实；用户选择后才将完整结果登记为素材，可命名或使用默认名。素材详情不要求完整步骤和来源展示；保存失败先核对，不盲目重跑 |
| 结果归属与共享 | 用户可选择任何具体结果加入同一 workspace 素材库，不按中间／最终分类或扩展名限制；未选文件不自动登记，完整中间文件不作为长期保存内容。多次画布压缩预览随工作流保存，删除工作流删除专属预览 |
| 生命周期 | 已有共享原件、历史校准、导入及生成中的缓存按实际规则保护；目标是在移除素材前展示受影响工作流，确认移除后保留节点并提示重新选择。已有阻塞条件不因确认而绕过 |

可追溯不等于位级可复现；软件算法、硬件或并行执行造成的不确定性如实记录。上述目标不能反向表述为移动、节点输出登记或完整来源链已经实现。

设备资料目标：相机像元尺寸以一个字段呈现，不要求填写原生位深；望远镜可记录减焦／增距附件及倍率，滤镜仅名称与可选带宽；赤道仪和配件可选登记。设备管理以组合为主要入口，组合内可选择或新建可复用设备；项目页面从此模块移出，项目数据及其他模块能力保留。设备、组合和拍摄预设确认影响后直接删除，不经过回收站；删除设备移除组合关联并清除预设设备默认值，历史素材、固定版本与已受理任务保留设备快照。现有设备字段及类型暂不改变，详见[②数据设计](../architecture/data-models/02-data.md)。

设备组合允许选择多片滤镜；每个拍摄预设从所属组合选择本次使用的一片滤镜，未指定时沿用组合默认滤镜。增益模式支持Gain及Offset。预设名称由可选的用户前缀和滤镜、曝光、温度、ISO或Gain／Offset参数后缀组成；参数变化同步更新后缀，保存前显示完整名称，数值0不省略。既有设备、预设及导入快照规则保持。

设备组合和我的设备默认隐藏记录选择框，通过“更多→批量管理”显式进入选择模式；取消全部勾选仍保留模式，点击完成退出，搜索、分页及切换页签清空勾选并退出。普通设备选中后在该行显示编辑，继续复用新建表单。按钮、菜单、页签和批量复选框复用宿主ComfyUI原生组件及主题，设备类别使用非选择控件形式的图标。

## 6. 本地上下文记忆

### 6.1 保存内容与范围

| 类别 | 本地保存的内容 | 作用域与来源 |
|---|---|---|
| 用户偏好 | 审美倾向、色彩／背景与细节偏好、常用处理方式、操作习惯 | 工作区级；用户明确表达与 Agent 推断分别标记，项目约定可覆盖但不回写全局偏好 |
| 项目背景 | 对象与目标、素材与设备背景、处理约束、质量要求、当前进展和待办 | 绑定项目；关联实际资产、工作流与运行，项目之间隔离 |
| 工作流经验 | 适用条件、方案选择、参数经验、优选结果、已知失败及适用软件版本 | 绑定项目或用户明确保存的复用范围，引用固定工作流、运行及结果身份 |
| 交接摘要 | 当前目标、已确认决策、已做事项、未完成问题及建议下一步 | 用户或外部 Agent 主动提交；注明来源与关联对象，供重启或更换客户端后读取 |

工作流、运行和资产仍由所属模块保存权威事实，记忆通过引用关联它们，不另建一份可编辑的执行真相。自然语言审美偏好是用户目标，不被当作客观科学指标。

### 6.2 写入、检索与治理

- 用户和外部 Agent 可通过受控平台操作保存和管理记忆。用户表示结果满意后，外部 Agent 可结合项目背景总结偏好并通过 MCP 自动保存；注明来源项目和 Agent 分析，与用户原话及执行事实区分，不作为科学结论。
- 按当前项目及任务读取必要背景；个人偏好可跨项目参考并保留来源项目，项目约定仍按其作用范围使用，不在每次调用中塞入全部历史。
- 提供查看、修改、停用、删除和修订信息。个人偏好保留旧正文及必要的修改时间、用户表达／Agent分析和来源项目等信息，用户可查看并将旧内容恢复为当前偏好；后续读取采用当前启用内容，不把历史内容全部注入Agent，也不改写旧运行。只为偏好保存必要历史，不扩展为通用修订或审批框架；其他记忆类别沿用既有要求，不据此统一承诺历史恢复。
- 停用或删除后立即停止检索；删除个人偏好包括其当前和历史正文。若有索引、可控副本与备份，如实说明内容清除和保留边界，审计不继续保存已要求清除的正文。
- 适用性仅按来源能否定位、记录的软件版本差异及用户标注提供事实提醒，不自动判断偏好或经验是否有效；与实际工作流或运行事实冲突时，以对应权威记录为准。
- 摘要由用户或外部客户端主动写入，平台不自动获取完整聊天、不保存模型私有状态、不承诺恢复客户端原会话，也不为提炼记忆引入内置模型。

本地保存保证项目资料持续存在；当用户允许外部 Agent 读取时，返回内容仍可能被其客户端发送给模型。平台说明自身返回范围，不能承诺控制客户端服务之外的数据使用。

## 7. 非功能需求

编号随相关能力首次交付开始验收；完整产品阶段补齐全部有效要求。这里定义约束与测量方法，不报告当前测试通过情况。

| 编号 | 现行约束 | 验收方法 |
|---|---|---|
| NFR-01 | 程序资源与 workspace 数据分离，更新和卸载程序不自动删除原件、版本、配置与本地记忆 | 在隔离数据上验证安装、升级与恢复及配置目录定位，核对身份、内容和引用；当前不提供workspace搬迁服务 |
| NFR-02 | 科学大文件不为显示或 Agent 上下文全量加载到浏览器内存或模型上下文；索引、散列、复制和预览异步、有可见状态 | 固定尺寸和文件数的数据集测任务状态、内存和可交互性；查看及 MCP 只传必要资料／预览，上传不要求浏览器全量解码科学图像 |
| NFR-03 | 长任务不冻结 UI；未知进度用真实阶段、时长和日志表达，不编造百分比 | 同时操作画布、侧栏和任务视图，核对实际进度与界面状态 |
| NFR-04 | 异常后区分失败、未知和待核对；断连不自动视为成功，不盲目重复副作用 | 对提交后断连、服务重启、工具未退出和登记失败分别核对运行、进程及产物 |
| NFR-05 | 核心手动功能不依赖云模型或生成式模型；平台管理的本地embedding只用于工具检索，模型不可用明确关键词降级；本地记忆按需交付 | 无Agent生成式模型配置仍可手动处理；检索降级及原因可见，科学原始文件不默认外发，聊天与Agent推理由外部客户端负责 |
| NFR-06 | 性能门槛依据固定基准确定，不编造“秒开”“超大文件流畅”等数值承诺 | S0 记录机器、平台、版本、素材及指标；能力交付前确定对应门槛并写入验证矩阵，实测与目标分别记录 |
| NFR-07 | 对明确受支持的节点、数据格式、软件和平台保持协议及版本一致；范围外明确未验证或不可托管 | 测受支持组合的保存、加载、执行及升级；特殊节点、失效依赖和未支持平台不静默降级 |
| NFR-08 | 操作、当次图内容、节点、运行、尝试、产物和日志之间可关联，错误可定位且凭据脱敏 | 从一次失败的操作或结果追溯到请求、输入、实现及日志，诊断内容不泄漏令牌 |

性能基准任务在S0建立测量清单：冷／热启动、导入和索引吞吐、首次预览、图变更提交与确认、事件重连、运行日志及峰值内存，新增工具目录规模、embedding加载／索引更新、检索耗时及Top10相关性。记录CPU、内存、磁盘、系统、软件／模型版本，文件数量、大小、格式、HDU、图规模和并发条件；相关能力具备后补测并确定门槛。现有基准和未解决限制保留证据，未定门槛不能写成性能验收已完成。

## 8. 阶段交付与成功标准

完整依赖顺序见[开发路线](../development/platform-roadmap.md)。①达到可联调基线后，②③与⑤基础入口可并行；④⑤尽早联调，再由⑤打通实际执行，⑤完成整体协作。每一阶段已有数据与原生行为继续保留。

| 阶段 | 交付范围 | 阶段出口 |
|---|---|---|
| S0 需求与边界 | 明确当前闭环、数据引用、节点定义、当前图保存、运行结果与性能基准任务 | 近期任务的责任和验收可对应；工具、素材和具体契约在相关实施任务锁定，未定项不写成现有能力 |
| S1 公共基础 | ①及 FR-13～FR-15 的基础环境、workspace、认证、版本和诊断 | 隔离 workspace 可运行，客户端访问同一服务，数据独立且启停真实 |
| S2 数据与软件基础 | ②固定数据，③固定软件包及一个操作，⑤精简入口／整体迁移、已知能力直达和按需混合检索 | 输入可读、就绪原因及同一目录可查，Skill／参考／协议测试同步，不留旧入口，搜索Top10及显式关键词降级成立 |
| S3 节点与工作流 | ④⑤联调FR-16／02／01／08，⑤真实试运行基础，⑤最小接管 | 一种节点制作、保存、可选测试、连接、保存重载，支持Skill／JSON起点；最近测试对应被测内容，手动改图及旧提交核对成立 |
| S4 首个真实运行 | ⑤联调FR-09、FR-10及②登记，支持整图／受支持目标、两类输入保证、核对补登记和完整重跑 | 固定数据、图、范围与实现后真实执行，输出可读且来源可查；失败、取消请求与实际停止可辨，未知不盲目重跑 |
| S5 双入口协作闭环 | FR-07／08及运行用图／另存方案恢复，与⑤整体联调 | 网页和Agent同一类闭环，手动接管／明确交回、多页签、离线待确认／重连冲突及各环节真实结果返回成立，换Agent共享当前图允许状态，但不恢复已撤销控制，用户选中结果可保存到素材库 |
