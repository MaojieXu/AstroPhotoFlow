# 数据库与图像资产管理实施计划

**更新日期：2026-10-22；关联任务：T01。**

**主要需求：FR-04；同时落实 FR-01、FR-10、FR-11、FR-14、FR-15 中与资产直接相关的基础约束。**

本模块先完成真实天文素材的持久化资产管理，为下一步 AI Panel 和 Agent 数据管理提供同一领域 API。第二阶段完成应用内单文件／文件夹批量导入、资料直接编辑、版本化数据集、项目选用、后台任务及 FITS 元数据／预览，并在服务重启后继续查询和恢复未完成任务；删除沿用归档及移除关联，不物理删除原件。

持续目录索引、标签搜索、高级集合组织、手动 HDU／切片选择和多类型深入解析保留为后续候选；第三阶段拖入画布及资产引用节点也暂缓。这些不作为当前数据库闭环或合并门槛。基础数据集、成员版本及本次任务恢复能力仍属于第二阶段，不因暂缓第三阶段而删减。

当前阶段范围与交付顺序以[资产管理实施计划](资产管理三阶段实施计划.md)为准，接口分别执行[第一阶段技术与接口设计](第一阶段技术与接口设计.md)及[第二阶段技术与接口设计](第二阶段技术与接口设计.md)。第二阶段 S2-AT-01 至 S2-AT-10 已验收，实际证据见[第二阶段验收记录](第二阶段验收记录.md)；本文保留全量需求与 A0 至 A7 的参考拆解，不能将其当作当前执行清单。

本模块统一采用本机单用户跨项目共享库；项目通过既有内部记录 ID 引用资产，中间产物归属项目。共享不表示互联网公开。此约定取代早期“所有资产必须归属一个项目”的设计。

第二阶段采用最新简化规则：每个导入批次独立建档；分类、拍摄参数和备注直接编辑，项目及数据集显示资产最新资料，不建立图像资料修订历史。人工明确填写值优先，原始 Header／文件解析值独立保留，设备默认值不自动追写资产。列表和进入项目不扫描原件、不复算散列；使用时缺失或读取失败再提示，不建设来源变化确认、监控或自动更新。数据集固定成员版本仍保留。与这些规则冲突的早期图像版本约束不再作为第二阶段验收要求。

返回[开发总计划](开发计划.md)。数据与恢复规则以 [05 素材版本与项目记忆](AstroPhotoFlow_Requirements_v1.0/05_素材版本与项目记忆.md)为基线；FITS 与端口边界见 [03 软件适配与科学数据协议](AstroPhotoFlow_Requirements_v1.0/03_软件适配与科学数据协议.md)。

### 素材角色

资产至少区分科学输入、校准素材、处理中间结果和最终结果；派生预览单独登记。第二阶段的 Subframe／Masterframe／Video 与 Light、Bias、Dark、Flat、Dark Flat 分开记录，Master Light 不自动视为最终成品。ISO／Gain／常规模式仅控制人工参数填写，Mono／Bayer／RGB 另表图像结构。Siril 等适配器接入后再增加其实际需要的角色细分。

科学文件与派生预览分别登记。内容已成功入库时，解析／预览失败不撤销成员资格，独立显示问题；未完成的暂存或登记不能作为成功内容。按本阶段范围不支持解析／预览的非 FITS 正常入库。

## 三 技术落点与存储结构

采用需求基线中的 Python 领域服务、SQLite 和文件对象库。SQLite 保存资产关系与状态，大文件保存在文件系统；前端及后续 MCP 调用同一领域服务。单个服务进程负责业务写入，文件复制、散列和解析不占用长数据库事务。

后端采用独立 FastAPI 服务，使用 SQLAlchemy 2 同步 ORM 与 Alembic；数据库启用外键和 WAL，短写事务使用 BEGIN IMMEDIATE，迁移前通过 Python 标准库 SQLite 备份接口生成一致备份。FITS 读取采用 Astropy，显示转换采用 NumPy 和 Pillow，均在第二阶段实际接入时安装。Python 环境使用 uv 管理，依赖在领域服务环境中固定；ComfyUI 扩展只提供同源薄代理，不导入服务 ORM 或科学处理依赖，也不启动服务进程。前端沿用 Vue 3、TypeScript、Vite、Tailwind 4，资产状态与接口契约使用 Pinia、Zod。

服务、前端扩展入口及测试代码按现有架构职责建立；先提供资产当前需要的模块，不预建其他 19 项任务的完整代码骨架。

两个进程读取 `~/.config/astrophotoflow/config.toml`，默认 `data_dir=~/.local/share/astrophotoflow`，允许用户明确指定独立目录。第一阶段仅使用数据库、服务令牌、管理锁和必要备份；托管原件、预览与暂存目录从后续对应能力首次实现时建立。所有托管路径相对数据目录保存，外部引用位置另行记录。

```text
<data_dir>/
  astrophotoflow.sqlite3
  service.token
  backups/
  objects/<asset_version_id>/source.fits   # 第二阶段起，路径不强制绑定项目
  previews/<preview_id>.jpg               # 第二阶段起
  staging/<task_id>/                     # 第二阶段起
```

第二阶段复制模式下，每个独立导入条目保存自己的托管内容，不以路径或散列跨批次合并条目或做物理去重；引用模式记录来源路径。分类／参数／备注直接编辑，不生成新内容记录或复制大文件。BLAKE3 在导入时计算并保存，不在进入列表或项目时复算。第一阶段仅约定该字段，不读取文件或计算散列。

第二阶段在应用内文件页面浏览配置的素材根目录，以根目录 ID 和相对路径选择 WSL 文件或目录，可包含挂载盘。默认引用，可切换复制托管；不通过浏览器上传代替路径引用，也不自动猜测 Windows 与 Linux 的路径映射。

## 四 数据模型

### 核心实体

以下包含第一阶段实体及后续扩展；仅前七项进入第一阶段初始迁移。第一阶段字段以其技术文档为准，第二阶段增量以第二阶段技术文档为准；后续候选实体不预建，在获准开发时再细化。

| 实体 | 主要字段或关系 | 建立时机 |
|---|---|---|
| Project | `id`、名称、目标、说明、状态、revision 及时间 | 第一阶段 S1–S2 |
| Equipment | `id`、固定 kind、名称、型号／序列号、类型化 specs、状态、revision 及时间 | 第一阶段 S1–S2 |
| CaptureProfile | `id`、设备关联、帧类型、可空拍摄默认值、状态、revision 及时间 | 第一阶段 S1–S2 |
| ProjectCaptureProfile | 项目与多份拍摄配置的关联集合，不表示处理顺序 | 第一阶段 S1–S2 |
| Asset | `id`、范围、名称、当前分类／参数／备注、用途、状态及 revision | 第一阶段只读；第二阶段增加当前资料直接编辑及归档／恢复 |
| AssetVersion | 保留第一阶段内部内容 ID、存储位置／方式、导入散列及文件解析记录，供关联与预览定位 | 第二阶段不将其作为资料修订历史；显示及分类／参数筛选以 Asset 当前资料为准 |
| ProjectAssetReference | 项目引用固定 `asset_version_id` 及加入时间 | 第一阶段 S1／S3，只读 API |
| FitsHduMetadata | 素材版本、HDU 索引／名称／类型、维度、像素类型、缩放、单位、原始 Header、常用检索字段及解析器版本 | 第二阶段；手动 HDU／切片选择后续扩展 |
| Preview | 素材版本、自动选定 HDU、100／1024 px 派生预览、显示参数、算法版本、文件引用、状态及错误 | 第二阶段；切片预览后续扩展 |
| AssetTask | 任务 ID、共享／项目范围、任务类型、目标资产／版本或索引目录、阶段、状态、已处理数量、错误及起止时间；导入任务保存暂存与最终位置 | 第二阶段起，不进入第一阶段迁移 |
| AssetTaskItem | 逐文件来源、阶段、内容结果、解析／预览状态、关联资产／内容记录、错误及重试来源 | 第二阶段，无分类／来源变化确认状态 |
| Dataset / DatasetVersion / DatasetMember | 数据集身份、固定成员版本及顺序；增删成员产生新版本 | 第二阶段，替代下述旧 Collection 命名 |
| ProjectDatasetReference | 项目引用固定数据集版本，不自动展开或跟随最新成员 | 第二阶段 |
| IndexedFolder | 项目、根路径、导入方式、递归选择、扫描任务及最近扫描状态 | A5 |

旧称 Collection／CollectionRevision／CollectionMember 对应 Dataset／DatasetVersion／DatasetMember 的固定版本语义，不建立两套重复模型。标签、成员手动排序及高级集合组织列为后续候选，不属于当前数据库闭环。

### 数据约束

- Asset 保存当前用途、分类、参数与备注，直接编辑后所有关联页面显示最新资料。AssetVersion 保留既有内部内容记录及导入信息，路径不替代关联 ID，不为资料编辑新增图像版本。
- 导入散列、大小、原始 Header 和文件解析值记录当次读取结果；不以此承诺外部文件永久不变，不自动检测变化或创建新版本。
- 当前人工分类决定 `role` 及校准级别；科学参数与备注可直接维护。原始 Header 和文件解析记录不被人工值覆盖，设备默认值不自动追写资产。
- 数据集成员引用固定内部内容 ID，保留成员与顺序；资料编辑不增删成员，但成员展示和筛选使用资产最新资料。
- 散列采用 `blake3:<hex>`；尚未完成导入的内容不能当作成功成员。第二阶段不开放 Node／MCP 执行，也不增加它们的输入预检；后续运行输入契约由 T02／T07 另行落实。
- 同一内容散列可对应不同逻辑素材，数据库不以散列唯一约束合并这些用途。
- 外键和服务查询共同保证共享／项目范围；共享库不返回项目私有资产，项目只引用共享或本项目资产的指定版本，不能越界读取其他项目私有内容。共享资产当前版本改变不修改项目既有引用。
- 设备和拍摄配置的 revision 用于默认值并发修改保护；其编辑或归档不自动改写资产资料。资产当前资料编辑受 Asset revision 保护，失败不部分提交。
- 第二阶段资料修改不建立图像历史；人工明确填写值优先，导入时未填写项可采用文件解析值。Master 单帧曝光与累计曝光不混用。
- 第二阶段数据集增删成员产生新版本，旧成员顺序保留、新成员追加；项目选用指定数据集版本。归档不删除版本、原件或既有引用。
- 后续 T08 在首次产生科学处理输出时增加运行／节点产物来源关系。当前导入版本从创建时保存实际导入来源，避免用空运行记录替代来源。

常用索引围绕项目内列表、资产版本、标签关联、集合成员顺序及 FITS 筛选字段建立，以实际查询为依据。

## 五 导入与文件发布流程

### 引用导入

1. 接收根目录 ID、有序来源列表、导入方式、本批默认分类、可选设备／参数及备注；第二阶段统一进入共享库，不提供项目私有导入。核对来源在允许范围内及读取权限。
2. 在短事务中登记后台批次及所选来源，返回 HTTP 202 与任务 ID；后台枚举时再逐文件登记处理记录。受理不等于枚举完成、入库或解析成功。
3. 在后台读取文件并计算导入散列，保存内容记录；实际读取或登记失败则报告失败，不进入来源变化确认流程。
4. 保存原始 Header／文件解析值，采用本次人工填写的分类和参数；未填写项可用文件解析值补充，差异不阻塞任务。
5. 生成自动选定图像的预览，内容、解析及预览结果分别展示；内容成功即可成为数据集成员，解析／预览失败独立告警。

引用文件仍可能在之后被外部软件修改。导入完成仅建立本次读取记录，不提供永久不变保证；列表和进入项目不扫描原件，之后需要读取原件时才访问路径，找不到或读取失败再提示。不将已有缓存预览解释为原件刚刚验证可读。

第二阶段单文件形成独立资产，多选／文件夹形成一个数据集；文件夹递归、保留相对路径，不按子目录自动拆组。同批重复来源只处理一次，跨批同文件独立建档，不合并资产或数据集。部分失败保留内容成功项；数据集初版在批次结束或取消时发布，零成功内容不发布空数据集。

### 复制托管

1. 登记任务、目标版本 ID、源位置和暂存位置。
2. 将文件复制到该任务专用 staging 目录，计算散列并核对实际复制大小及暂存内容；读取或复制失败明确记录，不发布未完成内容。
3. 关闭并完成暂存文件校验，保存任务的已验证内容信息和预定最终位置。
4. 将已验证文件发布到该版本独有的受控位置，再用短事务提交可用版本；不覆盖已有版本文件。
5. 从托管文件解析元数据并生成预览。科学文件发布成功后，解析或预览失败分别保留其错误状态。

文件发布和数据库事务分别完成。中断后由用户恢复原任务，依据该任务阶段、目标位置及已记录信息继续未完成登记，不核对整个素材库；已经成功登记的内容不重新复制或建档。无法完成的项报告错误，不自动重跑整批或删除文件。用户选择项重试时另建关联新任务，保留原尝试。

### 按需读取与后续目录管理候选

第二阶段不建设导入后的文件变化监控、确认、自动更新或全库可用性扫描。目录索引／重扫列为后续候选，须另行明确范围，不能被实现为每次进入列表或项目的检查。

| 场景 | 处理规则 |
|---|---|
| 引用源被删除或移动 | 使用时找不到或读取失败再提示，保留资产及关联记录，不后台扫描 |
| 引用源内容改变，路径不变 | 不检测、不确认、不自动更新；按使用时内容读取，已存导入信息不冒充最新检测结果 |
| 托管导入的源文件后来变化 | 不监控原来源，托管条目继续使用自己的已复制文件 |
| 同一索引根目录下既有文件未变化 | 复用既有索引关系，更新扫描观测，不重复制造资产 |
| 目录出现新文件 | 按该索引目录明确的导入方式创建条目 |
| 文件被重命名 | 按旧位置缺失、新位置发现处理；不根据相似名称猜测身份 |
| 预览文件缺失 | 显示预览不可用，提供重新生成；科学文件状态独立 |

第二阶段不提供全库完整性检查或变化确认入口。BLAKE3 用于导入记录及本次托管发布，不在页面加载时重新计算。后续实际科学运行的输入要求由相应任务另行确定，不能借此扩展第二阶段。

“引用导入”与“仅引用执行”分别配置。T07 接入执行时，默认将输入物化为内容已验证的快照；仅引用执行采用需求基线规定的明确授权和较弱一致性标识，不能把硬链接当成不可变快照。

## 六 FITS 解析与预览

### 元数据

先读取 Header 和 HDU 描述，避免为了列表展示而加载完整像素数组。保存下列信息：

- 文件格式、HDU 索引、名称及类型。
- 图像维度、BITPIX／像素类型、BSCALE、BZERO、BUNIT 及无效值约定。
- 可获得的目标、曝光时间、滤镜、观测时间、仪器信息与 WCS。
- 按原始卡片顺序保存的 Header，保留重复的 COMMENT／HISTORY 等信息；常用检索字段另行提取。

保留 FITS 原始字段及其含义。缺失字段不猜测默认值，科学数值零与缺失不同。损坏 FITS 返回可定位到文件及解析阶段的错误；已复制的字节是否完整、能否解析、能否预览分别展示。

### 支持范围

第二阶段保存 HDU 描述，自动选择首个支持的 Mono／具有明确 CFA 信息的 Bayer／具有明确通道含义的 RGB 图像；不提供手动 HDU 切换或通用切片界面。手动选择及类型专属查看列为后续候选；本阶段支持状态由固定版本测试清单声明。

不可预览的 HDU 可保留其可解析描述，并显示不支持原因。初次按已声明规则自动选定后，处理失败不换用其他 HDU；不把任意三维数组推测为 RGB，也不把元数据缺失改写为有效值。

### 显示转换

第二阶段预览只读取自动选定的图像 HDU，记录显示范围、拉伸预设、降采样尺寸和算法版本。Bayer 按已确认 CFA 信息生成彩色显示，Mono／RGB 自动拉伸；生成最长边 100 px 缩略图和 1024 px 详情 JPEG，保持宽高比，不放大小图。完整高级拉伸、切片与比较界面由后续阶段及 T09 扩展。

缩略图和浏览预览写入独立目录。处理无效像素时记录显示规则，无法生成预览则提供不可计算原因。科学文件不经过 PNG 转换后再进入处理主链路。

预览身份包含素材内容散列、HDU、切片、显示参数及生成器版本。不同条件的预览不能误用同一缓存结果；复用派生预览不登记为一次新的科学处理。

## 七 后台任务与状态展示

使用服务内受控后台工作执行本次导入枚举、复制、散列、元数据、预览和任务恢复，任务记录持久化到 SQLite。初期按实际文件处理顺序安排工作，不引入分布式队列或全库可用性检查。

| 状态维度 | 展示内容 |
|---|---|
| 任务状态 | 排队、运行、正在取消、完成、部分失败、失败、取消、中断；保留阶段、错误和任务 ID |
| 内容登记状态 | 未完成、成功、失败；实际使用中发现的缺失／不可读单独提示，不表示全库刚经检查 |
| 元数据状态 | 待处理、可用、失败、不支持 |
| 预览状态 | 待处理、生成中、可用、失败、不支持或文件缺失 |

文件总数或字节总量已知时展示实际完成数量；未知工作量显示当前阶段和运行时长。前端不能把数据库中已有条目解释为所有后台工作已完成。

目录批次报告逐文件结果，部分失败与全部完成可区分。重试由用户明确发起，保留此前尝试记录；取消结果在实际文件工作及枚举安全停止后确认。报告通过任务及来源的 `enumeration_completed` 标明是否完整枚举，不为未枚举文件生成 ID、数量或成功结果。

重启后保留未完成任务，用户通过 resume 恢复原任务，只处理该任务未完成部分；通过 retry 选中失败或未完成项时创建关联新任务。内容已成功入库的项只重试失败处理阶段，不再次登记资产。不自动恢复队列或重跑整批，不把失联任务标为成功。取消保留成功内容，实际安全停止后才报告 cancelled。

主动取消后的 `retry` 仅接受已经枚举并登记 ID 的逐文件项，不继续目录枚举，`resume` 也不接受 cancelled 任务。尚未枚举的来源由用户在文件页面重新选择范围，显式另建导入批次；重新选择整个原目录会对已有文件再次独立建档，界面必须说明。零已枚举项不提供空重试，零成功内容不发布空数据集。

向已有数据集追加成员发生 revision 冲突时，保留成功资产和任务发布错误，不覆盖当前成员。正常结束任务为 completed_with_errors，已取消任务保持 cancelled。报告返回数据集 ID、冲突 revision 及未追加的内部内容 ID；用户通过现有成员编辑入口，读取当前成员后以最新 revision 手动补入。原任务错误保留，不重新处理成功文件阶段，也不新增专用恢复接口。完整契约见[第二阶段技术与接口设计](第二阶段技术与接口设计.md)。
