# 数据库与图像资产管理实施计划

**更新日期：2026-10-22；关联任务：T01。**

**主要需求：FR-04；同时落实 FR-01、FR-10、FR-11、FR-14、FR-15 中与资产直接相关的基础约束。**

本模块建立真实天文素材的持久化资产库，为后续 Node、MCP 和运行服务提供统一的数据入口。首个可用交付应完成：导入一个 FITS 文件，查看元数据与预览，通过稳定版本 ID 再次查询，并在服务重启后继续访问。

完整资产模块还包括目录索引、标签搜索、集合版本、多 HDU 选择、引用文件变化检测及导入异常恢复。这些仍属于首版 P0，按下述实现批次逐步交付。

返回[开发总计划](开发计划.md)。数据与恢复规则以 [05 素材版本与项目记忆](AstroPhotoFlow_Requirements_v1.0/05_素材版本与项目记忆.md)为基线；FITS 与端口边界见 [03 软件适配与科学数据协议](AstroPhotoFlow_Requirements_v1.0/03_软件适配与科学数据协议.md)。

### 素材角色

资产至少区分原始曝光、校准素材、处理中间结果、最终结果和展示预览。首阶段通过导入时选择及人工编辑角色建立这些信息；Siril 等适配器接入后再增加其实际需要的角色细分。

科学文件与派生预览分别登记。预览生成失败不改变原始文件的完整性状态，失败任务的部分文件不进入成功结果列表。

## 三 技术落点与存储结构

采用需求基线中的 Python 领域服务、SQLite 和文件对象库。SQLite 保存资产关系与状态，大文件保存在文件系统；前端及后续 MCP 调用同一领域服务。单个服务进程负责业务写入，文件复制、散列和解析不占用长数据库事务。

首批实现使用 Python 标准库 `sqlite3` 管理数据库及明确版本的 SQL 迁移；FITS 读取采用 Astropy，显示转换采用 NumPy 和 Pillow。依赖在领域服务环境中固定，ComfyUI 薄节点通过服务访问资产。

服务、前端扩展入口及测试代码按现有架构职责建立；先提供资产当前需要的模块，不预建其他 19 项任务的完整代码骨架。

建议配置 `data_dir`，本机默认位置采用 `/home/maojiexu/.local/share/astrophotoflow`，允许用户明确指定其他位置。所有托管路径相对该目录保存，外部引用位置另行记录。

```text
<data_dir>/
  astrophotoflow.sqlite3
  objects/<project_id>/<asset_version_id>/source.fits
  previews/<project_id>/<preview_id>.png
  staging/<task_id>/
  backups/
```

首阶段每个托管版本保存自己的文件，内容散列用于身份核对；相同内容的不同逻辑素材保留各自用途、标签和来源。物理文件去重在确有存储需求后另行实现。

外部导入路径使用 WSL 路径。Windows 浏览器提交本地用户明确选择的 WSL 文件或目录；不在第一阶段自动推测 Windows 与 Linux 的路径映射。

### 数据约束

- Asset 表达逻辑用途；AssetVersion 表达具体内容版本；物理文件是否仍存在是可用性事实。文件路径不能替代素材版本 ID。
- 版本的内容散列、大小及已解析科学信息绑定其观测内容。引用源变化后保留旧记录，显式确认后登记新版本，不把旧版本元数据覆盖为新内容。
- 标签和角色属于逻辑素材。预览参数变化生成对应派生预览，不制造新的科学内容版本。
- 集合成员引用固定的 AssetVersion，包含顺序及图像选择。目录更新或资产出现新版本不修改历史集合成员。
- 内容散列统一采用 SHA-256，允许在后台计算期间为空，此时显示待处理。完成身份核对前，该条目不作为已固定科学输入交给节点或 MCP 执行。
- 同一内容散列可对应不同逻辑素材，数据库不以散列唯一约束合并这些用途。
- 外键和服务查询共同保证项目归属；ID 不能被用于越过项目范围读取其他素材或预览。
- 后续 T08 在首次产生科学处理输出时增加运行／节点产物来源关系。当前导入版本从创建时保存实际导入来源，避免用空运行记录替代来源。

常用索引围绕项目内列表、资产版本、标签关联、集合成员顺序及 FITS 筛选字段建立，以实际查询为依据。

## 五 导入与文件发布流程

### 引用导入

1. 接收明确的项目、文件列表、导入方式和角色，核对用户授权的源路径及文件读取权限。
2. 在短事务中登记后台任务及待处理资产／版本，并返回任务 ID。
3. 在后台读取文件观测指纹，流式计算内容散列，解析元数据；核对处理期间源文件是否发生变化。
4. 保存本次观测的内容身份和元数据状态，生成指定图像预览；前端显示每个步骤的真实状态。
5. 若处理期间检测到变化，将条目标记为需重新核对，保留诊断；不将读取到的混合状态登记为已确认输入。

引用文件仍可能在之后被外部软件修改。导入完成仅建立本次观测，不提供文件永久不变的保证。预览及重新解析前要核对版本与源内容的关系。

### 复制托管

1. 登记任务、目标版本 ID、源位置和暂存位置。
2. 将文件复制到该任务专用 staging 目录，计算散列并核对实际复制大小及暂存内容；检测到复制期间源变化时明确失败。
3. 关闭并完成暂存文件校验，保存任务的已验证内容信息和预定最终位置。
4. 将已验证文件发布到该版本独有的受控位置，再用短事务提交可用版本；不覆盖已有版本文件。
5. 从托管文件解析元数据并生成预览。科学文件发布成功后，解析或预览失败分别保留其错误状态。

文件发布和数据库事务分别完成。服务启动时根据 AssetTask 的阶段、目标位置与已记录散列核对未完成发布；已经发布且内容匹配的文件可继续登记，文件仅存在不能作为成功依据。状态无法确认时显示待核对，不盲目重新复制或删除文件。

### 源文件变化与目录重扫

| 场景 | 处理规则 |
|---|---|
| 引用源被删除或移动 | 旧版本显示缺失；保留记录；没有保留旧字节时显示旧内容不可恢复 |
| 引用源内容改变，路径不变 | 标记变化，保留旧散列与元数据；用户确认后创建新版本 |
| 托管导入的源文件后来变化 | 记录源变化，已验证托管版本继续指向原有内容 |
| 同一索引根目录下既有文件未变化 | 复用既有索引关系，更新扫描观测，不重复制造资产 |
| 目录出现新文件 | 按该索引目录明确的导入方式创建条目 |
| 文件被重命名 | 按旧位置缺失、新位置发现处理；不根据相似名称猜测身份 |
| 预览文件缺失 | 显示预览不可用，提供重新生成；科学文件状态独立 |

快速指纹用于发现疑似变化，内容散列用于内容身份核对。用户可发起完整性检查；在后续每次科学运行前，还要重新验证实际交给工具的输入。

“引用导入”与“仅引用执行”分别配置。T07 接入执行时，默认将输入物化为内容已验证的快照；仅引用执行采用需求基线规定的明确授权和较弱一致性标识，不能把硬链接当成不可变快照。

## 六 FITS 解析与预览

### 元数据

先读取 Header 和 HDU 描述，避免为了列表展示而加载完整像素数组。保存下列信息：

- 文件格式、HDU 索引、名称及类型。
- 图像维度、BITPIX／像素类型、BSCALE、BZERO、BUNIT 及无效值约定。
- 可获得的目标、曝光时间、滤镜、观测时间、仪器信息与 WCS。
- 按原始卡片顺序保存的 Header，保留重复的 COMMENT／HISTORY 等信息；常用检索字段另行提取。

保留 FITS 原始字段及其含义。缺失字段不猜测默认值，科学数值零与缺失不同。损坏 FITS 返回可定位到文件及解析阶段的错误；已复制的字节是否完整、能否解析、能否预览分别展示。

### 支持范围

首个可用闭环支持一个明确的二维图像 HDU。资产模块完整交付时列出多 HDU，并支持选择其中的二维图像以及已实现的显式切片；数据立方体、压缩或表格类型的支持状态由固定版本测试清单声明。

不可预览的 HDU 可保留其可解析的描述，并显示不支持原因。系统不自动换用另一个 HDU、不把任意三维数组推测为 RGB，也不把元数据缺失改写为有效值。

### 显示转换

预览只读取所选 HDU／切片，记录显示范围、拉伸方式、降采样尺寸和算法版本。第一批显示能力采用明确参数的线性显示拉伸；完整高级拉伸与比较界面由 T09 扩展。

缩略图和浏览预览写入独立目录。处理无效像素时记录显示规则，无法生成预览则提供不可计算原因。科学文件不经过 PNG 转换后再进入处理主链路。

预览身份包含素材内容散列、HDU、切片、显示参数及生成器版本。不同条件的预览不能误用同一缓存结果；复用派生预览不登记为一次新的科学处理。

## 七 后台任务与状态展示

使用服务内受控后台工作执行扫描、导入、散列、元数据、预览和完整性检查，任务记录持久化到 SQLite。初期按实际文件处理顺序安排工作，不引入分布式任务队列。

| 状态维度 | 展示内容 |
|---|---|
| 任务状态 | 排队、运行、完成、失败、取消、待核对；保留阶段、错误和任务 ID |
| 科学内容状态 | 待核对、可用、引用已变化、缺失；与真实可读内容对应 |
| 元数据状态 | 待处理、可用、失败、不支持 |
| 预览状态 | 待处理、生成中、可用、失败、不支持或文件缺失 |

文件总数或字节总量已知时展示实际完成数量；未知工作量显示当前阶段和运行时长。前端不能把数据库中已有条目解释为所有后台工作已完成。

目录批次报告逐文件结果，部分失败与全部完成可区分。重试由用户明确发起，保留此前尝试记录；取消结果在实际文件工作停止后确认。

重启时恢复尚未执行的排队任务，已运行但未确认完成的任务先进入待核对。优先核对已发布的文件和记录，不把失联任务自动标为成功。

6. 后台任务列表、逐文件结果、错误、取消、重试与重新检查。

使用官方扩展挂载点。首个可用闭环先提供导入、列表与详情；完整查看和对比交互继续归 T09。

前端、后续 Node 与 MCP 共用资产 ID 和素材版本 ID。外部调用不通过任意输出绝对路径绕过服务的对象解析。
