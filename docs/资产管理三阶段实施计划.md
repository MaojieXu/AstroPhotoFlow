## 开发分支与合并规则

- 当前数据库与资产管理的前两个阶段统一在 Git 分支 `feature/database` 上开发，包括相关领域服务、迁移、代理、前端、测试及文档变更。
- `feature/database` 是分支名称，不是源码目录；既定的 `service/`、前端及扩展入口位置不变。
- 实现 worktree 必须检出 `feature/database`，不能在 `main` 或 `dev` 上直接实施本模块。
- 第一阶段完成后保留阶段成果；第二阶段完成后提交验收记录并停止，不自动实施第三阶段或 AI 功能。
- 第一、第二阶段验收及必要的集成回归均通过，且没有未解决的阻断性问题后，即具备将 `feature/database` 合并到 `dev` 的条件，不要求先完成暂缓的第三阶段。
- 达到合并条件后报告验收证据与合并就绪状态；本计划不授权 Agent 自动合并，实际合并按用户后续指令执行。

第一阶段可复制的执行指令见[第一阶段执行 Prompt](第一阶段执行Prompt.md)。

## 已确定的基础方向

- 前端沿用 Vue 3、TypeScript、Vite、Tailwind 4，资产状态与接口契约使用 Pinia、Zod。
- 后端采用独立 FastAPI 服务，通过 SQLAlchemy 2、Alembic 管理独立 SQLite 数据库。
- ComfyUI 扩展自动启动并监控独立服务；服务依赖预先准备，已有数据库仍按显式迁移流程升级。
- 内容散列使用 BLAKE3，Python 环境使用 uv 管理。
- 沿用第一阶段最终确认的 AstroFlow Section 工作区及宿主主题；第二阶段增加应用内文件选择页面、参数表格和 ComfyUI 内预览浮层，连接自己的资产业务与数据库。
- 资产采用本机单用户跨项目共享库；项目引用指定资产版本，中间产物归属项目。不再要求所有资产必须属于某个项目。
- 第二阶段分类、参数和备注直接编辑，引用页面显示最新资料，不建立图像资料修订历史；内部内容记录 ID 与数据集固定成员版本仍保留。
- 保留已完成的侧栏入口及主题继承，不重复原有通过性验收。

## 第一阶段：整体框架与基础连通

**目标：连通侧栏内资产工作区、同源代理、领域服务及数据库；配置可管理，资产只读。**

| 部分 | 建设内容 |
|---|---|
| 资产界面 | AstroFlow Section 侧栏内呈现素材库、节点仓库、可安装软件、Agent 聊天和设置五个区域；素材库和设置连接实际功能，其余只显示未接入；校准素材在库内筛选，不打开独立窗口 |
| 界面状态 | 提供加载、空列表、服务不可用和请求失败状态；尚未接入的操作明确不可用 |
| 后端服务 | 建立独立 FastAPI 应用、共享本机配置、本地令牌认证、健康及能力接口 |
| 数据库 | 建立 SQLAlchemy 基础层、Alembic 初始迁移；包含项目、设备、拍摄配置、项目配置关联、资产、资产版本和项目资产引用 |
| 配置接口 | 项目、设备和拍摄配置可创建、编辑、归档／恢复；项目配置关联可调整；使用 revision 防止旧版本覆盖 |
| 资产接口 | 只读查询共享库、校准素材、共享当前版本及项目固定版本引用；不提供任何资产写入接口 |
| 前后端连通 | 经 ComfyUI 同源薄代理读取真实服务；令牌只由后端持有，不使用模拟资产冒充已实现能力 |

**阶段验收：**

- 能在 AstroFlow Section 侧栏内展示工作区，保持宿主主题及画布；工作区随宿主挂载和卸载，内部切换不跳转页面。
- 项目、设备、拍摄配置及关联形成真实管理闭环，服务重启后可读，旧 revision 修改被拒绝。
- 共享／项目资产查询范围正确，项目引用固定版本；产品库保持真实空库，空列表与服务错误可区分。
- 独立数据目录、新库初始化、已有库显式迁移、必要备份及恢复说明可用。
- 新增行为测试、实际 OpenAPI 和交付记录完成。

**第一阶段停止线：**上述配置管理与只读查询闭环验收完成后停止。不得继续增加文件导入／复制／扫描、BLAKE3 计算、资产引用修改、成品发布、格式解析、预览、校准匹配、科学处理、AssetTask／队列／runner、软件 Node、MCP 或 Agent。生产库不写入演示资产。未通过验收仅修复本阶段问题，通过后等待下一阶段指令。

第一阶段通过只代表阶段完成，成果继续保留在 `feature/database`，不得合并到 `dev`。

第一阶段内部按 S1 服务与数据库、S2 配置管理、S3 资产只读查询、S4 代理与工作区、S5 验收交付推进，具体契约见[技术与接口设计](第一阶段技术与接口设计.md)。

## 第二阶段：基础资产管理闭环

**目标：完成“选择素材 → 填写信息 → 后台入库 → 查看资产／数据集 → 项目选用”的真实闭环。**

本阶段提前纳入原第三阶段中的文件夹批量导入、基础数据集及成员版本管理；具体字段、接口、状态及验收见[第二阶段技术与接口设计](第二阶段技术与接口设计.md)。

本轮“增删改查”包含项目、设备、拍摄配置和资产／数据集的创建或导入、查询、编辑、归档／恢复，以及成员和项目引用的添加／移除；不扩大为物理删除原始文件。

| 部分 | 建设内容 |
|---|---|
| 来源选择 | 应用内浏览配置的素材根目录，支持单文件、多选、文件夹递归；仅收集声明格式，其余列入跳过报告 |
| 文件导入 | 默认引用，可切换复制托管；均进入共享库；单文件为独立资产，多选／文件夹为一个数据集 |
| 素材信息 | Subframe／Masterframe／Video 与帧用途分开；可选相机、ISO／Gain、Offset、曝光、温度、Binning、成像系统、滤镜和备注 |
| 内容与当前资料 | 导入时计算 BLAKE3；跨批次同文件独立建档；分类、参数和多行备注直接编辑，人工值优先，原始 Header／解析值保留 |
| 数据集与项目 | 内容成功即可入集；固定成员及顺序，增删生成新数据集版本；项目手动选用／移除引用，显示资产最新资料 |
| 后台任务 | 批次及逐文件结果持久化；解析／预览问题独立显示；取消保留成功项，恢复继续中断原任务，已枚举项重试创建关联新任务；成员追加冲突由用户手动补入，取消时未枚举来源另建批次 |
| 文件使用 | 列表及进入项目不扫描原件、不复算散列；使用时缺失或不可读再提示，不建设文件变化确认或自动更新 |
| 元数据与预览 | FITS 提供 Mono／Bayer／RGB 的已声明支持路径，自动选首个支持 HDU；其他格式先入库，解析／预览明确不可用 |
| 素材界面 | 表格左侧 100 px 最长边缩略图，右侧参数独立列；点击后在宿主内浮层显示 1024 px 最长边预览 |
| 归档与持久化 | 资产／数据集可归档恢复，保留历史引用；重启后查询版本、任务及已生成预览，不物理删除原件 |

**阶段验收：**

- 单文件、多选及文件夹导入结果符合约定，引用／复制可辨；零成功项不发布空数据集。
- 人工明确填写值优先，未填写项可采用文件解析值；分类差异不阻塞，Subframe／Masterframe 及两种曝光语义清楚。
- 资产具有稳定 ID；资料直接编辑后相关项目显示最新值，不建立图像资料历史。数据集成员增删仍生成新成员版本，项目不自动增删成员。
- 跨批重复导入独立建档，同批重复来源只处理一次；列表不扫描原件，实际读取失败准确提示。
- FITS 元数据和 100／1024 px 预览对应正确版本，表格不使用封面参数冒充全数据集参数。
- 原始文件不被修改；内容成功但解析／预览失败仍可入集且明确告警；预期不支持正常入集，恢复／重试不重复成功阶段。
- 数据集追加 revision 冲突后保留成功资产与原任务错误，通过现有成员编辑流程手动补入；queued／枚举未完时取消只保留已枚举项供重试，剩余来源明确另建导入批次，遵守跨批独立建档规则。
- 显式迁移、备份、接口契约及 S2-AT-01 至 S2-AT-10 的实际验收记录齐备。

**阶段出口：**完成第二阶段验收与交付记录，核对前两阶段及必要集成回归通过后报告合并就绪，成果保留在 `feature/database`，实际合并等待用户明确指令。不得自动增加拖入画布、资产引用节点、目录监听／重扫、校准匹配、配准叠加、视频逐帧、NumPy 切片、软件 Node、MCP、AI Panel 或 Agent。

## 第三阶段暂缓与后续候选

当前不安排第三阶段实现，也不将其作为数据库闭环的完成条件。保留以下候选，待实际需要及新的开发指令再确定范围：
