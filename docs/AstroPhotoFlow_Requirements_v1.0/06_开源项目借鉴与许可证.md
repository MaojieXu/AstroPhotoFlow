# 06｜开源项目借鉴总结与许可证边界

**核验日期：2026-10-22。范围：README、可见许可证、与需求直接相关的关键源码。未运行这些项目，也不是全仓库安全审计。**

## 1. 总结：组合机制，不拼装整个产品

本次核验的项目分别覆盖 Agent 控制、CLI 封装、配置驱动控件、节点生成、依赖隔离和天文应用桥接。没有证据表明把这些仓库一起安装就能获得 AstroPhotoFlow 的完整产品链路；共享状态、科学数据协议、来源、版本和项目记忆仍需要自建。

| 采用层级 | 项目 | 决策 |
|---|---|---|
| 受控代码复用 | comfyui-mcp、comfyui-mcp-panel | 锁定版本、保留许可，改造业务写入／执行边界 |
| 设计借鉴为主 | Blender Wrapper、VideoHelperSuite、G’MIC、RB Command | 借鉴调用、参数、日志和交接模式，不作为默认运行依赖 |
| 可选技术验证 | EasyNodes、comfy-env | 用实验决定是否引入，不将内部实现绑成核心契约 |
| 天文后续适配参考 | astro-pi-mcp | 借鉴 MCP／应用内桥接、指标和知识分层；PixInsight 不列首版必需 |
| 暂不复制代码 | ComfyUI-ImageMagick | 可研究行为；本次未找到明确适用于该仓库的开源授权 |

## 2. 各仓库的核验与借鉴

### 2.1 artokun/comfyui-mcp

**核实：**`agent-backend.ts` 定义后端能力与统一会话事件接口；`panel-tools.ts` 通过桥接调用已连接画布，并共享工具定义；`package.json` 显示 Node.js／TypeScript 工程。[S01](08_调研来源与核验记录.md#s01)

**采用：**保留 provider 适配、事件规范化和工具封装模式，为内置 Agent 建立集成层。

**必须修改：**画布写入、运行、安装等工具接入 AstroPhotoFlow 权限与项目服务，禁用旁路；天文知识和项目经验分开。

**不能推定：**它已有 AstroPhotoFlow 数据模型、任意节点无界面编辑、科学指标验证或自动完整追溯。

### 2.2 artokun/comfyui-mcp-panel

**核实：**前端使用带请求 ID 的命令／回执、受控图执行器和原生变更包络；Python 入口负责前端资源及本地发现／代理，而不是提供天文处理节点。[S02](08_调研来源与核验记录.md#s02)

**采用：**Agent 侧栏、操作回执、目标画布绑定和原生图撤销机制。

**必须修改：**增加项目／版本上下文、同步状态、审批卡、接管及结果入口；把每次写入纳入领域事务。

**维护边界：**README 明确说明目前仅有限维护、聚焦关键修复；不要依赖上游持续补齐领域功能。其源码仍直接涉及画布实现，必须维护兼容测试。[S02](08_调研来源与核验记录.md#s02)

### 2.3 IRCSS/comfyUI-blender-wrapper

**核实：**`blender_generic_node.py` 以后台 Blender 子进程执行，并从 JSON 读取输出路径／结果。[S03](08_调研来源与核验记录.md#s03)

**借鉴：**输入文件与配置 → 外部进程 → 输出文件与结构化结果。

**不照搬：**检查范围内的节点未形成完整超时、取消、退出码及产物契约体系；天文版本、科学格式和权限仍需另做。

### 2.4 Kosinkadink/ComfyUI-VideoHelperSuite

**核实：**`get_video_formats`、`iterate_format`、`apply_format_widgets` 读取格式 JSON 并生成控件／命令参数；示例 JSON 声明枚举、整数和布尔项。[S04](08_调研来源与核验记录.md#s04)

**借鉴：**统一声明驱动控件和执行参数，减少人工维护两份参数逻辑。

**不照搬：**它针对视频格式，不是任意软件发现框架；AstroPhotoFlow 还需要单位、文件语义、操作版本和结果登记。首版优先独立实现协议，不复制整套视频运行系统。

### 2.5 jtydhr88/ComfyUI-ImageMagick

**核实：**`image_magick_node.py` 支持有限图像输入与参数，将输入转换成 `uint8` PNG 后调用 `magick`，再读取结果。[S05](08_调研来源与核验记录.md#s05)

**借鉴：**理解最小 CLI 封装的输入／输出生命周期。

**不照搬：**该像素转换与输出路径设计不适合作为 FITS 科学主链路。本次查看的根目录、README 和目标源码没有明确授权声明，授权未补齐前不复制其代码。

### 2.6 gemell1/ComfyUI_GMIC

**核实：**`comfy_gmic.py` 分别调用 `gmic` 与 `gmic_qt`，通过临时 PNG 交接并清理文件。[S06](08_调研来源与核验记录.md#s06)

**借鉴：**区分自动 CLI 与需要应用界面的交互型适配器。

**不照搬：**Qt 交互不等于可无人值守；临时 PNG 路线不承担 FITS 元数据与精度。GUI 等待必须有明确状态，不能让队列永久无提示阻塞。

### 2.7 itribs/comfyui-rb-command

**核实：**动态输入与占位符、工作目录、超时、stdout／stderr／退出码；执行路径使用 `shell=True`，并含结果缓存。[S07](08_调研来源与核验记录.md#s07)

**借鉴：**命令日志、参数可观察性、超时和输入组合。

**不照搬：**不把通用 Shell 交给默认 Agent；自有生产 runner 改为预注册操作与结构化参数。不能仅复制缓存方式，否则可能把未重新执行误记成新运行。

### 2.8 andrewharp/ComfyUI-EasyNodes

**核实：**`@ComfyNode`、类型和参数辅助对象可生成节点定义；源码有 `INPUT_TYPES`／节点映射等相关机制。[S08](08_调研来源与核验记录.md#s08)

**借鉴：**由声明生成节点，避免每个软件操作手写大量样板代码。

**不照搬：**它不自动理解 CLI 或 MCP 的领域语义；与官方节点 API 的兼容性需要实测。首版保持自有 Schema，EasyNodes 不是强制依赖。

### 2.9 PozzettiAndrea/comfy-env

**核实：**当前 README 描述按目录配置独立环境、使用 Pixi 管理环境并以持久子进程隔离；公共入口限制了稳定 API 范围。[S09](08_调研来源与核验记录.md#s09)

**借鉴：**环境描述、独立进程和环境复现。

**不照搬：**它不是简单的 `uv venv` 脚本，也不是安全沙箱。文件型天文任务不必先引入张量 IPC／CUDA 管理；对内部类的直接依赖可能增加维护成本。

### 2.10 ncarlinix/astro-pi-mcp

**核实：**MCP 服务通过文件 JSON 桥与 PixInsight 内的 PJSR watcher 通信，后端不自行启动 PixInsight；README 说明 ASTAP 定位接入，LICENSE 为 MIT 并记载另一 MIT 项目的来源。[S10](08_调研来源与核验记录.md#s10)

**借鉴：**应用内桥接、任务／结果关联、图像评价和按需知识组织。

**不照搬：**不能视为纯无界面工具，也不能把其 README 中的实现数量当作已验证产品质量。产品的开源授权不等于获得 PixInsight 应用或其插件的分发权限。

## 4. AstroPhotoFlow 的开源策略

建议自有集成代码采用 GPL v3 系列兼容方案；对自己拥有版权的新代码可选择 `GPL-3.0-or-later`。外部代码保留其原始许可及版本范围，不能仅凭根目录放置一份许可证，就把他人代码扩大为 `or-later` 或取消 MIT 通知。最终 SPDX 声明在引入实际代码清单后确定。

本路线目前不复制 Desktop，因此不应仅凭此前讨论就给整个 Extension 套上 Desktop 的许可证。未来真正 Fork／捆绑 Desktop 时重新核对所采用版本的授权；不能把未来选择当成当前义务或豁免。

发布前应提供源码对应版本、构建／安装说明、第三方通知、修改记录，以及对模型、星库、测试素材和外部软件的分发范围说明。自己的产品不商用且开源，也不能免除第三方许可证义务。

本节是工程合规清单，不是正式法律意见；存在授权歧义的内容不得先复制后补手续。

## 5. 最值得保留的六条借鉴

1. Agent 负责受控操作，不是只输出 JSON；操作必须回执并绑定正确画布。
2. 工具能力用结构化清单描述，同一描述驱动节点、校验与 Agent 工具目录。
3. 外部软件通过稳定文件／结果契约接入，不把进程退出等同于业务成功。
4. 科学数据和界面预览分流，避免展示链路改写真实数据。
5. 独立环境解决依赖冲突，但不是权限边界或沙箱。
6. 图撤销、文件恢复、运行取消和聊天回退分开设计，不能相互冒充。

**依赖策略：只复用有明确价值且可维护的模块，不因“找到了十个仓库”而增加十个产品依赖。**
