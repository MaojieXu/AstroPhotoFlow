# 03｜软件适配与科学数据协议

**目标：把经过明确描述的外部操作变成可靠节点，而不是自动理解任意软件。**

## 1. 适配包是什么

适配包是 AstroPhotoFlow 的领域扩展，不等于 ComfyUI 节点包，也不等于外部软件本身。它包含能力清单、参数及数据契约、执行绑定、版本检测、结果解析、必要的知识和测试样例。

一个适配包可以声明多个操作；由 AstroPhotoFlow 的节点生成层将操作注册到 ComfyUI。通常一个软件对应一个分类，一个操作对应一个节点。操作 ID、节点类型 ID 和显示名称分开；改中文名称不应破坏旧工作流。

自动扫描仅识别遵守协议的适配包。CLI 的 `--help` 或 MCP `tools/list` 可辅助发现，但不能替代对文件语义、单位、输出、取消和授权的声明。

## 2. 能力描述的最小字段

| 字段组 | 必须描述的内容 |
|---|---|
| 身份 | adapter ID／版本、operation ID／版本、显示名、分类、说明、兼容范围 |
| 输入输出 | 端口 ID、语义类型、支持格式、单个／集合、可选性、HDU／通道等约束 |
| 参数 | 类型、默认值、范围、枚举、单位、互斥／依赖关系、是否可由连线提供 |
| 绑定 | runner 类型、允许的入口／操作名；CLI 参数构造或 MCP server/tool 绑定 |
| 环境 | 可执行文件、软件版本、依赖／星库、操作系统、环境锁、检测方法 |
| 结果 | 预期文件、文件类型、指标、预览、日志、成功与失败判定 |
| 生命周期 | 超时、进度协议、取消能力、可重试性、幂等性、临时目录策略 |
| 安全与许可 | 安装来源、许可证、读写范围、网络需求、GUI 需求、潜在费用 |
| 科学语义 | 原始数据是否修改、像素精度转换、单位变化、元数据传播及 WCS 处理规则 |

示意清单如下，字段和操作名属于本项目拟定协议：

```yaml
schema_version: 1
adapter_id: org.astrophotoflow.siril
adapter_version: 0.1.0
operations:
  - operation_id: org.astrophotoflow.siril.register
    operation_version: 1
    node_type_id: APF_SirilRegister_v1
    category: AstroPhotoFlow/Siril
    inputs:
      frames:
        type: AstroFrameSet
        formats: [FITS]
        required: true
    parameters:
      reference_index:
        type: integer
        minimum: 0
        default: 0
    outputs:
      registered_frames:
        type: AstroFrameSet
        formats: [FITS]
    execution:
      runner: cli_script
      handler: siril.register
      working_directory: per_job
      input_mutation: forbidden
    lifecycle:
      timeout_seconds: 1800
      cancellation: process_group
      retry: explicit_only
```

这不是完整 Siril 参数表。最终字段必须对照锁定软件版本并用真实素材验证；不要把示例参数直接当作 Siril 原生命令参数。

## 3. 安装、发现与注册

流程为：**生成安装计划 → 用户授权 → 安装到隔离环境 → 检测软件 → 读取／校验清单 → 更新能力目录 → 更新节点注册 → 必要时受控重启 → 校验恢复。**

适配器 Python 包优先通过 `uv` 管理独立环境；需要系统库或非 PyPI 包时允许独立的环境后端。不能假定 `uv` 安装 Python 包就会安装 Siril、ASTAP、星库或图形应用。

能力清单优先静态读取；确需运行发现代码时在明确授权的适配器进程中执行，不把未知包导入 ComfyUI 或项目服务主进程。MCP 动态能力也要转换、校验并版本化，不能直接变成可自动执行的节点。

首版在后端加载时注册节点。工具可用性可动态刷新；新增节点类型或 Schema 变化则经过受控重启，不承诺热注册。重启前保存项目、停止新提交并处理已有任务；不能中途重启导致运行记录失真。

失效操作保留历史 Schema 和说明；旧工作流显示“依赖缺失／版本不兼容”，不丢掉参数和连线。破坏性更新提供迁移预览，拒绝静默更改含义。

## 4. 科学数据端口

主链路使用文件／对象引用，不以普通 `IMAGE` 端口承担完整天文语义。

| 拟定类型 | 内容 |
|---|---|
| `AstroFrame` | 素材版本、受控存储引用、格式、HDU、像素类型／维度、单位、元数据引用 |
| `AstroFrameSet` | 已固定顺序的素材版本列表、集合版本、筛选规则记录 |
| `AstroTable` | 星表／测量表的文件引用、列 Schema、单位和坐标系统 |
| `AstroMetrics` | 指标名、值或不可用状态、单位、算法版本、ROI 和来源 |
| `AstroPreview` | 由哪个素材版本生成、显示转换参数、预览文件；不得冒充科学原件 |

ComfyUI 的 `IMAGE` 是图像张量类型，并非天然只能是 8 位；问题是它本身不能表达完整 FITS 文件及项目来源契约。ImageMagick 示例中的 8 位转换是该扩展的具体实现，不是 ComfyUI 的普遍限制。[S05](08_调研来源与核验记录.md#s05) [S17](08_调研来源与核验记录.md#s17)

端口传递稳定引用和轻量元数据，不通过 JSON 发送完整 FITS 字节。路径由项目服务解析，Agent 不直接任意指定输出绝对路径。自定义端口类型检查之外仍需执行前的语义校验。

## 5. FITS 与元数据规则

原始文件不可被处理工具覆盖。数值处理保持工具所需的明确精度；发生转换必须记录源类型、目标类型、缩放和单位，不笼统承诺所有步骤都保持原始数据类型。

首版支持 FITS 图像 HDU 的元数据解析和可预览的二维图像／明确选择的切片。多 HDU 文件应能列出并选择；不支持的数据立方体、压缩或表格类型要明确报出，不能自动选错 HDU。

FITS Header、缩放信息、曝光／滤镜、无效值和 WCS 都要纳入元数据策略。配准、裁切或重采样后不能机械复制旧 WCS；适配器应更新、验证，或标记无效。显示拉伸、归一化和缩略图生成不得改变科学原件。

Astropy FITS 文档用于实现层的数据读写核对；本项目的精度与元数据测试要求由验收用例约束。[S22](08_调研来源与核验记录.md#s22)

## 6. CLI 执行约束

借鉴 Blender Wrapper 的独立进程与文件结果交接，但为本项目补齐退出码、超时、取消和输出验证。其源码可以核实后台子进程和 JSON 输出读取路径。[S03](08_调研来源与核验记录.md#s03)

正式 runner 使用预注册操作和结构化参数构造 `argv`，不默认 `shell=True`，不让模型拼接任意 Shell。参数中路径、换行、引号及工具自身脚本语法也要校验；关闭 Shell 不等于已经防住软件脚本注入。

每个 job 使用独立工作目录、配置和输出 staging 目录；明确环境变量白名单。日志连续采集并限制大小；失败保留诊断，敏感内容脱敏。只有退出状态和输出契约同时满足才算成功，不能仅凭文件存在或退出码为零。

CLI 操作声明取消能力：可终止进程组、仅软取消、不可中断等。超时后处理子进程和临时文件；部分输出先隔离，不登记为成功结果。

## 7. MCP 工具执行约束

工具 MCP 服务是适配器的下游，不是能任意编辑 AstroPhotoFlow 项目的上游 Agent。

调用时固定目标 server 身份、版本、工具名、Schema、输入素材版本和 job ID。返回文本不直接作为可信结果路径；必须解析为结构化结果，再验证文件确实存在、处于允许目录且属于本次任务。

区分 MCP 传输取消与实际外部工作取消。没有可核实的 job 终止能力时显示“取消请求已发送／外部状态未知”，不能承诺已停止。

若工具需要软件 GUI 或内部会话，明确 `requires_gui` 和连接健康状态。例如 astro-pi-mcp 的 PixInsight 后端依附于用户已开启的 PixInsight 与 watcher，而不是独立无界面执行器。[S10](08_调研来源与核验记录.md#s10)

## 8. 统一结果模型

每个操作返回 `job_id、operation_id、status、outputs、metrics、log_refs、tool_version、started_at、finished_at、warnings、error`。

`outputs` 指向经过验证的产物；产物暂存到运行目录，验证后由服务登记为新 AssetVersion。取消、失败和未知状态可保留诊断文件，但不能混入成功结果集合。重试创建新 attempt，保留此前记录。

对外部工具完成但登记失败的情况，支持“待登记”恢复；不得直接重跑可能有副作用的操作。

## 9. 第一批适配器

| 适配器 | 首版目标 | 明确限制 |
|---|---|---|
| Siril | 能力检查、受控脚本、序列配准与叠加；按素材补齐校准操作 | 序列文件和关联帧必须一起管理，不能只传一个 `.seq` 路径 |
| ASTAP | 本地定位、星库检测、读取解算状态和 WCS 产物 | 未安装星库时明确不可用；不得在原始文件目录写 sidecar |
| 本地 FITS MCP 示例 | 通过同一协议读取元数据／计算有限指标，验证 MCP 结果交接 | 项目自行开发，不宣称已有可直接安装的现成仓库 |
| PixInsight | 后续通过 MCP 适配 | 不作为 WSL 首版必需；不捆绑授权，不承诺 headless |

Siril 的 `-s` 与命名管道由官方文档说明。首版优先单 job 脚本，持久管道会话留作后续优化。[S11](08_调研来源与核验记录.md#s11)

ASTAP 官方文档说明命令行会在输入旁生成结果文件；默认 `.wcs` 的格式也不能一概当成完整 FITS。适配器必须在 staging 中运行，校验解算成功标记、退出状态和 WCS，再生成自己的受控结果。[S12](08_调研来源与核验记录.md#s12)

## 10. 不作为默认依赖的参考项目

VideoHelperSuite 用于借鉴“声明 → 控件 → 参数替换”，EasyNodes 用于借鉴“类型描述 → 节点定义”；本项目保持自己的适配契约，不强绑定其内部实现。[S04](08_调研来源与核验记录.md#s04) [S08](08_调研来源与核验记录.md#s08)

RB Command 可供隔离实验理解 CLI 行为，不能作为生产 Agent 默认执行入口。comfy-env 用于环境隔离对比；首版天文文件链路未验证需要其张量 IPC／CUDA 能力前，不把它设为硬依赖。[S07](08_调研来源与核验记录.md#s07) [S09](08_调研来源与核验记录.md#s09)
