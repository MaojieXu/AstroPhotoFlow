# 双语文档

[English](README.en.md) | 中文

本仓库的文档以中文为主，英文是配对翻译。三件套的结构、记录和门禁都由本页定义；写或改任何配对文档前先读本页。

## 文件三件套

每个配对文档由三个文件组成，放在同一目录：`foo.md` 是中文主文档，`foo.en.md` 是英文翻译，`foo.i18n.yaml` 是两侧内容哈希记录。三者一起提交，缺一即门禁失败。

## 语言切换行

中文主文档在 H1 标题后空一行，再写一行 `[English](foo.en.md) | 中文`。英文文档在 H1 标题后空一行，再写一行 `English | [中文](foo.md)`。切换行不参与正文哈希，但结构与位置由门禁校验。

## 记录文件

`foo.i18n.yaml` 以四行注释开头，说明本文件由门禁生成、按小节记录两侧哈希、复记命令。其后每个小节一组三行：第一行是 `/<h1-slug>/<h2-slug>` 形式的小节键，后接 `  en: <16 位十六进制>` 与 `  zh: <16 位十六进制>`。忽略空行与注释行，其余行按三行一组解析，重复键或格式不合即视为损坏。

## 分节与哈希

每个标题开启一个小节，子标题小节键带上祖先标题的 slug 路径；重复标题由门禁加 `~2` 去重。小节按出现顺序在两侧对齐，两侧小节数必须相等。哈希取该小节顶层文本块按行连接后的 sha256 前 16 位，不包含围栏代码块。两侧都为空的小节不产生记录。

## 结构镜像

中英文必须同构：标题层级与顺序一致，列表类型、起始序号和条目数一致，表格行列数一致，代码块的语言标记与内容逐字一致，链接指向同一语义目标。结构不一致时先改结构，再重记哈希。

## 链接语言

中文文档链接中文配对，路径以 `.md` 结尾；英文文档链接英文配对，路径以 `.en.md` 结尾。链接到配对范围外的目标时保留作者写的路径。语言切换行是唯一例外。

## 范围

范围由 `scripts/doc-pairs.json` 列出，只登记中文主文件。`AGENTS.md`、`.agents/notes/**`、`.agents/skills/**` 只写中文，不配对；`docs/api/*.json`、`reference/**`、`frontend/**`、`engine/**` 不在范围。

## 更新流程

先改中文主文档，再改英文翻译。运行 `python scripts/verify_docs.py pairing --write <中文主文件>` 重记该对哈希，然后运行 `pnpm check:docs`。`pairing --list` 只报告 ok、missing、out-of-sync，不修改文件；`--write-all` 全量重记，仅在批量迁移时使用。

## 责任边界

哈希通过只表示记录生成时两侧内容一致，不代表翻译质量或语义等价。审核由独立 reviewer 完成，门禁不替代人工判断。
