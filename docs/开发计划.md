## 分阶段交付

### 资产与数据基础

以 T01 为当前主要交付，按[资产管理实施计划](资产管理三阶段实施计划.md)完成前两阶段。第一阶段在 AstroFlow 侧栏内建立资产工作区、同源代理、独立服务和数据库，交付项目、设备及拍摄配置管理，以及共享／项目资产只读查询，具体事实以 `feature/database` 已验收的 `ce8404e` 为基线。第二阶段实际进度以实现分支和交付记录为准；本次仅调整文档，不宣称第二阶段已完成，主工作区旧第一阶段草稿不能覆盖已验收约定。

T01 采用本机单用户跨项目共享资产库；项目使用指定资产版本，处理中间产物归属项目。该模型取代“每条资产必须归属项目”的旧约定。项目创建、编辑、归档／恢复及关联拍摄配置在 T01 第一阶段落实，T03 继续完善工作流、运行、会话与记忆的工作台组织。T04 复用原生画布，仅接入当前受支持节点和保存能力。ComfyUI 加载 Extension 时自动启动或复用资产服务及健康监控由 S2-AT-11 验收。

第一阶段出口：配置可持久化管理，资产只读查询真实连通，错误及空库可辨，迁移／备份及新增行为验收完成。到此停止，不自动进入下一阶段。

第二阶段在该基线上实施应用内文件选择、单文件／文件夹批量导入、导入时 BLAKE3、版本化数据集、项目选用及 FITS 元数据／预览。不同批次同文件独立建档；分类、参数和多行备注直接编辑，人工值优先，项目显示最新资料，不建立图像资料修订历史。默认引用原文件；列表及进入项目不检查全部原件，使用时缺失或不可读再提示，不做文件变化确认或自动更新。内容成功即可入集，解析／预览问题独立报告；恢复继续原任务，选中项重试建立关联新任务，成功阶段不重复处理。

任务恢复边界：数据集追加 revision 冲突后，由用户通过现有成员编辑流程手动补入成功资产，保留原任务错误；主动取消只保留已枚举逐文件项供重试，未枚举来源需显式另建导入批次，继续遵守跨批独立建档规则。具体请求、报告及验收见第二阶段技术文档。

表格使用 100 px 缩略图，点击打开 1024 px 宿主内预览浮层。其他声明格式先入库，按范围不支持解析／预览是正常结果。数据集固定成员版本保留，不因编辑资产资料而增删成员。验收后停止；第三阶段拖入画布及资产引用节点暂缓，目录监听／重扫、视频逐帧、NumPy 切片和高级素材库列为后续候选，不阻塞当前数据库闭环。

T01 当前前两个阶段在 Git 分支 `feature/database` 的 worktree 中开发；分支名称不改变 `service/` 等源码目录。第一、第二阶段验收和必要集成回归均通过、无未解决阻断性问题后，即可报告 `feature/database` → `dev` 合并就绪，不等待暂缓的第三阶段。实际合并按用户明确指令执行。第一阶段执行指令见[第一阶段执行 Prompt](第一阶段执行Prompt.md)。

### 下一步：AI Panel 与 Agent 数据管理

数据库闭环验收后，优先推进 T15 的 Panel、T16 的 Agent 后端连接及 T14 的数据管理工具子集，让用户通过 Agent 查询、导入、编辑和管理现有数据。复用既有领域 API、任务状态和错误契约，必要的写入权限与并发保护同时落实；此时不要求实现软件执行、工作流改图或完整科学处理 Agent。具体范围、协议和验收另行规划，当前不自动实施。

### 首批软件处理闭环（后续）

推进 T05 至 T09。先选择一组许可清晰的小规模 FITS 素材，接入 Siril 的一个真实操作，再扩展到与素材匹配的配准／叠加流程。ASTAP 和受控 FITS MCP 示例按既有跨软件验收要求继续补齐。

T06、T07、T08 共同构成可运行交付：注册节点时同时落实执行入口、任务状态和来源记录。T06 中先开放首批软件操作的 MCP 查询及受控调用；T14 再补齐完整 Agent 业务工具面。

阶段出口：前端与 MCP 分别提交受支持工作流，都能使用固定输入版本完成真实处理，查看日志、登记产物并比较两组参数结果。

### 状态控制与完整 MCP

完善 T10 至 T14，覆盖多页签目标绑定、版本冲突、接管、历史恢复、权限及服务重启核对。外部 Agent 通过统一 MCP 直接使用业务服务。

阶段出口：手动与 MCP 交替操作不会静默覆盖；画布关闭后项目查询和受支持的已保存工作流运行仍可用；断连和未知状态可见。

### Agent 完整处理闭环（后续扩展）

在首批 AI Panel 与数据管理 Agent 的基础上继续完善 T15 至 T18；等相应软件、工作流与运行能力可用后，再扩展到处理规划、执行、评价、迭代及经验保存。各后端分别通过实际支持的工具闭环验收，不将完整处理能力作为首批数据管理 Panel 的前置条件。

阶段出口：内置 Agent 使用已验证的领域工具，在明确授权范围内完成处理；用户接管后旧写操作失效；项目经验有来源且可管理。

### 存储治理与发布

完成 T19 的管理界面及 T20 的集中回归，补齐升级、回退、导出、诊断、许可和发行材料。正式首版以原需求中的全部 P0 用例通过为出口。
