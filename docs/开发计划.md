# AstroPhotoFlow 开发计划

**更新日期：2026-10-22**

**实施主线：先建立数据与软件工具闭环，再接入 Agent。**

本计划将 v1.0 需求按功能模块的主要交付顺序排列。每个模块先交付当前闭环需要的部分，再逐步完善；排序靠后不表示其基础约束可以推迟。首个真实软件运行就要具备输入版本、有效参数、日志、输出来源及必要的权限校验。

## 分阶段交付

### 资产与数据基础

以 T01 为第一个主要交付，按[三阶段实施计划](资产管理三阶段实施计划.md)推进。第一阶段先建立独立资产工作区、同源代理、独立服务和数据库，交付项目、设备及拍摄配置管理，以及共享／项目资产只读查询。具体 API、revision、认证、迁移及停止范围见[第一阶段技术与接口设计](第一阶段技术与接口设计.md)。第一阶段已完成实现并验收；当前成果保留在 `feature/database`，不合并到 `dev`。

T01 采用本机单用户跨项目共享资产库；项目使用指定资产版本，处理中间产物归属项目。该模型取代“每条资产必须归属项目”的旧约定。项目创建、编辑、归档／恢复及关联拍摄配置在 T01 第一阶段落实，T03 继续完善工作流、运行、会话与记忆的工作台组织。T04 复用原生画布，仅接入当前受支持节点和保存能力。

第一阶段出口已通过，交付和验证证据见[交付与验收记录](第一阶段交付与验收记录.md)。到此停止，不自动进入导入、资产引用修改、解析、预览、任务处理或软件／MCP／Agent 建设。收到第二阶段指令后再打通 FITS 导入、元数据及预览，第三阶段完善集合和多类型素材库。

T01 的三个阶段统一在 Git 分支 `feature/database` 的 worktree 中开发；分支名称不改变 `service/` 等源码目录。第一、第二阶段通过后仅保留阶段成果并停止，不合并到 `dev`。只有三个阶段全部完成、各阶段验收和必要的三阶段集成回归均通过、无未解决阻断性问题，才具备 `feature/database` → `dev` 的合并条件。Agent 报告合并就绪后停止，实际合并按用户后续指令执行。第一阶段执行指令见[第一阶段执行 Prompt](第一阶段执行Prompt.md)。

### 首批软件处理闭环

推进 T05 至 T09。先选择一组许可清晰的小规模 FITS 素材，接入 Siril 的一个真实操作，再扩展到与素材匹配的配准／叠加流程。ASTAP 和受控 FITS MCP 示例按既有跨软件验收要求继续补齐。

T06、T07、T08 共同构成可运行交付：注册节点时同时落实执行入口、任务状态和来源记录。T06 中先开放首批软件操作的 MCP 查询及受控调用；T14 再补齐完整 Agent 业务工具面。

阶段出口：前端与 MCP 分别提交受支持工作流，都能使用固定输入版本完成真实处理，查看日志、登记产物并比较两组参数结果。

### 状态控制与完整 MCP

完善 T10 至 T14，覆盖多页签目标绑定、版本冲突、接管、历史恢复、权限及服务重启核对。外部 Agent 通过统一 MCP 直接使用业务服务。

阶段出口：手动与 MCP 交替操作不会静默覆盖；画布关闭后项目查询和受支持的已保存工作流运行仍可用；断连和未知状态可见。

### 内置 Agent

推进 T15 至 T18。先接入 Panel 的消息与工具回执，再连接模型后端，最后完成规划、执行、评价、迭代及经验保存。各后端分别通过真实工具闭环验收。

阶段出口：内置 Agent 使用已验证的领域工具，在明确授权范围内完成处理；用户接管后旧写操作失效；项目经验有来源且可管理。

### 存储治理与发布

完成 T19 的管理界面及 T20 的集中回归，补齐升级、回退、导出、诊断、许可和发行材料。正式首版以原需求中的全部 P0 用例通过为出口。

## 从第一阶段开始执行的约束

| 约束 | 最早落实时机 |
|---|---|
| 独立数据目录、稳定项目与资产 ID、数据库迁移前备份、本机访问身份校验、revision 并发保护 | T01 第一阶段首次持久化与管理接口 |
| 共享／项目查询范围及固定版本引用 | T01 第一阶段只读资产接口 |
| 原件保护及导入路径校验 | T01 第二阶段首个导入接口 |
| 后台任务真实状态、导入中断及重启核对 | T01 首个异步任务 |
| 软件、适配器及相关运行版本记录 | 首个实际使用该软件的操作 |
| 运行快照、输入字节一致性、有效参数与输出来源 | 首个真实软件运行 |
| 原生运行按钮、快捷键及 MCP 的统一提交路径；节点执行授权 | 首个托管工作流运行 |
| 请求与结果关联、缓存失效、取消及失败语义 | 首个外部执行节点 |
| 受支持节点的在线／无界面转换一致性 | 首次开放无界面编辑或运行能力 |
| 模型工具权限、项目会话隔离、审批与接管 | 首次允许 Agent 修改或执行 |
| 行为测试、真实宿主验证、测试素材来源记录和必要性能测量 | 对应功能首次交付 |

T10、T13、T19、T20 排在后面，表示完善这些模块及交付界面的主要时机。基础启动、权限、备份和相关测试随功能一起实现。

## 每次交付的记录

每个实现批次记录关联任务与 FR／AT 编号、实际支持范围、版本组合、验证结果和剩余阻断项。使用小而完整的实现批次，不一次建设尚未被当前功能使用的通用框架。

D0 中涉及图同步、提交拦截、缓存、文件型节点、无界面转换、Agent 权限和许可的阻断项，在首次使用相应能力前验证。未通过的能力显示其实际支持状态。
