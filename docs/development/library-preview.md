# 单图预览与缓存

<a id="library-performance-preview"></a>

## 素材库当前显示规则

全部可自动预览图片（含各类校准子帧和Master）后台生成最长边100px的JPEG，不阻塞导入，不显示缩略图进度条。组使用固定版本排序第一成员的配方，首帧不可用不改选其他成员；独立素材分别计算。参考首帧和固定内容决定缓存身份，追加或改首帧不会覆盖历史组上下文。

当前视口及邻近行通过IntersectionObserver提升取图队列优先级，单页最多四个请求；同页刷新保留在途读取。缩略图单元格独立订阅缓存键，就绪后逐张替换占位；已知失败或不支持的成员停止重复HTTP取图，显式重试仍使用既有批次接口。后端继续自动补齐其余图片，按批巡检丢失文件并支持重启恢复。

统一大图查看器复用已保存配方，缺失时只计算明确参考帧；不回放导入任务或旧Object分组历史。overview按512/1024/2048px选择采样，放大瓦片按区域读取。显示会话与内容缓存分开；新overview解码后替换画面并复用查看器，近期显示描述有界保存，最多预取一个下一帧并使用低优先级。过时准备协作取消。缓存预算增量记账，启动或低频维护核对；缓存命中的prepare只读，生成／读取租约仍保留必要的持久化保护。

图片原件只读，不执行校准、叠加或质量分析。具体解码器仍可能需要完整解码（例如XISF）；100px输出不等于只读取100px。下文100/1080及Object共享描述属于旧display接口，不覆盖本节的素材库缩略图和统一查看器规则。实现、静态编译、部署与未运行测试的边界见[本轮记录](test-matrix.md#library-performance-implementation)。

## 2026-10-29 Siril Auto Stretch 节点实时预览

直接连接 APF_DATA_REFERENCE 的固定素材／组后，节点提供单独的1024px快速预览区。修改 linked、shadowsclip、targetbg 后防抖350ms，只为当前成员生成预览；相同来源和成员复用线性 FITS 样本。该样本来自原件连续条带读取，保留数值及RGB通道，不从已拉伸缩略图重新处理。预览统计基于低分辨率样本，不能承诺与完整原件逐像素相同。上游其他处理节点仍可正式运行，实时预览当前要求直接连接素材库数据节点，未支持时明确提示。

预览使用平台安装的 Siril 1.4.4 CLI，并沿 preview_workers、现有预览执行器和共享 MediaCache 排程。过期请求、断连及关闭取消本次专用预览，当前代次之外的结果不显示。预览写现有 size=siril-live 记录，生成期间阻止原件永久清理，所属文件纳入4GiB缓存预算／LRU、清理及启动中断回收。软件维护和工作台重启在请求未结束时拒绝；查询、取消和预览不提交原生队列。

正式运行继续解析完整科学输入并调用 Siril。render_output_preview 的 auto_stretch 默认保持True；Siril显式传False，仅按输出类型和数值范围映射到JPEG，不计算二次MTF或白平衡。节点内快速预览PNG同样直接映射。执行HTTP会话与原生执行事件循环同寿命，避免复用网页服务线程的ClientSession。

组件、接口、缓存、线性值及两事件循环回归用例已编写，均未运行；类型／编译／构建与隔离更新日志归 `.artifacts/implementation/siril-live-preview-20261029/`，质量、速度和真实Siril行为由用户验收。

## 2026-10-29 统一媒体查看器候选

节点和素材库共用原生Dialog与OpenSeadragon；适应窗口、原图100%、缩放、平移、固定组切换及视频播放／暂停帧放大。显示读取不改变科学输入或工作流。按当前成员和可见区域生成512px分级瓦片，邻帧只预取概览；不能对千张图批量解码或预生成完整金字塔。浏览器瓦片128MiB、后端显示缓存256MiB、派生磁盘缓存4GiB，缓存可回收但原件和科学记录保持。需全帧解码的格式只为实际查看成员解码，缓存预算不等于解码库瞬时RSS上限。既有MTF／同Object子帧共享规则沿用，所有瓦片使用同一配方。测试只编写不运行，编译构建及隔离更新后由用户预览。

原生节点加载当前成员2048px概览，点击后与素材库、项目固定成员共用宿主注入的MediaViewer。组内顺序固定，支持跳转；同尺寸成员保持查看位置及倍率，不配准。100%按设备像素换算，超过100%关闭平滑。未准备区域由概览先展示，高清瓦片按需补齐，不把低清缓存当作原尺寸。

media_sources按FITS／SER／NPY局部读取，XISF、RAW、普通图片及压缩NPZ只为所选图像／数组解码一次并保存可回收pixels.npy；数组头列举不读全部数组正文。NumPy选择数组、水平／垂直／通道轴及其余切片，拒绝非数值／无效轴；展示选择不更改科学引用。X-Trans／Quad Bayer在未提供去马赛克实现时明确以原尺寸灰度马赛克查看，不宣称彩色解码已支持。

media_cache保留最多256MiB的后端编码瓦片字节，磁盘4GiB包括显示底图、瓦片、代理及帧映射；浏览器按512px RGBA瓦片设置128项上限，纹理／解码器／浏览器本身开销不等于此数值。缓存淘汰只删除previews中的自有派生文件，原件不动。每次读取持有Preview生成所有权和文件租用；流结束或断连后释放，已有永久清理和维护繁忙检查继续生效。

视频优先原生HTML video与Range流，不兼容编码及SER按需生成≤1920px H.264播放代理。SER有有效采集时间时通过FFmpeg时间基准及setpts命令保留时间；没有时标注10fps预览。代理记录实际PTS到源帧编号映射；暂停后读取原件帧，不把代理截图当原分辨率。FFmpeg showinfo整数PTS与time_base用于映射，避免浮点显示时间精度或平均帧率推算误差。没有FFmpeg／编码器、时间戳无法匹配及超预算均明确报错，不自动下载工具。

consumer_id及generation仅用于当前查看请求取消；服务内存淘汰失效记录，不写入缓存、科学记录或工作流。切换丢弃旧响应并使未开始的旧准备失效；瓦片断连可取消尚未开始的执行，已执行读取保留到释放，不在运行中删除文件。

旧100／1080接口继续服务现有非原生消费者；本候选不批量重建历史缩略图，也不把导入任务旧缩略图状态改写为新查看器验收事实。证据及未验证项见[验证矩阵](test-matrix.md#media-viewer)和`.artifacts/implementation/media-viewer-20261029/`。

以下100／1080行为描述既有缩略图与旧display接口；原生网页入口按上述候选使用统一查看器。科学原件与显示缓存分开，缺失预览不表示原件丢失。

## 网页行为

预览对话框表达加载、未就绪、失败和不支持状态，支持显式重试及按钮／背景／Escape 关闭。关闭后释放图像 URL 与轮询，迟到响应不能重新打开；未保存或保存失败的资料仍受离开保护。

项目固定组按引用版本的成员分页，不替换为集合或资产当前版本。组内浏览、参数编辑、排序、分页和删除继续保留，不再提供重复的管理成员入口。

网页打开单图时复用已有MTF配方；缺少时才从原件计算：RGB估计背景白平衡后使用统一MTF曲线，Mono只拉伸。配方属于所选固定版本及HDU，保存算法、偏移、通道系数、阴影／高光和中间调；首次自动测量的旧缩略图与大图仍同一事务更新。其他成员、原件及科学参数不变。算法细节见[素材说明](../architecture/assets.md)。

2026-10-28 最新选择覆盖此前全部逐图独立及256×256固定网格：图像组内subframe按同来源目录、相同Object及兼容布局复用固定顺序首张有效帧的MTF数值，masterframe每张独立；Object缺失独立，未知分类保留旧规则。统计改为原图空间分层随机抽样，固定种子、最多262144个空间样本，RGB保持通道对应，Bayer使用完整色彩单元。不是先缩图后测量，随机采样也非全量精确统计。显示尺寸仍为100／1080，XISF底层仍可能全帧解码。共享数值在每张配方及任务report保存，恢复／失败重试和已有组缓存回填可复用；已有可用缓存不批量重算。

## 调度与读取接口

共享作用域为 `/api/v1/library/assets/{asset_id}/versions/{version_id}/previews`；项目作用域为 `/api/v1/projects/{project_id}/asset-references/{reference_id}/previews`，解析项目固定版本并检查归属。

| 方法与后缀 | 行为 |
|---|---|
| POST `/display` | 用已保存配方调度或显式重试大图缓存 |
| POST `/display/auto-stretch` | 单图自动配方及缓存；已有结果复用，不强制重算 |
| GET `/display/status` | 查询状态，不启动任务 |
| GET `/display` | 只读取可用缓存 JPEG，不隐式生成 |

调度生成中返回 202，否则返回 200。状态为 `not_ready`、`generating`、`available`、`failed` 或 `unsupported`，包含固定版本、尺寸、错误及 stretch 结果；字段以[OpenAPI](../api/openapi.json)为准。失败缓存保留错误，显式调度可重试。

## 配方、并发和生命周期

缓存按固定版本、HDU、尺寸和算法版本定位。已有可用文件直接复用；同一版本生成时复用任务。使用服务共享预览线程池，遵守 preview_workers，不为单次请求创建解码线程池。

普通大图调度使用已保存配方；网页自动配方独立保存。已保存数值不依赖历史参考照片仍然存活，重建直接使用配方，不能从拉伸 JPEG 反推。等待旧配方任务的网页会在其完成后补齐自动配方。

元数据重试在同一事务将缩略图缓存标为 pending；旧 JPEG 即使仍在磁盘，也不作为可用配方。实际缓存状态决定可用性，不使用历史导入任务的 unsupported／failed 结果代替当前缓存。回填有效预览不改写历史任务和人工参数。

RAW 按请求尺寸选择内嵌或解码图像，不拿小封面冒充大图；SER／视频沿用首帧预览规则。XISF 等格式仍有全帧解码成本。

## 清理保护

生成中的明确所有权阻止并发永久清理。清理已开始时拒绝新预览；发布前在写事务中重新检查版本、所有权和状态，不能在版本被删除后补写缓存。共享缓存路径、临时文件和外部原件继续受保护。

启动将中断的 generating 任务标为可显式重试的失败，退出排空正在生成的任务。缓存失败不覆盖原缩略图或配方。当前检查见[验证矩阵](test-matrix.md)，回归主要位于 `tests/modules/data/test_display_previews.py` 和 `test_auto_stretch.py`。
