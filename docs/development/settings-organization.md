# 设置组织：设备组合与拍摄预设

## 已实现行为

- 选中组合后并排显示“新建拍摄预设”和“编辑设备组合”，下方显示已有预设，不重复展示组合名称、设备数量或清单；编辑打开现有组合表单，“更多”仅保留刷新及删除组合。单件规格继续在“我的设备”编辑。设备管理页签、组合表格及组合表单移除ⓘ图标，表格完整设备名称直接通过悬停文字查看。
- 拍摄预设表单展示可选名称前缀、所属组合滤镜、温度、曝光时间和ISO／增益模式及对应数值；增益模式同时展示Offset。不展示素材分类、相机默认值、累计曝光、Bin、CFA和说明。已有预设的隐藏字段保留，编辑可见字段不会清除旧值；HTTP契约、稀疏参数及零值语义不变。
- 组合可多选注册滤镜，预设选择本次使用的一片，候选只来自所属组合；未指定时沿用组合中首片注册滤镜的既有默认规则。旧预设引用组合外滤镜时显示原选择并保留，除非用户主动更改。
- 名称自动追加滤镜、曝光、温度及当前模式的ISO或Gain／Offset，示例为 `M31 [OIII · 60 s · -10 °C · Gain 100 · Offset 50]`。前缀可留空，未填的数值不加入后缀；全部为空且无默认滤镜时名称为“拍摄预设”。保存前显示完整名称，再次编辑本次生成的名称会拆出前缀，更新后缀而不重复追加；不另建名称存储字段。

- 设备组合列表采用固定六列横向表格：名称、相机、望远镜、赤道仪、滤镜、光学附件，左侧保留勾选框。缺少类别显示 `—`，同类多件显示摘要与数量，悬停文字查看完整名单；注册设备、组合内设备和历史成像系统均可显示，历史成像系统在望远镜列标明类型。不新增表单必填项，我的设备与素材库布局不变。
- 六列表头均支持首次升序、再次降序及方向提示；初始仍按创建时间倒序。组合排序与素材库独立，服务端先排序再分页；切换排序回到第一页并清空勾选，未保存草稿及保存期间禁止排序。长名称省略显示，表格仅在自身区域横向滚动。

- 素材库右上的“设备管理”入口默认展示设备组合，另有我的设备；项目页面从该模块移出，既有项目数据与接口保留。支持相机、望远镜、滤镜、赤道仪和配件，所有类别均为可选；保留历史类型及接收快照。
- 新建组合在原生md限宽弹窗中以五行搜索多选选择设备，勾选或取消直接更新组合草稿，不再单独点击加入。新建及编辑组合内设备在同一弹窗切换，返回保留组合草稿；“保存设备并加入”先登记设备，再加入组合草稿；取消组合不删除已登记设备，并直接显示保存提示。单件设备可跨组合复用。
- 使用组合可以关联注册设备，或保存只属于该组合的内联设备。编辑组合不会改写注册设备，也不会把内联设备登记进设备库。
- 拍摄预设在所属组合内创建和编辑，删除先展示影响，再直接删除，不经过回收站。预设参数保持稀疏结构：未触碰字段不写入；清空已填写字段传 `null`；数值 `0` 保留。
- 设备组合和我的设备统一精简工具栏：保留搜索与单个新建按钮，刷新放入“更多”，设备类别在我的设备页直接选择；组合不再显示筛选按钮和重复标题。列表勾选后显示批量删除，固定每页50条，仅多页显示分页。拍摄预设仍在组合详情内维护；单条及批量删除规则保持，新增和修改继续使用输入表单，不提供设置文件导入。
- 永久删除设备时，素材当前参数和固定版本保留设备快照，设备外键解除；直接删除时从关联组合移除该设备，并清除预设中对应设备默认值；不创建组合内副本。旧设置回收站接口仍保留原有项目及历史归档语义。接受后的导入任务独立保留设备资料，设备永久删除不会导致后续登记或重试失败。
- 旧版 CaptureProfile 已移除，包括旧入口、接口、项目字段和数据表；配置统一使用设备、使用组合、拍摄预设。0001–0008 为历史迁移，0009 移除旧结构，不转换旧配置为新预设。
- 项目固定版本引用的业务语义、数据和公开接口保留；设备管理不再展示项目页面，本轮不新增其他项目入口。
- 导入对话框先选组合再选所属预设，只提交 `capture_preset_id`，不把默认值填入人工表单。接受任务时由公共 `capture_defaults_snapshot` 保存配置快照，重试沿用原快照；人工／文件／预设的最终优先级由共享导入流水线计算。
- 组合和预设表单有未保存修改时，切换区域／记录会确认；搜索、筛选、分页与刷新在保存或取消前停用。

预设ISO模式只显示ISO，增益模式显示Gain及Offset，未设置或常规隐藏这些数值，切换保留草稿。清空Offset传null、0保持为0；滤镜恢复组合默认时传filter_id:null。预设归属及导入优先级规则保持，表单精简不改变原有数据。

## API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET / POST | `/api/v1/equipment-setups` | 分页查询／创建组合 |
| GET / PATCH | `/api/v1/equipment-setups/{setup_id}` | 读取／更新组合 |
| GET / POST | `/api/v1/equipment-setups/{setup_id}/presets` | 查询／创建组合内预设 |
| GET | `/api/v1/capture-presets` | 跨组合查询，可按 `equipment_setup_id` 筛选 |
| GET / PATCH | `/api/v1/capture-presets/{preset_id}` | 读取／更新预设 |
| POST | `/api/v1/equipment-management/delete-preview` | 读取设备／组合／预设的实际删除影响 |
| POST | `/api/v1/equipment-management/delete` | 校验 revision 与预览 fingerprint 后直接删除 |

列表沿用 `limit/offset/q/status/sort_by/order`。更新需要 `base_revision`，冲突返回 `409 REVISION_CONFLICT`；不存在对象为 `404 RESOURCE_NOT_FOUND`，错误设备关联为 `422 INVALID_REFERENCE`。预设参数和分类 PATCH 合并明确提供的字段，状态通过归档管理。后端 DTO、前端 Zod、代理白名单和生成的 OpenAPI 同步更新。

组合 `sort_by` 可用 `created_at/name/camera/telescope/mount/filter/accessory`；设备列比较组合内顺序拼接的完整设备名称，空列始终最后，同值按组合名称及ID稳定排序。原有 `component_kind` 按实际设备类型过滤，历史成像系统归入望远镜展示和排序不改变该过滤语义。

回收站、设备快照与当前手动检查见[设置记录管理](settings-management.md)，导入优先级见[导入流水线](import-pipeline.md)，验证证据见[验证矩阵](test-matrix.md)。
