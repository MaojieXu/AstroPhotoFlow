# 导入流水线

2026-10-28 选择器焦点修订：导入文件与文件夹采用同一原生窗口生命周期，读取当前前台宿主作为owner，显示时临时置前并随即取消全局置顶属性，后续由所属窗口关系维持层级。网页取消／卸载中止fetch，网关和服务逐层传递断连，先请求关闭本次子进程窗口，无法退出时仅终止该子进程并恢复宿主可交互状态；选择锁在退出后释放，重复打开返回明确冲突。不执行导入、复制或数据库写入。工作台配置自身的目录选择接口保持原有行为。

2026-10-28 用户修订：网页直接打开Windows本机选择器，按本次选中的绝对文件清单导入，不配置或限制预设授权目录。文件夹仅当前层支持格式；选择取消不建立任务，选完后沿现有资料确认及托管流程。imports省略root_id时接受绝对路径并固定清单和来源观察，任务内部空root_id表示直接来源；既有root_id相对路径和上传接口保留。此条覆盖本页较早授权目录前置说明，不改变登记、单次复制同步BLAKE3、原子归位、分阶段状态及通知规则。

导入分为登记、内容托管、元数据与预览阶段，各阶段状态分别表达。任务接口、CLI/MCP 和网页使用同一套领域规则。

## 登记与后台处理

登记固定成员顺序，读取 FITS／XISF Header，建立 Asset／AssetVersion、不可变接收资料及逻辑数据集；不在单项登记内散列、复制或解码图像；已登记项的复制可以与后续项登记重叠。待处理版本的 availability 为 unknown，hash／size 为空，content_status 为 pending。完整原件散列完成后才可用。

网页现在通过授权目录浏览API选取固定文件清单并调用managed导入；文件夹由网页展开为当前层支持文件，不提交递归目录。既有上传及授权目录递归HTTP／CLI／MCP行为保留。受理时枚举并保存sources.entries及size／mtime观察；后台不追加受理后到达的文件，来源变化阻止发布错误副本。

`task.report.registration` 包含 total、registered、completed；registered包括已完成的跳过／失败判定。`report.content`包含total／succeeded／failed／skipped／metadata_failed、bytes_total／bytes_copied及completed；bytes_copied是已就绪字节与正在复制的字节，不当作已校验可用字节。`report.preview`包含total／available／failed／unsupported及completed。网页主进度按原件字节和成功数量显示，登记100%不表示整批结束；原件阶段完成后可以继续后台预览。任务status仍在所有阶段结束后进入原有终态。

服务 lifespan 管理共享文件线程池与优先级预览执行器，默认 file_workers=2、preview_workers=1，所有导入、恢复和重试共用；退出时排空任务。导入任务等待自己的内容和预览任务结束才进入终态。活动或中断任务继续保护待处理资产，不能被永久清理。

登记一项后即可提交原件复制，独立轻量调度线程从已登记ID清单取任务，未收集完成的复制Future最多为file_workers的两倍；登记不因复制队列满而等待整文件完成，整组资料可先发布；合并进度写入间隔为0.5秒，文件完成及阶段结束强制刷新。取消检查在流式复制期间合并为至多每0.25秒一次，原子归位前再次检查。图像组仍固定成员顺序并保留版本／校准规则。

预览在原件阶段结束后使用共享执行器。文件夹／批量图像组中，相同Object的兼容subframe按固定顺序先测量首张有效帧，再分别排队渲染其余图片；首张失败时继续寻找下一张，不使整组失败。masterframe及无Object的subframe各自测量，不等待组基准。主动大图任务优先、可见缩略图请求提升尚未执行项，不打断正在运行的工作；原件阶段就绪先于预览完成，重试已有available原件不重复复制／哈希，已完成的预览不重建。

原生Toast通知仅面向本次提交或本会话观察的任务；以workspace／任务ID／content或preview类别保存在当前站点localStorage去重。原件阶段按成功／部分失败／全部失败表达，metadata_failed单独说明；晚到的预览异常按阶段只提示一次，历史任务不弹出。异常Toast提供本次详情及既有失败项重试；无历史页、通知中心或常驻结果汇总。详情任务仍运行时禁止重试，避免与在途任务并行重试。

## 原件与恢复

本地 managed 文件在后台一次读取中散列并复制到暂存文件，再原子归位。上传文件已经暂存，后台只散列并原子移入 objects，不再整文件复制。

归位后、数据库提交前中断时保留分配路径；恢复／重试重用原资产和版本 ID。取消清除未发布的部分复制，外部原件保持原位。

外部来源保留登记时 size／mtime；后台读取前后发现变化时返回 SOURCE_CHANGED，availability 为 changed，不发布部分副本。调用者确认当前来源后重新导入，不通过修改时间戳或盲目重试绕过检查。已发布 managed 原件的恢复不依赖外部来源仍然存在。

## 分类、参数和快照

FITS／XISF 按明确 Header 分类，保留原始观察值；无依据则未知，不按文件名猜测。省略的分类键使用文件／预设信息；提供的键覆盖整批对应字段，包含显式 null。网页整批手动分类同时提交两个键。

参数优先级为人工非空值、文件观察、接受时冻结的预设、未知；数值 0 有效。接收时固定组合、预设及设备完整快照，重试和恢复沿用原快照，不读取后来修改或删除的设备资料。`import_provenance` 保留字段来源、文件观察和默认值；后台不重写人工资料。

2026-10-28 最新分类策略：已有图像组中，明确为subframe或masterframe的FITS／XISF／常规图片使用原有MTF／背景白平衡算法；仅subframe可按Object共享。键包含本次任务、来源根／目录、规范化Object及格式／数值／颜色布局，不跨目录、任务或不兼容通道复用。Object来自登记的文件观察target_name，不猜测文件名。分类未知及非图像组来源继续既有百分位预览。任务report.preview_stretch_groups保存共享auto_stretch与reference_version_id；每张缩略图配方仍自包含，重试复制组数值，回填优先采用已有组配方且不改写历史任务。masterframe即使同Object也不登记共享配方。数据集成员顺序、发布和旧校准默认／覆盖保持，元数据与预览失败按原阶段规则重试。

## 性能证据与限制

历史候选 `c84f1a3` 与基线 `3f72b71` 使用同机、同输入、独立子进程测量；8 张 2048×2048 float32 合成 FITS，共 134,254,080 字节、每组 3 次。managed 总耗时中位数由 1.7769 s 到 0.3268 s，upload 由 1.9146 s 到 0.4145 s；这是当时暖文件系统样例，不保证所有格式或存储都有同样改善。

上传候选只写一次同等源文件字节，后续无第二份整文件写入；散列仍读取全部字节。阶段累计时间会重叠，不能相加还原墙钟时间。原始[初轮测量](import-pipeline-benchmark.json)与[后续分阶段测量](import-pipeline-phases.json)保留历史候选及环境，后者修正了首轮 RSS 可比性问题。

统计不再使用256×256固定步长缩图：原图按行和列分层，在每层随机取坐标，固定NumPy种子，预算最多262144个空间样本，小图使用全部像素。FITS读取抽中行的连续条带再在内存选列，保留缩放及平面／交错RGB语义；Bayer按2×2完整色彩单元取R、平均G和B，避免固定采样落在同一CFA相位。XISF及常规图片在原件解码后抽样，不从JPEG反推；XISF仍可能全帧解码。8位映射继续限定在预览规模，大图最长边1080。采样是速度／代表性取舍，不能保证全图极值或细小结构全部入样；未运行测试、性能测量或图像质量验收，不宣称实测精度改善、提速幅度或最快策略。实现使用既有[NumPy随机生成器](https://numpy.org/doc/stable/reference/random/generator.html)，不增加依赖。

回归入口为 `tests/modules/data/test_import_pipeline.py`、`test_ingestion.py` 和 `test_equipment_snapshots.py`；当前结果见[验证矩阵](test-matrix.md)。
