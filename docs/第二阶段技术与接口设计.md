> 本文保留第二阶段基线；“素材库第二轮 UI 与导入优化”是现行交互与接口补充。冲突时，现行规则优先：Windows 系统文件／文件夹选择后上传托管；文件夹只收集第一层；分类可全部未指定；视频生成首帧预览；素材默认简约列表，细节模式双击单元格编辑；筛选为可拖动即时生效浮窗。

**更新日期：2026-10-22；关联任务：T01；状态：设计定稿，实际实现与验收结果见[第二阶段验收记录](第二阶段验收记录.md)。**

本文记录 human–agent loop 中已经确认的第二阶段需求、技术边界及接口增量，作为实现与验收依据。接口、状态和格式支持以本契约、实现 worktree 的实际代码、导出的 OpenAPI 及验收记录共同核对；设计条款本身不代表功能已通过验收。

返回[开发总计划](开发计划.md)；当前阶段划分见[资产管理实施计划](资产管理三阶段实施计划.md)；全模块需求见[数据库与图像资产管理实施计划](数据库与图像资产管理实施计划.md)。第一阶段既有技术约定见[第一阶段技术与接口设计](第一阶段技术与接口设计.md)，具体实现及审查状态以 `feature/database` 的对应交付记录为准。

**本轮简化决定：**分类、拍摄参数和备注直接编辑，相关项目显示最新资料，不为这些编辑建立图像历史版本；不同导入批次对同一文件独立建档；不进行导入后的全库可用性检查、文件变化监控或变化确认。本文据此替代早期关于“参数修订新版本、重复导入复用旧资产版本、来源变化确认”的第二阶段条款。数据集成员固定版本规则继续保留。

## 一、目标与阶段边界

第二阶段交付以下真实闭环：

> 选择素材 → 填写信息 → 后台入库 → 查看资产／数据集 → 项目选用。

本阶段已经纳入文件夹批量导入、基础数据集及成员版本管理。当前先完成数据库增删改查、导入和资料编辑；“删除”沿用归档／恢复及移除关联，不物理删除原始文件。第三阶段暂缓，拖入画布、资产引用节点及其他素材库增强不作为本次交付要求。下一步另行建设 AI Panel 和 Agent 数据管理，本阶段不自动实施。

实施基于第一阶段审查修复后的 `feature/database`。该名称是 Git 分支，不是源码目录；服务、扩展和前端仍沿用既有目录。第一、第二阶段验收及必要集成回归通过且无阻断问题后，报告具备合并到 `dev` 的条件，不等待暂缓的第三阶段；实际合并按用户明确指令执行。

本阶段允许创建共享资产及内部内容记录，直接编辑资产资料，写入数据集及其成员版本、项目引用和导入任务。保留第一阶段的项目、设备及拍摄配置管理，不扩大为软件执行或 Agent 建设。第一阶段事实以已验收的 `ce8404e` 为基线，不以主工作区旧草稿覆盖该分支的实现约定。

## 二、导入交互与素材信息

### 1. 文件选择

- “导入”菜单打开 Windows 系统文件或文件夹选择器；文件经 ComfyUI 同源代理流式上传至 WSL 服务并托管，不要求配置 `imports.roots`。
- 文件夹只收集所选目录第一层；明确忽略子目录。
- 文件夹入口支持常规图片、FITS、RAW、XISF 和视频格式；其他扩展名不导入。整个文件夹选择形成一个数据集，即使只有一个有效文件。
- 原有 `/imports` 根目录接口保留；素材库界面使用上传接口。不修改源文件，不在源目录生成 sidecar 或预览。

| 选择方式 | 结果 |
|---|---|
| 单独选择一个文件 | 独立资产 |
| 多选文件 | 一个数据集，每个文件仍是独立资产 |
| 选择文件夹 | 一个数据集，即使其中只有一个有效文件 |
| 没有文件成功入库 | 保留失败报告，不发布空数据集 |

同一次导入中的重复来源只处理一次。文件选择顺序作为多选的初始顺序；文件夹内按来源相对路径升序固定顺序。数据集保存该顺序，不在每次查询时重新扫描目录计算成员。

不同导入批次即使选择同一个文件，也创建新的独立资产条目，参数和备注互不影响，不按路径或散列跨批次复用条目。新的多文件／文件夹批次创建新的数据集；向已有数据集增加已入库资产通过成员编辑完成，不因目录名称相同而自动合并数据集。重试不是新的导入批次，不能重复登记已成功的资产。

### 2. 信息填写

选好来源后可以填写本批素材信息，也可以全部留空直接确认导入。未指定的分类和参数保持为空，不默认设为 Subframe／Light。

| 字段 | 规则 |
|---|---|
| 素材形态 | 未指定、`subframe`、`masterframe`、`video` |
| 帧用途 | 未指定、`light`、`bias`、`dark`、`flat`、`dark_flat`；Video 不设置帧用途 |
| 相机 | 可选，引用已有具体设备档案 |
| 参数填写模式 | ISO 型、Gain 型、常规型 |
| ISO 型 | 显示可选 ISO |
| Gain 型 | 显示可选 Gain、Offset |
| 通用参数 | 可选单帧曝光、传感器实测温度、Binning |
| Masterframe | 另外提供可选累计曝光时间 |
| Light／Flat | 显示可选成像系统及滤镜，包含对应 Masterframe |
| 备注 | 导入表单可选；单文件写入资产备注，多文件／文件夹写入数据集备注；每张图像详情均提供独立可编辑的多行备注块 |

三种填写模式仅控制人工表单，不用于判断 Mono／Bayer／RGB，也不丢弃文件已有的其他参数。未知值保持为空；零曝光、零 Gain／Offset、负温度继续按既定规则处理。

设备关联及最终采用参数作为资产当前资料保存，可直接编辑，不自动修改设备或拍摄配置默认值，不按型号或名称猜测具体设备 ID。Master Light 作为已叠加的输入素材管理，不自动认定为最终成品或执行发布。

导入时均进入本机共享库，随后可由项目选用既有内部资产／内容记录 ID；不要求用户管理图像版本。第二阶段不提供项目私有导入或项目成品发布。

### 3. 字段与单位

以下名称用于请求模型和资产当前资料，延续第一阶段命名：

| 字段 | 类型及约定 |
|---|---|
| `frame_class` | `subframe` / `masterframe` / `video` / null |
| `frame_type` | 帧用途枚举 / null；Video 必须为空 |
| `camera_id`、`optical_system_id`、`filter_id` | UUID / null；存在时检查对象及设备类型 |
| `parameter_mode` | `iso` / `gain` / `standard`；表示人工填写模式 |
| `iso` | 正整数 / null |
| `gain`、`offset` | 有限数值 / null，不套用未经设备验证的范围 |
| `exposure_seconds` | 非负有限数值 / null，输入单帧曝光，单位秒 |
| `integration_seconds` | 非负有限数值 / null，Master 的累计曝光，单位秒 |
| `sensor_temperature_c` | 有限数值 / null，传感器实测温度，允许负值 |
| `binning_x`、`binning_y` | API 保留两个正整数 / null 字段；界面选 Bin1–Bin16 时同时写入两字段。旧非方形值只读时保留 |
| `cfa_pattern` | null、`MONO`、四种 Bayer、`XTRANS`、`QUAD_BAYER`；新非 Bayer CFA 仅登记元数据 |
| `notes` | string / null |

JSON 数字不通过字符串猜测转换，不使用零代替未知值。文件中的制冷设定温度与实测温度分别保留，不能把环境温度或设定值直接写入 `sensor_temperature_c`。

### 4. 文件信息与人工信息

- 用户明确填写或修改的值优先；导入时未填写或为 null 的可选参数，可以采用文件解析值，双方都没有值时保持 null。零是有效输入，不能当作未填写。
- 原始 Header、文件解析结果和当前人工填写内容分别保存，记录参数来源及解析器版本；人工编辑不覆盖原始 Header 或解析值，不改写原件。
- 导入时用户确认的分类直接生效。与文件分类不同则展示原始信息供查看，不暂停任务，不等待逐文件确认。
- 资产详情、数据集及项目页面均显示该资产最新分类、参数和备注；数据集中的不同成员仍可具有不同的当前资料，不能以封面资料代表全部成员。
- Master 的单帧曝光与累计曝光分别保存；来源语义不明确时保留原字段，不自行推算，也不直接用帧数乘曝光猜测累计值。[Siril 曝光字段说明](https://siril.readthedocs.io/en/latest/processing/hdr.html)
- 选择已有设备不等于把其当前参数全部认定为拍摄事实；设备／拍摄配置默认值修改不自动追写资产资料。

本阶段不保存分类、参数或备注的修订历史。文件信息是导入或本次解析时记录的事实，不能将其显示为刚刚检测过的源文件现状；人工资料以最近一次成功编辑为准。

## 三、数据模型、版本与接口

### 1. 基础技术约定

沿用第一阶段 Vue 3、TypeScript、Vite、Tailwind 4、Pinia、Zod、独立 FastAPI、Pydantic、SQLAlchemy 2 同步 ORM、Alembic 和 SQLite；数据库启用外键和 WAL，写事务使用 `BEGIN IMMEDIATE`，Session 不跨线程共享。

本阶段实际接入 BLAKE3、Astropy、NumPy 和 Pillow，依赖由独立服务的 uv 环境管理并锁定。ComfyUI 扩展继续仅承担同源代理，不导入科学处理依赖。ComfyUI 加载扩展时，扩展后端认证并复用健康的本机服务；否则使用锁定环境自动启动服务并等待就绪。依赖必须提前准备，ComfyUI 启动不安装依赖或执行数据库迁移。

自动启动使用 `uv run --project service --locked --no-sync apf-service serve`。先在进程 `PATH` 中查找 uv，再查找本机 `~/.local/bin/uv`。等待服务就绪最多 20 秒；失败时后端记录明确错误，代理返回资产服务不可用状态，不阻止 ComfyUI 完成本身启动。运行期间健康检查间隔 5 秒，连续三次健康检查失败后标记不可用。受管服务意外退出时只自动重启一次；扩展退出只停止其启动的进程，复用的外部服务保持运行。

ID、UTC 时间、分页、错误外壳、请求 ID、Bearer 认证、浏览器来源检查和 revision 并发规则沿用第一阶段。未声明字段不进入请求模型；写入失败不部分提交，不自动覆盖或重试。

### 2. 模型增量

| 模型 | 增量职责 |
|---|---|
| Asset | 保存当前 `classification`、`parameters`、名称、备注和用途 `role`，支持直接编辑、归档／恢复及 revision 保护 |
| AssetVersion | 保留既有内部内容记录 ID、存储位置、导入时散列及文件解析信息，用于关联与预览定位；不作为资料修订历史，不承诺外部引用文件始终不变 |
| Dataset | 数据集稳定身份、名称、备注、状态、revision 及当前版本 |
| DatasetVersion | 数据集不可变成员版本及创建时间 |
| DatasetMember | 指向固定 AssetVersion，保存成员顺序及来源相对路径 |
| ProjectDatasetReference | 项目引用指定数据集版本，不展开为自动跟随最新版本的成员 |
| AssetTask / AssetTaskItem | 批次及逐文件阶段、分层结果、错误和重试来源；区分内容入库与解析／预览结果 |
| FitsHduMetadata | 保存版本绑定的 HDU 描述、原始 Header 及解析信息 |
| Preview | 保存版本绑定的派生预览、尺寸、参数、算法版本及状态 |
| CaptureProfile | 增加可空 ISO 及 `iso`／`gain` 参数模式字段；旧资料保持未指定模式 |

`role` 表示资产当前用途，由当前分类确定：帧用途为 `bias`、`dark`、`flat`、`dark_flat` 时为 `calibration`，其余导入素材为 `raw`；因此 Master Dark 为校准素材，Master Light 为原始输入素材，未指定校准用途的 Video 为原始素材。不因 Masterframe 自动赋予 `intermediate` 或 `final`，后两者仍留给后续实际处理／发布流程。

不把 Subframe／Masterframe 简单复用为校准级别：Light 也可为 Masterframe。校准用途的 Subframe 对应 `individual`，Masterframe 对应 `master`；Video 和非校准用途的 `calibration_level` 为 null。分类编辑在同一事务中更新当前用途及派生分类。共享库、校准库、项目及数据集的显示与分类／参数筛选统一使用 Asset 当前有效资料，不再使用历史内容记录中的旧分类作为权威值。

旧全量计划中的 Collection／CollectionRevision／CollectionMember 对应本阶段 Dataset／DatasetVersion／DatasetMember 的固定成员版本语义，不为两组名称分别建立重复实体。

原始 Header、文件解析结果与可编辑的当前资料分开保存。保留项目的内部内容记录引用和数据集成员 ID，不代表冻结资产资料或永久保留外部文件字节；修改资料不替换这些关联 ID。

### 3. 直接编辑、独立建档与数据集版本

- 每个导入批次独立创建资产和内部内容记录，不按路径或 BLAKE3 复用其他批次的资产，也不自动合并其物理存储。
- 名称、备注、分类和拍摄参数通过同一资产编辑入口直接修改，成功后增长 Asset revision，不新增图像内容记录，不复制科学文件。
- 相关项目和数据集读取该资产最新资料；一个独立条目的编辑不影响其他导入批次的条目。
- 列表、进入项目及读取数据库记录时不扫描原件、不复算散列、不弹出可用性确认。需要读取原件时才按对应路径访问，缺失或读取失败即明确提示。
- 不建立导入后的文件变化监控、自动更新或变化确认流程。引用方式按使用时实际可读的文件读取，导入散列不是以后文件未改变的保证。
- 数据集增删成员产生新版本；原有成员保持顺序，新成员追加。手动排序界面列为后续增强候选。
- 项目引用的数据集成员版本仍固定，不自动添加或移除成员；固定成员不冻结各资产可编辑资料。
- 归档不删除版本、原件或既有项目引用；按 ID 读取历史引用时仍能显示其归档状态。物理清理不属于本阶段。

### 4. 素材根目录配置

在共享的 `~/.config/astrophotoflow/config.toml` 中增加素材根目录配置，保留原服务、存储及 ComfyUI 配置。例如：

```toml
[[imports.roots]]
id = "astrodata"
path = "~/AstroData"

[[imports.roots]]
id = "mounted-data"
path = "/mnt/d/AstroData"
```

这是配置示例，不创建上述目录或默认授予其权限。没有配置来源时，现有管理及查询功能继续可用，导入页面明确提示尚未配置素材来源。

浏览器以根目录 ID 和相对路径提出浏览／导入请求。服务展开配置路径并核对实际来源在允许范围内，不允许通过路径穿越或符号链接解析越出根目录。递归枚举不得通过目录链接形成循环；不支持的来源类型列明原因。

### 5. API 增量

统一使用 `/api/v1`，请求和响应为 JSON；预览图片使用对应图片内容类型。成功创建、读取、编辑及错误外壳沿用第一阶段，异步导入返回 `202`。

| 资源 | 接口与职责 |
|---|---|
| 素材来源 | 原有 `GET /import-roots`、`GET /import-roots/{root_id}/entries` 继续服务 `/imports` 接口；新增浏览器文件上传流程，不依赖根目录浏览 |
| 导入 | `POST /imports`：提交有序来源列表、存储方式、分类、可选参数和备注，返回任务 ID |
| 浏览器上传 | `POST /uploads`、`PUT /uploads/{task_id}/{index}`、`POST /uploads/{task_id}/start`：创建托管批次、流式传输文件并开始后台处理；`create_dataset` 支持单文件文件夹成为数据集 |
| 任务 | `GET /asset-tasks`、`GET /asset-tasks/{task_id}`：批次及逐文件结果 |
| 任务操作 | `POST /asset-tasks/{task_id}/cancel`、`POST /asset-tasks/{task_id}/resume`、`POST /asset-tasks/{task_id}/retry` |
| 资产管理 | `PATCH /library/assets/{asset_id}`：名称、多行备注、分类、拍摄参数及归档／恢复，携带 `base_revision`，返回完整当前资料 |
| 数据集 | `GET /datasets`、`GET /datasets/{dataset_id}`、`PATCH /datasets/{dataset_id}` |
| 数据集版本 | `GET /datasets/{dataset_id}/versions`、`POST /datasets/{dataset_id}/versions`：读取或提交有序成员版本集合 |
| 数据集成员资料 | `PATCH /datasets/{dataset_id}/member-parameters`：带数据集版本及各成员 revision，在一个事务内更新指定的成员参数或分类；任一冲突整批回滚 |
| 素材库 | `GET /library/items`：资产／数据集混合列表及服务端筛选；`GET /library/filter-options`：依据有效素材和数据集成员返回可用筛选值及数值范围；温度以四舍五入后的整数匹配，半度远离零 |
| 项目选用 | 为资产引用及数据集引用提供读取、添加、移除接口；添加时明确指定版本 |

导入请求结构示例：

```json
{
  "sources": [
    {"root_id": "astrodata", "path": "M31/Light"}
  ],
  "storage_mode": "reference",
  "classification": {
    "frame_class": "subframe",
    "frame_type": "light"
  },
  "parameters": {
    "camera_id": null,
    "optical_system_id": null,
    "filter_id": null,
    "parameter_mode": "gain",
    "iso": null,
    "gain": 100,
    "offset": null,
    "exposure_seconds": 60,
    "integration_seconds": null,
    "sensor_temperature_c": -10,
    "binning_x": 1,
    "binning_y": 1
  },
  "notes": "本批采集备注；本次明确填写的参数优先，未填写项可采用文件解析值。"
}
```

`storage_mode` 使用已有 `reference`／`managed` 枚举；界面分别显示引用／复制托管。来源是文件还是目录由服务检查，不只相信客户端声明。

`classification` 可以省略，也可以只提交 `frame_class` 或 `frame_type`；未提交字段保持未指定。文件 Header 中的分类只保留为解析资料，不自动填入当前分类。

异步受理响应示例：

```json
{
  "task_id": "98dbd487-bce8-42a0-a3b8-4c68de56592e",
  "status": "queued"
}
```

受理不表示文件、元数据或预览已经成功。来源枚举中出现的文件级失败通过任务报告返回，不使用 HTTP 202 掩盖后续错误。

资产 PATCH 的 `classification` 和 `parameters` 使用上述同名对象及字段，按提供的键局部更新；省略字段保留原值，可空字段明确传 null 表示清空，不再用文件解析值自动填回。`notes` 支持多行文本。分类对象及必填分类不能清空，Video 的 `frame_type` 可为 null。只检查已有数据类型、数值及设备引用规则，不自动创建设备或修改设备默认值。请求成功后，资产详情和引用页面返回最新有效资料。

不提供 `POST /library/assets/{asset_id}/versions` 科学修订接口，也不建设图像历史版本列表或界面。

### 6. 内部内容记录、数据集版本及项目引用读取

第二阶段保留以下按内部 ID 定位的读取路径及项目选用入口，不将其解释为图像资料历史管理：

| 方法 | 路径 | 职责 |
|---|---|---|
| GET | `/library/assets/{asset_id}/versions/{version_id}` | 按既有内部 ID 读取内容记录；当前分类与参数从所属资产读取 |
| GET | `/library/assets/{asset_id}/versions/{version_id}/hdus` | 读取已保存的 HDU 描述 |
| GET | `/library/assets/{asset_id}/versions/{version_id}/hdus/{hdu_index}/header` | 读取对应版本已保存的 Header |
| GET | `/library/assets/{asset_id}/versions/{version_id}/previews/{size}` | 读取 `thumbnail`／`detail` 两档预览 |
| GET | `/datasets/{dataset_id}/versions/{version_id}` | 读取指定数据集版本及有序成员 |
| POST | `/projects/{project_id}/asset-references` | 添加指定资产版本引用 |
| DELETE | `/projects/{project_id}/asset-references/{reference_id}` | 移除引用，保留共享资产与版本 |
| GET | `/projects/{project_id}/datasets` | 查询项目固定数据集版本引用 |
| POST | `/projects/{project_id}/dataset-references` | 添加指定数据集版本引用 |
| GET | `/projects/{project_id}/dataset-references/{reference_id}` | 读取具体数据集引用 |
| DELETE | `/projects/{project_id}/dataset-references/{reference_id}` | 移除数据集引用，保留共享数据集 |

第一阶段的项目资产列表及引用详情继续保留内部内容记录引用，分类、参数和备注改为展示所属资产最新资料。项目引用的添加／移除校验所属项目的 `base_revision`，更新与 revision 增长在同一短事务中完成；数据集成员修改校验 Dataset revision；资产直接编辑校验 Asset revision。冲突仍返回 `409 REVISION_CONFLICT`，前端保留草稿。

数据集版本创建请求携带 `base_revision` 和有序 `asset_version_ids`，不提交文件路径代替成员身份，不接受重复成员版本。添加引用携带明确 `asset_version_id` 或 `dataset_version_id`；移除只修改所属项目关联，不改变原件及其他项目。

预览及 Header 读取按资产版本提供，沿用共享／项目范围检查，不接受任意文件路径下载。共享路径不返回项目私有资产；项目视图必须先验证引用属于该项目，再读取其固定版本。预览未生成、生成失败和格式不支持分别说明原因，不返回虚构 URL。

代理白名单、Zod、OpenAPI 和 capabilities 随接口同步更新。`asset_import`、`asset_reference_write`、`asset_preview` 按实际实现开放，补充数据集、资料编辑和归档能力描述；不宣告图像科学版本修订能力。视频／NumPy 预览、校准匹配和发布仍不可用。实现时从实际应用导出 OpenAPI，不用设计文档代替运行结果。

## 四、后台处理、格式与展示

### 1. 文件处理与任务

处理顺序为：

> 来源枚举 → 文件读取／复制 → BLAKE3 → 记录文件信息与人工资料 → 预览 → 发布结果。

文件工作不占用长数据库写事务。后台工作由领域服务受控执行，任务持久化到数据库，不引入外部 runner 或分布式队列。

- 单个文件失败不阻止其他文件处理。
- 内容入库、元数据解析及预览生成分别记录结果；解析／预览失败不伪装成成功，也不抹掉已验证保存的文件。
- 数据集初始版本在批次结束或取消时发布，包含内容已成功入库的成员；已成功入库的独立资产可以查询。
- 取消时保留成功项，安全停止当前工作及来源枚举；只保留已枚举的逐文件项供选择性重试，未枚举来源另行发起导入，不显示为已处理或成功。
- 服务中断后标记任务，由用户明确恢复原任务；只核对该任务未完成部分，不检查整个素材库，不自动重跑整批。
- 重试只处理用户选定的失败或未完成项，创建关联原记录的新任务并保留原尝试。已成功入库的文件只重试失败的解析／预览阶段，不重新登记资产。向原数据集补充新成功成员时产生新数据集版本，不修改已发布成员版本；已有成员不重复追加。
- 不执行无限自动重试；无法恢复的项给出明确原因。

复制时先写任务专用暂存文件，核对实际复制内容后发布至受控位置，再提交成功内容记录。引用时记录来源位置及本次读取的散列；导入过程的读取、复制或登记失败按失败报告，不进入等待确认状态。

导入完成后不进行文件变化检查或定期巡检。已生成预览按缓存显示，不因此证明原件当前仍可访问；后续需要读取原件而失败时再提示。再次读取引用路径取得的是使用时内容，不宣称能恢复导入时字节；不自动改写保存的原始 Header 或导入散列。

### 2. 数据集成员资格与结果判定

“内容成功”表示本次引用文件读取及散列记录已完成，或托管文件已复制发布，并且资产／内容记录成功登记。用户在导入表单中确认分类，不再另设逐项分类确认。成员资格不以解析或预览成功为条件。

| 情况 | 数据集与项目选用 | 逐项结果／批次汇总 |
|---|---|---|
| 内容入库成功，已声明处理成功 | 允许 | 正常完成 |
| 内容已入库，FITS 解析或预览失败 | 允许，独立显示问题 | 有成功内容及错误，汇总为 `completed_with_errors` |
| 非 FITS 按本阶段范围不支持解析／预览 | 允许，标记不支持 | 预期未支持不算失败，可正常 `completed` |
| 文件读取、复制或内容登记失败 | 不纳入 | 记录失败；批次有其他成功内容时为 `completed_with_errors`，零成功时为 `failed` |
| 用户取消 | 保留内容已成功入库的成员 | 实际停止后为 `cancelled`，保留各阶段结果 |

跳过的非声明格式正常列入报告，不伪装成入库；零成功内容不发布空数据集。建立项目引用不表示素材已具备后续科学执行能力，第二阶段不为此新增执行预检或 runner。

### 3. 任务状态与操作契约

| API 状态值 | 界面含义 |
|---|---|
| `queued` | 已受理，等待执行 |
| `running` | 正在处理，显示实际阶段 |
| `cancelling` | 已收到取消请求，实际工作正在安全停止 |
| `completed` | 本次预期工作完成 |
| `completed_with_errors` | 有成功结果，同时存在失败或处理问题 |
| `failed` | 本次任务未形成成功结果 |
| `cancelled` | 用户取消，实际工作已安全停止 |
| `interrupted` | 服务中断，尚待核对和用户恢复 |

逐文件报告保留来源、阶段、内容登记结果、元数据／预览状态、关联资产／内部内容记录及错误，明确区分缺失、读取失败、处理失败和预期不支持；跳过项也列明原因。取消后，已经枚举并登记逐文件 ID 的失败或未完成项仍能被选中重试；未枚举文件不生成虚构的逐文件 ID 或条数。

任务计数分别表达已枚举、内容已入库、处理问题、失败、跳过和取消；不再设置跨批次复用数或待确认数，不把“文件已入库”等同于“全部科学解析与预览成功”。总量尚未枚举完成时，不显示虚构百分比。

| 操作 | 请求与允许状态 | 结果 |
|---|---|---|
| `POST /asset-tasks/{task_id}/resume` | JSON `{}`；仅 `interrupted` 原任务 | 沿用原任务 ID，将未完成部分重新排队；已成功登记内容不重复复制或入库，返回 202 与原 `task_id`、当前 `status` |
| `POST /asset-tasks/{task_id}/retry` | `{"item_ids":["已登记的逐文件项 UUID"]}`；原任务为 `failed`、`completed_with_errors` 或 `cancelled`，选中项必须有失败或未完成的文件处理阶段 | 创建新任务，保存 `retry_of_task_id` 与逐项 `retry_of_item_id`，返回 202 与新 `task_id`、`status=queued`；原任务记录保留；不用于修复数据集成员发布冲突或继续未完成的目录枚举 |
| `POST /asset-tasks/{task_id}/cancel` | JSON `{}`；`queued`、`running`、`cancelling` 或 `interrupted` | 返回 202 与原 `task_id`、当前 `status`；运行中的工作先进入 `cancelling`，实际安全停止后才为 `cancelled`；无在途工作的任务可直接取消 |

不允许的任务状态返回 `409 TASK_STATE_CONFLICT`，不创建新尝试；不存在的任务或不属于原任务的项返回 `404 RESOURCE_NOT_FOUND`；空或重复 `item_ids`、没有可重试阶段的选中项返回 `422 VALIDATION_ERROR`。操作前后状态在短事务中更新，重复的恢复请求不能再次启动同一个运行中任务。

恢复处理原任务已保存的进度；重试处理新任务选中的阶段。二者均不做全库扫描，不重新处理成功阶段。原批次已有数据集时，新增成功成员追加到该数据集的新成员版本；首次有成功成员时才发布数据集。数据集成员写入仍受 Dataset revision 保护，冲突保留已成功资产及错误记录，不自动覆盖用户修改。

#### 数据集追加冲突的处理策略

文件处理成功，但向已有数据集追加成员时发生 revision 冲突，该次成员发布事务不写入新成员版本或改变当前成员版本指针，已成功登记的资产保留。正常结束的任务汇总为 `completed_with_errors`；已经取消的任务仍为 `cancelled`，同时保留发布错误。

任务详情提供 `dataset_publish_error`，没有此错误时为 null；发生冲突时至少包含 `code=REVISION_CONFLICT`、`dataset_id`、`expected_revision`、冲突时读取的 `observed_revision`，以及尚未追加的有序 `pending_asset_version_ids`。这属于任务报告中的错误，不将任务查询本身返回为 HTTP 409。界面提供“手动补入数据集”入口。

恢复只使用现有成员编辑流程：用户重新读取数据集当前资料及当前成员版本，确认希望补入的资产，再以最新 `base_revision` 调用 `POST /datasets/{dataset_id}/versions`。请求保留用户确认的当前成员顺序，选中的未包含成员追加到末尾；不恢复用户已移除的其他成员，也不重复追加既有成员。再次冲突时按普通成员编辑的 409 处理，保留草稿，不自动重试。

手动补入成功后，不重跑文件、解析或预览阶段，不改写原任务的错误及终态。只有成员发布冲突、没有失败或未完成文件阶段的项，不符合 `retry` 条件，提交重试仍返回 `422 VALIDATION_ERROR`；不为此增加恢复端点或新任务状态。

#### 来源枚举期间取消的处理策略

批次受理时先保存所选来源；后台枚举时逐文件登记 ID，再处理相应文件。收到取消后停止继续枚举，不为补齐逐文件清单而遍历剩余目录，实际在途工作安全停止后报告 `cancelled`。

任务及所选来源报告保存 `enumeration_completed`：尚未开始或尚未完整枚举的来源为 false，完整枚举后为 true；任务级字段仅在所有来源都枚举完成时为 true。报告保留原始 `root_id` 和相对路径，明确提示“枚举未完成，剩余文件未处理”，不推算未知文件总数。

只允许对已登记逐文件 ID 的失败或未完成项调用 `retry`。未枚举的来源不能通过该操作继续；取消的任务也不能调用 `resume`。用户需要处理剩余来源时，重新打开文件页面选择相应范围，显式创建新的导入批次；该批次不自动归入原数据集。

新批次继续遵守跨批独立建档规则。界面须提示：重新选择整个原目录会对其中已入库文件再次独立建档，用户可改选剩余范围。若取消发生在 queued 且尚未登记任何逐文件项，报告零已枚举项，不提供空列表重试；零成功内容仍不发布空数据集。`interrupted` 原任务的恢复仍按现有 `resume` 契约执行，与主动取消区分。

本阶段不再提供 `resolve` 端点或 `awaiting_input` 状态。人工资料通过资产编辑更新；文件不可读通过实际使用或任务错误反馈。

HTTP 写请求不自动重试；用户重试和恢复通过显式任务操作发起。前端离开当前页面不取消服务端任务，页面重开可查询实际状态。

### 4. 格式范围

| 格式类别 | 入库 | 第二阶段元数据／预览 |
|---|---|---|
| FITS | 引用／复制，计算 BLAKE3 | 提供本节所定义的元数据及预览闭环 |
| 常规图片 | 按声明清单入库 | 明确显示暂不支持解析／预览 |
| 相机 RAW | 按声明清单入库 | 明确显示暂不支持解析／预览 |
| XISF | 入库 | 解析／预览留待后续 |
| NPY／NPZ | 入库 | 数组成员及切片查看留待后续 |
| 已录制视频 | 按声明清单入库 | 封面、视频解析及逐帧查看留待后续 |

实际实现必须发布扩展名与识别规则清单，并据此生成文件选择过滤及逐文件报告。非 FITS 格式显示“已入库，解析／预览暂不支持”；扩展名识别是格式线索，不是文件完整性验证。

FITS 规则：

- 保存 HDU 描述及按顺序保留的 Header，包含重复 COMMENT／HISTORY；列表仅返回摘要。
- 自动选择首个支持的图像 HDU，记录所选索引和依据；选定后处理失败则展示错误，不继续换用其他 HDU。
- 支持 Mono、具有明确 CFA 信息的 Bayer、具有明确通道含义的 RGB 图像；一般三维数组、表格等不自动猜测为 RGB。
- 保存尺寸、数值类型、BSCALE／BZERO、无效值及单位等已解析信息，不为列表加载完整像素数组。
- 科学原件保持只读。读取显示数据时正确解释缩放；预览不写回 FITS。[Astropy FITS 图像读取说明](https://docs.astropy.org/en/stable/io/fits/usage/image.html)

### 5. 预览规格

| 场景 | 规格 |
|---|---|
| 素材列表 | 最长边 **100 px** 缩略图 |
| 点击缩略图 | ComfyUI 内可关闭的预览浮层，使用最长边 **1024 px** 图像，不打开浏览器新窗口 |
| 尺寸 | 保持宽高比，不放大小图 |
| Bayer | 根据已确认 CFA 信息生成彩色显示；信息不足时提示补充 |
| Mono／RGB | 生成自动拉伸后的低分辨率显示 |
| 数据集封面 | 使用该数据集版本的第一成员；不可预览时显示原因 |

默认采用 JPEG 派生文件；记录预览算法、显示参数及所绑定版本。拉伸使用固定的自动预设，原始科学数据保持不变。算法及预设参数随实现明确记录，便于测试和重建，不提供本阶段以外的完整调色工具。[Astropy 显示归一化说明](https://docs.astropy.org/en/stable/visualization/normalization.html)

预览浮层保留素材库的滚动及选择位置，关闭后返回原位置；焦点及键盘行为限定在浮层交互中，不意外触发画布操作。

### 6. 素材表格

素材库以表格为主，左侧缩略图和名称，右侧独立列展示：

> 分类、成员数、相机、ISO／Gain、曝光、温度、成像系统、滤镜、存储方式、处理状态及备注。

宽度不足时横向滚动。单张和数据集通过类型与成员数明确区分，点击数据集可查看其固定版本成员；不把封面显示为合成结果。

数据集参数不一致时显示“混合”，部分缺失时明确标注，不以封面成员的参数代表整个数据集。不根据当前配置或成员数量猜测未知累计曝光。

## 五、验收、文档交付与停止线

### 1. 实现批次

| 批次 | 交付内容 | 出口 |
|---|---|---|
| S2-1 | 数据模型增量、迁移、素材根目录及来源浏览 | 第一阶段数据保留，来源边界清楚 |
| S2-2 | 引用／复制导入、BLAKE3、逐文件任务及独立建档 | 文件真实入库，同批去重、跨批独立和失败结果准确 |
| S2-3 | 当前分类／参数／备注编辑、数据集及项目引用 | 编辑直接生效，成员版本固定，修改受 revision 保护 |
| S2-4 | FITS 元数据、100／1024 预览及表格／浮层 | 显示正确，科学原件不变 |
| S2-5 | 取消、恢复、重试、契约核对及交付记录 | 完成本阶段验收并停止 |

批次是后续实现顺序，不代表本次已执行。各批次只建设本阶段实际需要的能力。

### 2. 必须验证的场景

| 编号 | 验收场景 |
|---|---|
| S2-AT-01 | 素材根目录边界、中文及特殊字符路径、文件夹递归和跳过报告 |
| S2-AT-02 | 单文件／多选／文件夹形成正确结果，引用与复制清楚可辨；零成功项不发布空数据集 |

## 本地文件选择与素材库导入

ComfyUI 中的“导入”通过浏览器文件选择器选择 Windows 本地文件。选择后先确认素材分类、参数、备注和可选数据集名称；确认前不创建批次或上传文件。上传文件由 WSL 资产服务托管，不依赖 `imports.roots` 配置。

- `POST /uploads` 创建上传批次并记录所选文件清单及素材信息。
- `PUT /uploads/{task_id}/{index}` 按文件流式上传至任务暂存目录；ComfyUI 代理将请求体流式转发，上传请求不使用普通 API 的十秒总超时。
- `POST /uploads/{task_id}/start` 在所有文件完整接收后启动已有入库任务。
- `POST /uploads/{task_id}/fail` 在上传中断时标记批次失败并清理该批次的暂存文件。
- `GET /library/items` 对资产和数据集统一搜索、筛选、排序及分页；数据集当前版本的成员不另列为顶层资产。
- `GET /library/filter-options` 返回共享素材和当前数据集成员实际使用的分类、设备、Bin 及数值范围，不按当前页或已登记但未使用的设备生成选项。

单文件上传形成资产，多文件上传形成数据集。界面在素材列表中显示活动任务的行内进度；浏览器上传中断时需重新选择文件。已经进入后台处理的任务继续使用原有任务恢复逻辑。

## 界面交互修正

- 扩展竖向导航重复点击会回到区域默认页，关闭当前详情／成员页并清空素材筛选及分页；设置默认进入项目列表。
- 素材库使用单个动态筛选面板；列表排序、过滤和分页在服务端完成，数据集由同一个成员满足组合条件才匹配。
- 素材、项目、设备、拍摄设置及数据集资料在详情字段和素材列表字段中使用类型化原位编辑，离开控件后按 revision 局部保存；不向用户展示 JSON。
- ISO 与 Gain／Offset 只显示当前模式，切换不清除另一组数值；Bin 输入统一写入 `binning_x` 和 `binning_y`，旧非方形值保留。
- FITS 与常规图片都存储 100 px 缩略图和 1024 px 预览。普通图片缺失预览由 `apf-service previews backfill` 补齐，仅生成缺失项。
