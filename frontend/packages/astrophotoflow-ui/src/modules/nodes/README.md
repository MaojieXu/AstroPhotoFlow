## 场景与界面责任

- 同一workspace节点库管理自定义节点，各项目可以使用；展示名称说明、输入输出、参数和实际执行内容。允许先保存使用，不强制项目草稿或测试发布流程。
- 沿用常用／高级参数和必要映射展示；自定义输入名称各自唯一、输出名称各自唯一。科学格式、单位等只展示实际需要的信息。
- 节点详情从⑤读取最近一次测试及运行链接；修改后注明旧测试针对修改前内容。保存失败、引擎加载失败、软件未就绪分别展示实际原因，不维护独立激活历史或复制测试记录。
- 更新前展示受影响工作流，经用户确认由⑤更新实例并保存当前图。参数全部采用新版默认值，不验证旧参数；名称和类型未变的端口保留连接，包括重排，改名／改类型／删除的端口断线。
- 正在执行任务保持已采用内容，历史运行事实不改写；③软件包配套节点仍按其规则更新，不把自定义节点约束扩大到所有第三方节点。
- [三种创作场景](../../../../../../docs/requirements/README.md#scenario-nodes)沿用S3软件操作、S6 Python及复合节点；复合内部修改保存为当前工作流独立副本，节点库及其他工作流不变。导出安装先保留目标。

## 与原生宿主的边界

复用原生节点库、控件及Subgraph／Blueprint。注册、加载、端口重排和连线映射集中在[原生桥接](../../../../../../frontend/src/platform/astrophotoflow)；私有UI通过公开导出消费能力，不导入原生Store或画布单例。

保存成功、实际加载、指定画布显示及真实执行分别确认。原生输出按位置保存，不能仅凭刷新宣称端口更新、热加载或执行中内容保护已实现。具体控件、代码环境及存储格式随实施任务确定，保留当前侧栏布局。
